# UI 设计规范

版本：A2「数据编辑室」；更新日期：2026-10-28。用户已确认A2方向，并在规范及全页图册制作后明确授权开始代码变更。按本文实施共享体系和页面迁移；设计图中的示例文案、数据及额外控件不新增业务能力。

本文为唯一视觉与交互契约。A2替代原液态玻璃、品牌蓝、胶囊按钮、大圆角、卡片抬升和240/76px常驻侧栏基线；这些旧规则不再约束后续设计。共享令牌、主导航与主要目录已进入代码迁移；旧名称及历史验收不能证明A2实现，实际覆盖见当前路线图。替换前快照与历轮图稿保留在本机忽略目录，不改写历史通过、失败或停止记录。

业务与安全仍遵循[数据接入与执行契约](../架构设计/数据接入与执行契约.md)、[内容与交付契约](../架构设计/内容与交付契约.md)；范围与启用由[当前路线图](../项目管控/开发路线图与当前任务.md)维护。[模块总览](../项目管控/功能模块总览与实现验收状态.md)与[核心流程](../项目管控/核心业务流程与状态图.md)不因视觉改版改变。

## 1 设计语言

### 1.1 数据编辑室

以暖灰工作面、墨黑文字、朱红操作、编号目录和细分隔线建立秩序。个性来自排版、比例和信息组织；不使用营销式巨型标题、蓝紫渐变、光晕、玻璃模糊、浮动卡片墙、装饰性数字或重复导航。

标题与主要对象名称使用克制的中文宋体，正文、表单、导航使用系统无衬线，SQL使用等宽。宋体不用于所有表格正文或小字，避免细笔画降低可读性。图标仅表达操作/对象类型，不给每段内容配置装饰图标。

目录以横向细线和对齐组织信息；编辑器以稳定分栏组织工作；治理以列表、变更明细和回执组织判断。同一风格不意味着每页都采用同一布局。

### 1.2 适用范围及边界

覆盖登录、个人入口、主路由、兼容页面、子页、对话框、抽屉、图表、编辑器和公开入口的停用状态。只按有效菜单与许可展示功能，不将设计图中的完整菜单视为所有用户可见。

保留 Vue 3、TypeScript、Tailwind、Element Plus、ECharts、Monaco及现有API/Store。设计不新增数据范围、审批权、真实启用或上线授权。公开分享仍按当前停用边界展示，不因出图启用。

### 1.3 知数品牌标识（2026-10-29）

用户已确认“数据成章”方案并授权素材制作与前端替换。产品展示名称统一为“知数”；技术标识、API、Cookie、存储键与仓库名称沿用原值，避免破坏认证与用户偏好兼容。

标识使用朱红方形几何印记、有序横线与镂空结构，搭配宋体中文轮廓字标。所有正式SVG文字转轮廓，不依赖客户端字体；不将生成图的纹理、阴影或渐变带入素材。浅底为朱红图形与墨黑字，深底为浅朱红图形与暖白字，另提供全黑、全白与朱红单色。图形四周留白至少图形边长的1/4，不拉伸、不旋转、不增加描边或阴影。

共享 `BrandLogo`：输入 `compact?: boolean`（仅图形，默认false）；无Emits、Store或API。默认28px图形高、22px字标视觉高，窄屏保持比例；以主题令牌适配浅深色。组件提供“知数”可访问名称，内部图形为装饰；作为首页链接时由外层链接提供“知数，返回获准首页”，隐藏重复图形名称。折叠兼容侧栏仅显示图形，登录、预览、主布局及分享页共用标识。品牌本身无加载、错误或禁用状态，不改变原有链接、权限及分享停用边界。

素材入口为 `frontend/public/brand/`：图形、横向组合、纵向组合、含拼音展示组合、单色版本、透明PNG和浏览器图标；PPT优先使用转轮廓SVG，旧版软件使用透明PNG。浏览器使用SVG、16/32px PNG与多尺寸ICO；另提供180px Apple触屏图标、192/512px应用图标及manifest，不新增离线能力。标题、元描述、可见说明、恢复码下载名称与默认水印统一为知数。

验收：核对文字与图形一致、SVG无外部字体或图片依赖、PNG透明通道、ICO尺寸；构建检查；实际检查页眉、登录、浅深主题与窄屏，确认标签标题与图标请求有效。素材说明与预览随素材维护，设计确认与功能验收分别记录。

朱红是品牌动作，不同时承担唯一错误提示；危险操作必须有“删除/冻结/撤销”等具体文字及影响说明。状态始终有文字，不能只靠色块。浅色朱红较图像参考略压暗，用于保持白字对比度，实际色值以本表为准。

背景、表格和浮层均不透明；表面无模糊、无渐变、无卡片抬升。浮层仅使用轻阴影区分遮挡，例如0 8px 24px rgb(35 36 34 / 12%)；主页面不铺阴影。遮罩为墨黑约28%，不可用模糊替代背景隔离。

文字对比目标至少4.5:1，大字及必要控件/图形至少3:1；结构细线不承担控件识别。颜色表仅是目标，所有实际组合与图表状态仍须测量。

### 2.2 字体与尺寸

| 用途 | 目标 |
| --- | --- |
| 页面一级标题 | 24px / 600 / 1.35；紧凑工作台可22px，窄屏22px；不超过28px |
| 主要报表/对象名称 | 15–16px / 600；可宋体，长名称换行或提供可访问完整名称 |
| 分区标题 | 16–18px / 600；默认无衬线 |
| 正文、导航、控件 | 14px / 400–500 / 1.5–1.6 |
| 辅助说明、列标题、时间 | 12px / 1.5，保持对比度，不用更小字号堆密度 |
| SQL、JSON、代码 | 14px等宽；SQL行号不混入可复制内容 |
| 数字、版本、ID | tabular-nums；精确值不省略有效位 |
| 字体栈 | 标题 Songti SC / Noto Serif CJK SC / SimSun / serif；正文系统中文sans-serif；SQL Consolas / SFMono-Regular / monospace |

不在本轮安装字体或增加网络字体依赖。无宋体时允许回退，但需检查字宽、换行与字重。代码迁移时增加明确的editorial字体用途令牌，不改变所有正文的全局字体。

### 2.3 几何与密度

基础间距4px，主要档位8/12/16/24/32px。桌面页边24px，窄屏16px；分区间24px，字段间16px。表单阅读宽上限约760px，短输入通常280–400px；列表/SQL充分使用内容宽度。标题说明最多约72ch。

按钮/输入圆角3px，数据表面0–3px，浮层6px；不再使用胶囊及18–24px大圆角。桌面主按钮和输入36px，次按钮32px；窄屏或coarse指针至少44px，可编辑输入字号16px。图标16/18px，独立触控目标至少44px。

目录行标准52–60px，密集表格内容自然撑高，单元格上下8px；触屏上下12px。不能固定行高裁掉多行内容，不能缩放整页制造密度。数字右对齐、标签左对齐，单位标于列名。

## 3 全局导航与布局

### 3.1 桌面

统一56px最小高度的横向页眉：知数品牌、主分类、当前空间、通知、外观与账号。示例四类为报表、查询、数据、管理，分类内用获准菜单下拉；待办/工单归入现有流程入口，不凭设计删除菜单。展开态显示完整中文，选中用2px朱红下划线与字重，不用大色块。

四类是展示分组，不是新增路由或许可。未知的获准菜单必须保留到对应组或“其他”，不得因固定映射丢失。个人设置、平台管理、治理恢复按既有资格进入账号或管理菜单。工作空间只出现一次，通知保留未知/失败/未读语义。

桌面分类和窄屏导航使用同一份已获准且设为显示的菜单。保留目录默认分组时，按 A2 的入口映射呈现。空间管理员修改分组后，两种导航都使用保存的分组，分组内仍按已保存的顺序排列。早期配置中的自定义分组名称归入「其他」，在编辑其他字段时保留其原值。

[#41 管理菜单整改](#management-menu-41)在现有 PC 顶部「管理」下拉集中展示获准的空间管理、办理中心和操作审计。待办、业务办理、数据库变更工单的菜单配置分别决定办理中心中的页签可见性，办理中心在任一页签可见时出现。三个来源的菜单编号和既有直达地址继续用于原入口授权、个人首页及菜单配置，不重复出现在顶栏。桌面和窄屏共用同一入口集合。

全局导航回答“去哪类工作”；本地页签回答“本页看哪部分”。同一组全部/我的/收藏只出现一次，不同时设置左分类栏和顶部页签。数据库对象树、编辑器资源树属于工作内容，允许保留。

### 3.2 响应式

| 宽度 | 布局 |
| --- | --- |
| 1440/1280 | 单行全局导航；目录与筛选优先单行；SQL 工作台脚本树默认宽 272px，数据目录按需展开 |
| 1024 | 分类可收为菜单，不缩小字号；SQL辅助区折叠，对象树可收起 |
| 736 | 抽屉式主导航；筛选换行，页头操作另起一行；保持空间和通知入口 |
| 390/320 | 单列信息结构，44px目标，局部表格滚动；禁止整页横向溢出 |

窄屏详情全宽抽屉。SQL对象树与辅助区按需显示，编辑和结果切换为明确页签；保留执行、取消和状态。不能将数据库能力不足画成SQL功能可用。

导航抽屉打开锁定背景滚动并设置inert；Tab约束于抽屉、Esc关闭、关闭后回焦触发器；点击当前路由也回焦。断点切换及卸载恢复原滚动设置。跳转后主内容获得焦点，但后台刷新不抢焦点。

## 4 页面模板

### 4.1 目录与列表

页头（标题/短说明/一个主操作）→单组范围页签→搜索筛选→编号目录或表格→分页。目录默认列表，不做卡片墙。对象名、状态、负责人、更新时间、打开和更多按列对齐；收藏保留名称、选中语义和键盘操作。原已发布/正式/个人范围必须可区分，“全部”不得合并未获准对象。

筛选保留可见名称与明确占位，不能出现多个无法区分的“请选择”。搜索未匹配和尚无内容分开。页码、排序和筛选按既有规则保留；返回尽量恢复获准上下文，安全代次变化先清理。

「数据 → 数据管理」（图册 09 左页与 #40 预览）使用一级标题「数据管理」和三个顶部分类，依次为「共享数据源」「报表执行账号」「驱动与模板」。默认请求第一个获准分类，只挂载当前分类；未知或未授权的直达分类显示提示。窄屏分类换行。旧任务链接移至 `/source-tasks`，保留工作空间、连接及其他查询参数和锚点，沿用两类任务查看许可与原空间核验。旧运行统计链接移至 `/dashboard` 并保留原查看许可。

共享数据源管理默认展示最新可见的共享修订，包含停用项。按名称或默认数据库搜索，按类型、环境、修订状态组合筛选，服务端先确定最新修订、再筛选和分页。桌面表格显示名称、类型与环境、发布范围、最新修订、启停状态及「管理」。736px 及以下按方案 A 排成数据源卡片，名称和默认数据库在卡片头左侧，右侧对齐同一个「管理」次级按钮，触控区域至少 44px，长名称可换行。细分隔线下方以两列展示现有四项信息。管理入口复用原按钮及其可访问名称、事件和回焦，桌面保留操作列。使用带可见标签的共享筛选栏、新建入口、加载、错误重试、空列表和无匹配状态。失败撤下旧结果和总数，筛选变化回到第一页。`SourceCatalog` 保留 `sharedPicker`、`added` 和现有用户 Store。个人选择器继续只列可见、已启用的共享源并进入本人绑定。

打开数据源管理弹窗，可切换「基础配置」「发布范围」「修订记录」。基础配置显示目标、默认库、TLS、超时及目录资料；保存发布范围前提示当前所有已发布修订及已有个人连接的影响。修订列表展示每版状态、变更和可读的个人连接、正式报表引用数；停用照旧在确认后提交目标修订与预期引用数。新修订使用原编辑表单，已有绑定按原修订继续使用。关闭管理弹窗后保留筛选，焦点返回对应数据源操作，行已离开筛选结果时回搜索。管理弹窗接收当前数据源和初始分类，回传打开状态、已保存变更和编辑修订事件；历史面板接收当前来源，沿用现有接口。验收覆盖角色与原空间、组合筛选与分页、引用冲突、焦点及 320/390px 深浅主题。

管理弹窗垂直居中，基础配置随内容定高。长内容达到视口高度上限时，正文区内部滚动，标题与底部操作保持可见。

执行账号（图册 09 右页）使用编号表格和选中详情。工具栏保留「新增执行账号」和「刷新」；筛选按账号名称或数据库用户名、数据源显示名称、状态组织。三个筛选均在已获准的当前空间列表内执行，修改筛选回到第一页。每页 20 项，列表或筛选变化后页码保持有效；选中账号离开结果时清除详情。账号名称按钮用键盘或点击打开详情。1024px 起目录和详情并列，窄屏为单列目录及全宽详情抽屉。抽屉关闭后回到触发按钮，触发按钮已不可用时回到搜索框。加载、请求失败、空目录和筛选无匹配分别显示，失败不显示旧账号、详情或总数。

`ReportAccountsPanel` 在数据管理和兼容报表入口共用，继续使用原接口与权限，无新增 Props、Emits 或 Store 依赖。`ReportAccountDetails` 接收选中账号、操作锁定状态、操作反馈和是否嵌入抽屉，发出 `test`、`rotate`、`toggle` 三个事件，操作和反馈在原面板处理。详情显示实际返回的数据源、固定修订、数据库用户名、已发布报表数量及启停状态；凭据不进入详情。用途固定为正式报表，保留测试强制只读、同身份密码轮换、停用影响确认和请求幂等行为。新建时搜索数据源与读取固定修订分别维护加载、失败和请求代次，只能保存已启用的已发布修订。验收覆盖键盘、窄屏回焦、两主题、筛选/分页、空态/错误/重试和三项既有操作。

「数据 → 我的连接」默认直接显示一张本人连接列表，页面只保留一个一级标题。桌面使用带分隔线的表格，列出连接名称、连接类型、环境、最近检查和操作。窄屏按行堆叠带标签的字段与操作，无整页横向滚动。搜索名称或主机，支持连接类型和环境筛选。未检查、检查通过、检查失败和等待回执分别显示；读取失败显示重试，空列表和无匹配分别说明。连接名称打开详情，详情单独列出连接类型和环境，并呈现检查原因与修复入口。连接类型优先显示 JDBC 模板的产品名，其他情况沿用系统类型名称。表格保留打开工作台、测试及更多操作，编辑和删除按原许可及归属控制。所有常用操作均可键盘进入。

页头以「添加连接」进入已有能力的两种路径：「从共享数据源添加」在弹窗内选择已发布且本人可见的环境及修订，使用原身份确认、测试与保存表单；「手动配置连接」复用个人连接表单。共享选择模式由 `SourceCatalog` 的 `sharedPicker` 属性启用，保存沿用 `added` 事件，关闭回到添加入口。手动表单的 TLS、超时和个人代理放入「高级设置」，环境留在基本配置。桌面弹窗随内容滚动，窄屏随视口收缩，加载及错误沿用共享反馈。代理从个人设置进入，编辑连接时可从高级设置打开同一代理管理页面；代理与连接任务不占用我的连接页签。

### 4.2 SQL、Redis与元数据工作台

SQL：连接/库/schema上下文→文件标签及执行工具栏→编辑器→结果/图表/执行信息。对象树约220px，主区自适应；辅助区默认收起，打开约280px。分栏可拖动且有键盘调整或预设比例替代。编辑区与结果区初始约55:45，不随悬停移动。

SQL 工作台（图册 06 左页）沿用唯一正式查询目标。当前空间内获准浏览的表和视图由全局数据目录展示，目录与执行目标独立。切换编辑、结果、资源视图，以及折叠和目标变化时保留编辑器。桌面可调编辑和结果分栏，手机通过编辑和结果视图切换。普通查询成功后可在「结果」「图表」「执行信息」之间切换，图表用该次已返回的行，执行信息展示该次目标、回执与耗时；切换分类不发执行请求。截断结果仅显示表格与执行信息。执行解释沿用专用展示。SQL 工作台沿用原执行、状态和事件契约。

从查询结果的「图表」另存为表格报表时，`ResultChartPane` 使用成功执行的 SQL、个人连接和目标数据库，向个人报表创建接口提交空的图表配置。保存失败时，原弹窗保留输入，正文在操作区上方就地显示接口错误并以 `role="alert"` 通知辅助技术，窄屏允许提示换行，用户可继续修改并重试。保存成功以创建接口响应为准，关闭弹窗并提示可到报表查看。沿用当前 Props、用户 Store 和接口，无新增 Emits。验收覆盖表格保存、保存被拒绝时保留输入，以及从个人报表列表重新打开后的独立执行回执与实取数据。

运行中禁用重复提交，取消中/已取消/失败/结果未知分别显示。用户发起取消后，自动核实原执行编号期间保留「取消中」及「正在取消请求并核实执行状态」。只有回执确认因取消而未完成时显示「已取消」，已失败或已完成的原回执照实呈现。未知结果优先核实，不默认重发。SQL 结果交付被权限复核阻止时，保留本次执行编号并进入既有待确认状态。权限失效会卸载受限工作区，后续仅在重新具备当前空间回执许可时由本人核对。验收用实际在途写入检查停止交付、无重复提交及独立持久回执。主题、导航密度变化不能重建 SQL 模型、清空撤销栈或执行查询。执行信息展示当前回执，SQL 工作台的独立历史入口按 #37 移除。队列、参数、执行解释、统计、血缘、结果比较及已有 AI 辅助沿用获准入口；AI 入口不构成全站品牌风格。查询工作台复用现有 `useSqlExecution` 状态和 `ExecutionReceipt` 输入。

从键盘启动查询后，运行按钮在执行、核实及结果未知期间使用 `aria-disabled` 且拦截操作，保留原焦点。进入待确认时，若用户仍在运行按钮上，将焦点送到「核实状态」。手动核实后若原按钮随状态变化卸载，待确认时回到该按钮，已得结论时聚焦结果标题。用户已移开焦点时，状态到达不得抢走焦点。原执行编号、恢复记录、结果与切换目标的阻断条件保持现有契约，Props、Emits 和 Store 不变。验收明确核对获取回执所用的编号和实际执行次数。

浏览器恢复记录按用户和工作空间保存。只在当前工作空间恢复其待确认编号和操作限制；离开空间保留原记录，返回后仍通过原空间权限核对。旧版仅按用户保存的记录没有空间来源，保留编号但不自动查询或展示为当前待确认执行。用户选择原空间后可主动核实旧记录；服务端返回匹配的回执后，按当前空间接续或结清，无法读取时保留旧记录并显示原因。旧记录查验期间禁用重复触发，新版以当前空间未结记录优先。不新增组件 Props、Emits 或 Store 依赖。验收核对同一账号跨两个真实隔离空间、返回原空间与请求次数。

执行解释（图册 24 左页）仅展示用户经原「运行」入口提交并成功返回的 `EXPLAIN` 结果。以实际执行快照中的 SQL 和来源方言判定，包括选中执行。允许 PostgreSQL 行注释与嵌套块注释，以及 MySQL `#` 行注释、`--` 后带空白的行注释与普通块注释位于语句首部。MySQL 的执行型注释保留原识别边界。当前编辑文字变化不切换既有结果视图。继续使用同一查询请求、目标、权限、取消及回执；无需额外执行语句、自动分析或调用模型。普通查询保留原结果表格。开始新执行、切换目标、失败或结果待确认时不保留旧计划。

`ExplainPlan` 接收现有结果列、行和执行快照 SQL。默认显示可识别的 PostgreSQL 文本计划节点，按服务端缩进呈现层级。估计成本、估计行数与实际行数、节点时间分列，缺项留空；无法安全解析的格式默认显示原表格。MySQL 表格计划保留服务端字段和 NULL，零值按原样显示。「原始计划」和「执行 SQL」可核对来源。已截断的结果保留原提示，节点时间不汇总为请求耗时。辅助区用共享 A2 分类，支持键盘切换和局部滚动；窄屏在编辑器下为计划结果留出足够高度，首个节点无需滚动辅助区即可看到。无新增事件或 Store 依赖。

PostgreSQL 的 XML 与 YAML 计划使用原计划表格，原始计划区按文本保留服务端返回的换行和内容。XML 以可读文本返回，不作为 HTML 解释。验收核对真实 XML 和 YAML 文本、选中执行的 SQL 快照、结果截断提示及切换时的读写次数。

Redis用键树、SCAN游标、类型、TTL和值查看，不显示SQL工具栏；元数据模式用字段/索引/注释等结构信息，只显示来源具备的能力。不同能力与来源切换的既有未保存/忙碌确认保持。

Redis 工作台（图册 06 右页）以固定逻辑库的键目录和所选键详情呈现。键名模式提交后执行现有 SCAN 请求，重试沿用最近提交的模式。类型筛选作用于本次返回的最多 200 个键，标明匹配数和本次读取范围。服务端未返回下一页游标及匹配总数，页面只显示实际返回数。键详情按「值」「元数据」呈现，显示服务端类型、TTL 和内存占用字节数，永久键与 0 秒分开。服务端明确确认所选键已不存在时，撤下该键、旧值和写入控件，显示「键已不存在」，保留同一键的刷新入口；若目录因此变化，分别显示本次返回数和当前目录项数。普通读取失败保留目录并允许重试。目录、服务信息、键详情分别可重试，切换键和重新搜索撤下旧详情，晚到响应不可覆盖新选择。现有写权限仍决定创建字符串键、更新 TTL 和删除操作。详情刷新及写入回执分别显示。窄屏目录和详情依次堆叠。

「刷新键详情」在读取期间保留按钮位置和键盘焦点，以 `aria-disabled` 表示暂不可再次操作并拦截重复触发。读取结束后从同一按钮重试，包括键已不存在和普通读取失败。用户在等待期间移动焦点时保留其选择。沿用 Redis 工作台现有 Props、Emits 和权限来源。验收核对键盘触发、在途重复按键、到期回执及等待读取时主动移焦。

元数据工作台（图册 07 左页）在唯一查询目标栏下显示模式、对象目录和当前对象字段。模式按接口值选择，无模式的连接器显示默认范围。目录按已读回的对象名、表或视图类型筛选；仅对已读回列表计数。字段以编号表格显示服务端字段类型、主键、可空、默认值和说明。清除或切换父级时撤下旧表与字段；模式、对象与字段的失败在对应区域显示并可重试。对象列表支持键盘选择，详情在窄屏排列于目录下方。索引、DDL、所有者、更新时间及行数缺接口字段时省略。结构采集沿用原许可和后台任务回执。两种工作台沿用 source、database（元数据）和 blocked 事件，无新增 Store 依赖。验收涵盖首次空状态、重试、迟到响应、字段缺项、窄屏、浅深主题及查询目标切换。

「刷新字段」在等待期间保留焦点和按钮位置，以 `aria-disabled` 标记等待并拦截重复触发。键盘触发「重试读取字段」时，先将焦点转到同一对象的常驻刷新按钮，再读取字段。读取完成后保留当前位置；等待期间用户移动焦点或改选对象时，回执不抢回焦点。继续沿用当前字段读取接口和元数据工作台现有 Props、Emits、Store。验收核对等待、重复按键、真实回读、失败重试和改选对象。

元数据工作台的「采集结构」在提交期间保留按钮焦点，以 `aria-disabled` 标记等待并拦截重复触发。服务端接单后显示完整任务标识，任务记录链接带当前工作空间、回执来源和采集类型，后台终态从任务记录读回。若焦点仍在提交按钮，则移到接单回执，下一次 Tab 进入任务记录链接。用户已经移焦时保留其位置；失败保留原位操作和错误说明。窄屏任务标识换行。沿用原任务接口、工作台 Props、Emits、Store 和权限来源。验收覆盖按键防重、回执、同一后台任务终态及采集产物读回。

#### 4.2.1 查询目标联合选择器（2026-10-29设计确认，2026-11-11补充异步边界）

**收起布局。** 页头保留“数据工作台”，工作台直接进入编辑状态。目标入口放在编辑器运行附近，显示“数据源名称 / 数据库名称 ▾”，环境文字常驻，详见 [#37](#workbench-37-ui)。按钮可访问名称保留完整目标，浮层候选可核对长名称。生产环境使用明确文字及危险色，非生产环境使用真实环境名称，未知环境显示“环境未标注”。初次未选目标显示“选择执行目标”。

**选择与切换。** 打开时复制当前有效目标为草稿，不复制敏感数据。换源立即清除旧候选数据库、选中库及错误，按需获取该源获准数据库，不预取所有来源。可将来源配置的默认数据库作为待选候选，仅当其存在于实际返回列表中；不能自动将列表第一项作为已确认目标。列表搜索无匹配与没有可用数据分开；刷新只重新读取候选项，不切换工作台。确认时重新核对身份、工作空间、权限代次、来源能力及候选存在性；切换成功才更新常驻目标和关闭弹窗，失败保留草稿并在弹窗内给出原因及重试。迟到响应按请求代次丢弃；权限或工作空间失效立即关闭并清空草稿，不恢复旧选项。

SQL 目标切换保留编辑文本及撤销历史，选择目标本身不执行 SQL。查看 Redis 键和元数据工具时，编辑器保留草稿；浏览目标独立应用。执行中、取消中、生产执行确认中及结果待核实状态禁止提交执行目标切换。切换后清除同一上下文中不再适用的结果或元数据，历史回执保留原执行目标。访问策略及查询限制使用正式生效的执行目标。

地址指定的数据源不在当前获准列表时，在工作台就地提示重新选择。候选弹窗仍显示本次成功读取的获准来源，可直接选择新目标。候选列表读取失败时在相应区域提示并提供重试。刷新遇到待核实的执行时优先保留回执入口，跳过地址触发的目标弹窗。保留已核实的回执显示，用户可在返回编辑后主动选择本次执行目标。确认有效目标后更新地址与工作台，清除旧地址提示。相关状态由 `WorkspaceView` 维护，身份或权限代次变化时随正式目标一并清理。

**来源差异。** SQL来源选择数据源与数据库；当前SQL执行未提供Schema选择，不凭本次设计增加执行Schema参数。元数据视图的Schema与表仍在工作内容区选择，换目标后按原依赖规则清理。Redis只展示连接器实际支持的逻辑库/固定上下文：没有选择能力时显示只读说明“使用数据源配置的逻辑库”，不虚构数据库列表或增加后端接口。无SQL/键值/元数据能力时说明不可用原因，不能通过选择器启用能力。

**状态与无障碍。** 首次载入、源切换加载、无来源、无数据库、搜索无匹配、读取失败、无权限、切换中分别呈现；失败和重试局限于所属栏，加载不显示假数据或“0条”。源错误时不展示其旧数据库。列表遵循单选listbox/option语义与方向键选择，Tab按搜索→列表→下一栏→底部操作移动，Esc关闭并回焦触发按钮；弹窗打开焦点放在数据源搜索，焦点约束和滚动锁定复用基础组件。提交中防重复，关闭不能隐瞒未知提交结果；错误就近alert、普通加载status。浅深色复用现有surface/selected/accent/border令牌，3px控件、6px浮层、无模糊或渐变，遮罩墨黑28%，列表不抬升。

**窄屏。** ≤735px 使用同一弹窗，四周留白 12px。数据源与数据库分步展示，标题和底部操作固定，当前候选区可滚动。打开时保留对话框焦点，点击搜索再唤起软键盘。目标在运行工具栏次行显示，保留环境标识，触控目标至少 44px。

**拟定组件契约（实施前核对调用点）。** `QueryTargetPicker` 为受控展示组件；输入 `open`、`currentTarget`、`draftTarget`、`sources`、`databases`、两栏loading/error、`submitting`、`disabledReason`；目标包含connectionId、数据库或受支持的固定上下文，名称/环境从获准来源解析。事件为 `update:open`、`select-source(id)`、`select-database(name)`、`retry-sources`、`retry-databases`、`confirm(target)`。搜索保留在组件内，默认只筛选已加载的获准候选；不暗示全局搜索或新增后端分页。父级拥有草稿、API请求及请求代次，工作台拥有正式目标与执行状态；组件不直接调用Store或执行API。正式目标的所有者及SqlWorkspace初始化流程须在实施前统一，禁止两份选择状态相互覆盖。

#### 数据工作台交互

本节将已沟通的布局与交互纳入 [#34 编码与验收计划](../项目管控/开发路线图与当前任务.md#workbench-34-must-plan)。设计评审见 `.local-docs/workbench-34-20261119/PC工作台布局研究与评审.md`，隔离预览及验收见同目录 `08-本地验收.md`。产品实现按 [8.3](#ui-change-workflow) 确认范围，工作台的执行、取消、回执和数据权限沿现行规则。

- **PC 主区。** 左侧为脚本树，中间为带执行目标的编辑器和结果，按 [#38 PC 分栏规范](#workbench-38-pc-ui) 展示。左侧脚本区和底部结果区可独立折叠，展开恢复尺寸及内容。左栏与主区之间左右拖拽，编辑器与结果之间上下拖拽，保留最小可读面积和键盘调整。运行后保留可见的状态和结果入口；新一次执行可展开结果表。1280 × 720 与 1440 × 900 的默认成功态首屏展示表头与至少一行。
- **对象与详情。** PC 和手机按 [#39 数据目录规范](#workbench-39-pc-catalog) 浏览当前工作空间内获准查看的表及视图，查看来源路径、字段、已有说明及复制原名。PC 使用贴边入口，手机从工作台「资源 → 数据目录」进入。
- **脚本目录与菜单。** PC 左栏和移动端资源区复用「我的脚本」和「分享给我」目录树。根或目录菜单可新建目录和脚本，目录可重命名；「新建脚本」含 MySQL、PostgreSQL、Redis。自有脚本可分享、取消分享和移动，获邀脚本可查看、复制。分享图标、只读标识及脚本类型沿用桌面树。PC 使用右键、菜单键或 Shift+F10，窄屏提供可触控的行操作。操作针对发起菜单的对象。打开脚本时激活匹配的编辑标签。关闭有未保存修改的标签时给出保存、放弃或继续编辑的选择。
- **脚本执行目标。** 脚本标题行显示类型和保存状态，实际执行目标按 [#37 工作台编辑及目标选择](#workbench-37-ui) 展示。复用同一选择器，按脚本类型筛选本人获准来源，SQL 方言匹配后选库并应用当前执行目标，已有可用默认值用于打开脚本时恢复。Redis 显示随连接配置的固定逻辑库。目标不可用时就地说明并允许重选。被分享者查看文本，复制后可使用本人获准连接。Redis 脚本编辑及绑定界面保留执行边界说明，命令执行交互在契约明确后实现。
- **结果与图表。** 成功后默认结果表，具名页签切换表格、图表、执行信息，保持同次结果。被省略的长值提供触控及键盘可操作的完整值视图，关闭回原单元格。执行目标、回执及状态绑定本次执行上下文。图表绘图区随分栏尺寸变化，放大时使用主区，恢复时保留尺寸、SQL、结果和配置。图表只映射本次结果到维度、指标和展示配置。聚合、排序及 Top N 由执行 SQL 表达。用原执行 SQL、连接和库另存为个人报表，重开时复用既有独立执行链。
- **窄屏与错误。** 320px、390px 使用明确的编辑与结果切换入口，操作附近可见执行状态，切换保留文本与结果。字段表及结果表可局部滚动，详情使用内容区内全宽方案。覆盖加载、空数据、读取失败、无权限、长名称和键盘回焦。界面提示用实际结果和回执，失效目标的缓存结果及时清理。

资源区接收当前空间的目录、可见脚本、当前脚本标识与权限，处理打开、创建、移动和逐人授权。编辑器维护本次草稿与未保存状态，通过脚本接口保存。父级沿用查询目标状态和 `useSqlExecution`，负责目标变化与在途阻断。对象详情接收已选连接、目录范围和对象标识，按当前许可读取字段与说明。结果区接收实际结果和执行快照，维护分栏、展开及图表配置。用户及空间身份沿用既有 Store。接口见[工作台脚本与结果接口](../接口规范/API接口规范.md#workbench-34-api)。

- SQL 结果组件沿用 `columns`、`rows`，在虚拟表格可见范围测量省略状态。省略或含换行的内容在原格提供按钮，弹窗显示列名、行号及完整值，提供复制与关闭。复制失败时允许选择原文。关闭后恢复到原单元格按钮，原格离开渲染范围时恢复到表格容器。新结果清除旧弹窗，组件内管理状态。
- Redis 键详情根据响应中的 `truncated` 在值和属性页签上方提示「当前仅展示前 10,000 项，键值还有更多项」。对象刷新沿用当前目标及模式，保留原选择并重新读取字段。对象消失时清除原详情，原位置说明原因。切换目标或模式后，只接纳新请求的结果。
- 工作台表格和图表均提供「另存为报表」。表格使用空图表配置，柱状图和折线图保存当前维度及指标。工作台向报表结果组件传入实际执行结果和可用高度，复用报表的字段与精度校验。工作台持有当次图表类型及字段映射，切换页签保留，执行新查询时重置。图表放大占中间主区，提供恢复按钮，切换结果页签时也恢复分栏。

#### 工作台编辑及目标选择（#37）

- **进入和运行。** PC 与手机默认挂载 SQL 编辑器，未选择目标时可编辑和管理脚本。工作台的功能以 PC 为准，窄屏资源区仅展示脚本树和按既有权限可用的数据目录。SQL 工作台取消独立的历史、对象和 Redis／元数据快捷页签。运行工具栏显示实际数据源与数据库，环境独立显示，长名称可核对全文。无目标时工具栏显示「选择执行目标」，有草稿时运行也可打开选择器。确认目标只应用连接，取消后保持草稿与原目标。查询回执继续以实际执行快照为准。
- **脚本及资源。** 打开自有 SQL 脚本时，通过现有连接和数据库权限读取恢复有效默认目标，载入过程中阻止执行。执行入口显示实际数据源、数据库和环境。失效、只读及 Redis 脚本分别显示适用反馈。数据目录沿 PC 规则从当前空间浏览获准表和视图，独立于执行目标。Redis 键和仅元数据工具保留已有连接及深链接入口。编辑器保持挂载，草稿、结果和脚本树各自维护状态。
- **移动端。** 共享页头第一行导航在左、品牌在右，第二行保留工作空间与账号操作。编辑工具栏优先呈现编辑、运行和取消，目标放在次行。保存脚本、格式化、另存为脚本、查询限制及访问策略在「更多操作」展开。目标选择器在窄屏一次显示一个候选区，顶部可返回数据源，普通目标的确认与取消在底部。触屏打开时聚焦弹窗，搜索由用户主动聚焦。候选区按可见视口处理软键盘与安全区。
- **窄屏工作区。** 1024px 以下从同一操作栏选择「编辑」「结果」或「资源」，三个区域互斥显示。退出资源回到进入前的编辑或结果，成功打开脚本后回编辑。脚本树保持展开、搜索与滚动，数据目录下钻及返回与 PC 共享组件。当前无执行结果时，结果区首屏说明状态并提供「返回编辑」。成功返回零行和未执行分别呈现，普通成功首屏优先显示表头和首行。运行进入结果区，结果视图提供同一执行状态机的取消入口。结果入口保留执行中、取消中、核实中及待确认状态，刷新恢复后可直接进入结果核实。受控取消、核实和失败规则沿用执行契约。仅压缩此工作台的标题留白，触控面维持至少 44px。
- **窄屏组件与验收。** `SqlWorkspace` 持有当前工作区、返回位置与资源类别，复用 `WorkbenchScriptDirectory` 的目录树和事件。脚本树通过 `touch` 展示行操作并适配菜单位置。数据目录以 `inline` 模式复用 `WorkspaceCatalogPanel` 的加载、搜索、下钻、复制及失败重试，沿用用户 Store 的 `catalog.metadata` 授权及原只读 API。内嵌面板显示时读取目录，关闭或断点变化随工作区管理。验收覆盖 Android 真机、320px、390px 和桌面，验证三视图、资源状态恢复、跨来源目录与权限、脚本只读及已保存目标、空态、零行、成功及运行中取消。
- **组件与验证。** `WorkspaceView` 管理可空执行目标、独立浏览目标和空间代次，`SqlWorkspace` 接收目标和浏览请求入口，通过事件请求选源、打开浏览工具或在打开脚本时恢复默认。共用 `QueryTargetPicker` 维护分步展示状态，候选加载及提交仍由既有逻辑校验。复用原用户 Store 与 API。验收覆盖 320 × 640、390 × 780、桌面 1280 × 720、Android 真机、生产确认、源和库变更以及加载失败。
- 桌面分隔条以可聚焦的 `separator` 表达方向、范围及当前值，支持拖动、方向键、Home、End。尺寸由工作台保留，展开后恢复。数据目录详情按对象标识独立请求授权字段，返回列表回到原对象。窄屏详情占资源视图宽度。
- **脚本数据源弹窗。** `ScriptTargetDialog` 使用独立草稿并按类型过滤来源，列表内标记当前目标和选中项，数据源行显示环境。切换数据源后等待用户选库，连接配置中的默认库不预选。点击或用 Enter、Space 激活数据库行后重新核验完整目标，成功即应用到本次执行并关闭。方向键只在数据库候选间移动焦点。SQL 点选只更新本次执行目标，用户保存脚本时才持久化绑定。Redis 点选固定逻辑库行即关联该脚本。脚本选择器移除整个底栏，用右上角关闭或 Esc 退出未完成的选择并回焦。核验期间禁止重复选择，失败在候选区提示并保留草稿。共享 `QueryTargetPicker` 通过直接选择模式启用此行为，沿用选源、选库事件及原有 Store 和加载状态。窄屏保留分步候选及返回数据源。验收覆盖鼠标、键盘、窄屏触控、取消、显隐、失效及重试、已有默认值恢复和普通选择器兼容。
- 编辑器分别显示保存状态、只读状态和目标确认状态。打开他人脚本时先读回当前可见内容，编辑区域禁止输入，复制读取当前接口。加载历史放入独立草稿并显示原执行目标，执行仍使用当前已确认目标。
- Redis 键和元数据页的「管理脚本」复用资源区与脚本编辑器。没有 SQL 查询目标时显示脚本文本、类型与绑定操作。选定类型匹配的 SQL 目标后，原脚本和编辑内容随当前页面保留。

#### PC 脚本目录树及分栏（#38）

- **布局结构。** 1024px 起左侧为可折叠的脚本树，默认宽 272px，右侧为编辑器与本次结果。桌面侧栏取消「对象」「历史」及外层「脚本」页签。已登记对象从数据资产查看，Redis 键和专用元数据从已有连接入口进入。窄屏继续由 #37 的工作台布局及真机验收管理。
- **脚本目录。** 顶部固定搜索和折叠入口，「我的脚本」和「分享给我」为可折叠分组。子目录与文件紧贴父目录展示，按层缩进，活动脚本高亮，名称前显示文件、目录或分享图标。行内提供脚本类型和只读标识。展开的分组与目录各用原有接口分页，搜索过滤这些范围，清空搜索恢复目录。读取失败按分组或目录显示及重试，深层目录保留可访问名称和完整名称提示。
- **节点操作。** 从「我的脚本」根节点和目录右键菜单创建目录或脚本。桌面菜单项左对齐，悬停与键盘焦点有可辨识反馈，边框用于菜单容器。「新建脚本」在一级菜单旁展开真实的二级菜单，列出 MySQL、PostgreSQL、Redis。右侧空间不足时向左展开，支持悬停、点击、方向键和 Esc 逐级返回。新建成功后在目标目录显示已保存的默认名称，直接进入原位重命名并选中文本。默认目录和脚本按同级同名顺延编号。Enter 保存，Esc 退出重命名并保留已新建的节点。空名称、重复目录名或请求失败在原行提示。自有节点可再次从菜单重命名，自有脚本保留移动、分享及取消分享，获邀脚本提供复制。目录中的脚本打开到对应编辑标签，分享权限由原接口核对。
- **PC 目标弹窗。** 编辑器的执行目标和脚本默认目标共用选择器。桌面打开弹窗时保持页面原有滚动条、滚动位置及工作台宽度，滚动操作限制在弹窗和候选列表内。弹窗关闭回到触发入口。窄屏使用 #37 的分步候选及可见视口规则。
- **编辑和结果。** 编辑器直接进入，标题显示类型和保存状态，桌面自有脚本提供可见的「保存」。唯一的执行目标和环境在「运行」附近。成功的普通查询将结果分类、状态和折叠入口置于同一行，表格紧接其下。实际 SQL、目标与回执在「执行信息」核对。
- **脚本保存位置（#42）。** PC 和窄屏从默认编辑区第一次保存、另存副本、以及未命名草稿的「保存并关闭」共用「另存为脚本」弹窗。弹窗包含「脚本名称」和「保存位置」，可选「我的脚本（根目录）」及本人当前空间的可用文件夹，以完整路径区分同名子目录。未命名草稿和共享脚本的副本默认本人根目录，自有脚本另存默认原文件夹（仍可用时）。既有脚本的普通保存沿用原目录和版本校验。目录读取失败可局部重试，提交期间禁用重复保存，提交失败保留名称和位置，取消保留原 SQL。保存成功由原创建接口返回脚本及实际目录，沿用脚本树读回。弹窗接收初始名称、目录和保存回调，回传关闭及保存结果，目录与创建沿用既有 API 的本人和工作空间校验。PC、320px 和 390px 验证多级目录、根目录、共享副本、普通保存及错误重试。
- **普通保存入口。** `SqlWorkspace` 在桌面提供「保存」按钮，桌面和窄屏都在「更多操作」提供「保存脚本」。焦点在工作台时，`Ctrl+S` 或 `⌘S` 与按钮调用同一保存操作，覆盖 Monaco 和基础编辑器。首次保存含内容的草稿时选择名称和目录，并保存当前已核验的连接与数据库。本人脚本按原编号、位置和版本保存。正文和新选定的 SQL 目标可单独保存，也可同次保存，已有脚本可保存空正文。未保存的临时选择随编辑标签保留。重新打开脚本仍按当前权限检查并恢复默认目标。共享只读脚本可复制或另存为本人副本。保存入口从当前正文差异及已确认的目标差异判断是否可用，锁定、无变更和重复按键期间不发送保存请求。成功按服务端回执提示，失败保留正文和已选目标，版本缺失或冲突时提示核对。无新增 Props、Emits 或 Store。验收覆盖首次保存后恢复目标、仅修改目标后保存、仅临时点选后重开、两种保存入口、无变更和共享只读边界。
- **组件与验收。** `SqlWorkspace` 管理桌面断点、侧栏和结果显隐、拖拽尺寸及执行状态。`WorkbenchScriptDirectory` 处理脚本与目录的菜单、创建及保存，桌面树管理原行输入和焦点。折叠两区域保留脚本和结果，复用可用键盘调整的分隔条。验收覆盖 1280 × 720、1440 × 900、长名称、分页与重试、同名不同目录、分享和撤回、执行回执以及窄屏回归。增加真实滚动条下弹窗开关的布局测量、悬停和键盘子菜单、原位保存和取消验收。
- **PC 工作台高度。** 保留页头和编辑器工具栏的执行目标。SQL 布局承接实际页头、标题、提示及内距之后的剩余视口空间，常规桌面高度下整页无需纵向滚动。脚本目录、编辑器及结果继续各自滚动，分隔条继续可调。视口高度不足以满足工作区最小高度时允许整页自然滚动，保留全部控件。Redis 键和元数据工具以及窄屏沿用各自的页面高度规则。验收检查常规视口无整页溢出、矮视口可滚动、弹窗开关稳定及分栏拖拽。

#### 多脚本编辑标签（#49）

- **新建入口。** 左侧目录标题只显示折叠入口。桌面在「我的脚本」根或任意自有目录通过右键打开「新建脚本」子菜单，窄屏沿用该行的操作菜单。在编辑器标签栏右侧悬停「＋」展开 MySQL 脚本、PostgreSQL 脚本、Redis 脚本。触屏点按或键盘激活也能展开。选中类型立即切到对应草稿，草稿类型和数据源选择保存在标签会话中。用户首次保存时选名称和目录，在保存成功后将同一标签关联到正式脚本。失败或取消保留草稿及撤销记录。目录入口按打开菜单的位置创建并保留原位重命名。
- **标签与编辑。** 在原编辑工具栏上方显示已打开脚本，目录重复打开同一脚本 ID 时激活原标签。当前标签用主题主色下划线和选中状态标记，未保存改动用圆点及无障碍名称提示。长名称截断并可核对全文。标签可横向滚动，新建入口始终可点。鼠标、触屏和键盘均可切换和关闭。切换保留各自正文、Monaco 撤销状态及临时执行目标。关闭活动标签后使用相邻标签，全部关闭后回到默认编辑区。
- **标签菜单与关闭确认。** 任意标签均可通过右键、菜单键或 Shift+F10 打开「关闭此标签页」「关闭右侧标签页」「关闭其他标签页」「关闭全部标签页」，作用范围以打开菜单的标签及当时的顺序为准。窄屏可从编辑器「更多操作」执行同样的命令。无适用标签的项禁用。关闭已保存脚本或有正文、绑定改动的草稿时，先激活该标签并显示其内容，再弹出带风险图标的确认框并显示脚本名称。默认聚焦「继续编辑」，Esc 同样可退出。已有未保存改动时可选「保存并关闭」或「放弃并关闭」。已保存且无改动时可直接确认关闭，提示从脚本目录重新打开。未修改的空白草稿直接关闭。批量关闭按标签顺序逐个激活并确认，全部通过后统一移除。取消或任一项保存失败保留整组标签，停在正在核对的标签，已经保存成功的标签按回执显示。
- **目标、结果与作用域。** 执行、普通保存与快捷键只作用于当前标签。切回标签时核验此前实际选择的执行目标，并按现有规则提示失效或当前目标变化。Redis 保留文本编辑和逻辑库绑定，共享脚本保留只读约束。每个标签只展示与其脚本及当前已核验目标相符的结果。正在执行、取消、核实、执行结果待确认及保存处理中沿用既有切换约束。标签状态归属当前页面会话及空间，身份变更由工作台原逻辑清除。
- **组件与验收。** `SqlWorkspace` 持有标签、草稿、Monaco 编辑实例、目标标识、风险确认和结果。标签栏接收标签、活动键与锁定状态，发送切换、带范围的关闭和脚本类型事件。脚本目录继续处理原目录创建和激活事件。`WorkspaceView` 按脚本或草稿类型复用既有来源和库权限核验。`ScriptTargetDialog` 接收会话键、当前脚本类型、目标和应用回调，使用同一选择器处理已保存脚本和草稿。复用原 Store、API 及数据模型。验收覆盖桌面、320px/390px 触屏和键盘，草稿零写入、首次保存及失败重试，确认前活动标签与正文一致、空白直接关闭、批量按序确认、关闭取消或保存失败、保存与放弃的实际回执，并复验目标与结果隔离。

#### 全局数据目录（#39）

- **入口与布局。** 1024px 起，公共工作空间布局提供一个右下贴边箭头。悬停或键盘聚焦显示「图标 + 数据目录」，点击打开后隐藏快捷项。抽屉覆盖内容区右侧并独立滚动。在工作台让出 SQL 编辑器工具栏，打开和固定时仍可使用执行目标和运行按钮。开关和固定不产生全局遮罩、滚动锁或布局占位。具备元数据读取许可的工作空间页面共用入口。窄屏工作台获准用户在「资源 → 数据目录」打开同一目录面板，独占主视图。桌面抽屉的图钉和贴边控件由资源视图的返回入口承担布局切换。
- **固定与焦点。** 默认点击抽屉和入口之外收起，同时执行原点击操作。图钉固定后继续打开，取消固定恢复外部收起。×、贴边箭头或抽屉内 Esc 可关闭。主动关闭回焦到入口，重新打开默认未固定。空间、会话或权限版本变化时关闭并取消旧请求。
- **对象列表。** 打开直接在一列平铺当前空间内本人获准浏览的表和视图。行内顺序是类型图标、对象名、复制图标、详情箭头。对象名称和箭头共用同一个查看详情按钮，复制为独立按钮。按对象名稳定排序并分批显示，重名才显示来源路径。搜索按名称匹配完整已读取范围，再分批显示；加载或部分连接读取失败时说明覆盖状态并允许重试。打开时沿现行权限读取各可用关系型连接及其授权目录，不依赖事先采集。每次打开最多同时读取两个连接的结构，取消关闭时的未完成请求。
- **下钻。** 同一抽屉替换为对象名、来源路径、已有说明及字段名与类型。表、视图和字段的复制返回完整原名。名称与类型单行省略，悬停或键盘可访问原值。详情单独滚动。返回列表恢复原搜索、显示批次、滚动位置和对象焦点。
- **组件与状态。** 公共布局挂载 `WorkspaceCatalog` 并按用户与空间权限版本重建。组件管理打开、固定、列表、搜索与详情。目录独立使用元数据接口，与执行目标、脚本、SQL、结果和分栏状态无绑定。接口按当前空间、账户及已有元数据授权逐次判断。目录范围与连接器既有元数据能力一致。
- **本地验收。** 从工作台和另一获准页面打开同一入口，验证跨数据源和模式的表、视图及同名对象、全列表搜索、复制、基础信息与返回状态。核对无许可、部分失败与权限上下文切换。固定目录后直接从原工具栏运行 SQL，使用工作台回执及布局测量验证目标、编辑区及分栏一致。Android 真机继续由 #37 单独跟踪。

### 4.3 报表与仪表盘

报表设计按来源、SQL、参数、展示、分析、契约分区，保存草稿与发布动作分开。阅读页显示固定版本、参数、执行/刷新状态、表格图形、来源、限制与时效。精确金额、超安全精度值、NULL和截断不得被美化或改写。

仪表盘目录采用列表；阅读布局可用网格，但图块之间使用细线与留白，不做漂浮圆角卡。设计器保留组件库、网格、属性区与键盘排序。受众、依赖、必需卡片受限、部分失败和刷新回执必须同时可见。批准不等于发布；发布不等于获得数据许可。

报表目录（图册 02 左页）以 `view` 参数恢复获准分类，使用共享分类控件的键盘操作。分类切换保留当前工作空间并清理上一分类的对象及业务筛选。显式指定不可用分类时显示说明，不挂载其读取组件。兼容用户仍可使用已存在的个人、已发布及其他获准入口。个人和发布目录均使用编号表格、服务端搜索和分页。输入后的未提交搜索不影响翻页、刷新及重试。读取失败撤下旧列表和总数，保留搜索条件；发布目录仅使用接口已有的发布号、内容版本和描述。收藏沿用个人报表能力。

正式报表阅读（图册 02 右页）使用全页标题、查询参数、已批准版本、结果和现有授权的完整导出申请。`/reports?view=published&report=…` 支持直达、前进后退和 `p_` 筛选。返回目录清理对象参数并恢复搜索状态，打开后聚焦阅读标题，返回后回焦到对应报表或目录。定义读取失败可先重试定义；未确认定义时不执行查询或导出。参数编辑取消在途查询并清除旧结果；结果失败保留参数且可重试。导出沿用冻结发布号、审批、格式与上限。`PublishedReportsPanel` 由 `focusReportId` 确定阅读对象，无新增 Store 依赖。共享 `PageCategoryTabs` 的 `hideTabs` 仅用于同页阅读，保留当前分类内容与筛选状态，阅读期间移除分类栏、面板标签和额外的键盘停靠点。验收覆盖获准分类、浏览器后退、定义与查询分别重试、筛选回填、取消、导出门槛及两主题窄屏。

报表图形及其可展开结果表使用冻结的字段展示名称。表格保留实际查询列顺序和原始值，包括绘图精度不足时的表格回退。展开表格可用键盘操作，无额外查询。共享结果表焦点用两像素内描边，让带滚动或裁剪容器的轮廓完整可见，强制色下用系统高亮色。报表的「刷新数据」在请求期间保持键盘焦点，用可访问忙碌和禁用状态阻止重复请求。沿用现有结果、列数组和查询请求，无新增组件事件。验收覆盖四档宽度和浅深主题的柱形、折线、饼图、指标卡、透视、堆叠和双轴，以及实际筛选变化、空结果、精度回退、展开明细、强制色和减少动态。

图形按去除补齐尾零后的有效数字判断绘图资格，结果表继续显示数据库返回的原小数位。超出安全数值范围或非零值解析成零时，沿用原始结果表和错误反馈。

下钻按冻结的字段映射从当前结果行传值。键盘选择明细与点击图表数据项共用目标定义读取，目标有当前查看权限后才导航，目标查询沿用自己的权限检查。延迟核对时保留明细按钮焦点、标记忙碌并阻止重复操作。改变明细选择、改变查询结果或离开后取消旧核对。失败保留原报表及结果，并将错误关联至原明细按钮。成功在当前工作空间打开目标，保留原报表及筛选在浏览器历史中。沿用 `ReportResult` 的既有 Props、图表选择事件和服务端接口。验收覆盖不同受众、键盘与点击、迟到响应、精确编号、地址转义和返回原筛选。

直接进入或刷新正式报表阅读页后首次返回目录，列表仍在读取时先聚焦目录。当前列表读取成功且焦点仍在目录容器时，将焦点送至原报表的打开按钮，窄屏表格同步滚动到该按钮。原报表不在当前结果或用户已经移开焦点时，保持当前焦点。快速重新打开报表、切换分类或读取失败时，旧读取结果不得移动焦点。沿用 `focusReportId`、既有列表和目录元素，无新增组件事件或 Store 依赖。验收覆盖 1024、736、390、320px 浅深主题，核对刷新后返回、在途期间自行移开焦点及报表未出现在列表中的情况。

正式报表阅读的应用筛选、刷新和恢复默认在提交前检查空的必填参数，以及整数和小数输入的格式及定义范围。数值检查按输入原文比较，保留大整数和小数精度。检查失败时保留当前地址，不发出查询，就地显示与输入关联的说明（`aria-invalid`、`aria-describedby`），并聚焦第一个无效字段；修正当前字段后清除其错误。共享 `ReportParameterForm` 暴露参数检查供正式阅读调用，沿用 Props、Emits 和其他入口现有行为；服务端继续校验所有参数及直达旧链接。应用有效参数时，地址同步和查询结果变化不得抢走焦点。共享布局只在路径或权限代次变化时聚焦主内容区。验收用键盘检查必填、格式和范围错误，核对字段名称、错误关联、有效空结果、更正后取数及直达无效链接。

仪表盘「开发与审阅」目录中，仅具备设计许可的当前责任人可编辑或预览已保存草稿。送审入口同时要求当前草稿可编辑及送审许可，预检按现有接口执行。归档、删除和恢复按设计许可、责任人及现有管理员资格展示。只有审阅许可的责任人仍可查看版本与审阅。撤回待审版本按冻结版本的提交者和现有撤回许可显示。兼容模式沿用服务端现有角色资格，页面入口继续由服务端核验。验收覆盖只有审阅权的责任人、只有设计权的责任人、具备设计和送审权的开发者、兼容开发者和正式内容读者。

添加卡片后，若焦点仍在即将禁用的添加按钮或随其禁用而丢失，聚焦新选中的布局卡片。键盘调整顺序时，仍可沿同一方向移动就保留当前按钮焦点，到达首位或末位导致该按钮禁用时聚焦同一张卡片在布局中的新位置。移除最后一张卡片时，布局标题使用共享 `ui-focus-target` 显示 2px 主题焦点边线及 2px 间隔。焦点已移到其他控件时保留该操作。以上交互沿用设计器的 Props、Emits 和 Store。用实际获准的两张正式报表验证窄屏和桌面上的排序、移除、焦点与保存后读回。

报表库和受众分别重试。读取期间保留原重试按钮和焦点，以 `aria-disabled` 标示不可重复操作，拦截再次触发并显示各自加载状态。再次失败时恢复同一按钮和本区域的就地错误。读取成功后，若重试按钮仍持有焦点，将焦点移到相应区域标题，应用共享 `ui-focus-target` 样式。用户在等待期间移走焦点时保留其选择，关闭弹窗后的响应不得移动焦点。保持已输入的名称、说明、布局和筛选。验收分别核对重复按键、连续失败、实库恢复、等待期间移焦及两条依赖互不覆盖。沿用设计器的 Props、Emits 和 Store。

仪表盘复核（图册 05 右页）分区呈现冻结版本、参数、受众、依赖和真实预览验证。依赖显示实际报表契约状态；版本列表失败撤下旧版本和动作，重试前不使用旧记录。已读取的预览只在同一轮全部卡片成功时可登记。更换版本、修改参数、关闭或暂停预览、再次查询及单卡重试时立即清除旧的待登记编号。`DashboardViewer` 保留现有 Props 与 `refreshed`，增加 `review-evidence` 事件传递当前可登记编号或空值，服务端继续核对全部回执、权限、时效和独立审阅。复核登记成功后才显示服务端验证时间，批准和发布继续分别操作。设计器和复核弹窗原 Props、其他 Emits 及 Store 依赖保持。验收覆盖局部失败、草稿保留、卡片排序、轮次清理、全部卡片成功、版本切换和窄屏。

仪表盘指定审阅人退回和作者撤回待审版本时，使用共享确认弹层注明动作和冻结版本号。退回须填写审阅意见，取消后保留原意见并回到原触发按钮。确认提交期间阻止重复触发。提交失败时保留已填写内容，焦点仍在原操作流程时移到错误提示，用户可用原动作重试。命令成功后显示带版本号的结果回执并读取版本列表。读回失败时保留回执、撤下旧版本及动作，重试仅重新读取。键盘仍在原操作流程时，回读成功移到回执，失败移到重试入口，重试成功后聚焦所选版本的回执。用户主动移焦时保留其选择。沿用弹窗 Props、Emits、Store 与现有服务端命令。验收核对四档宽度浅深主题、取消零写入、真实退回后作者读回意见、重新送审后真实撤回、提交失败及写后只读恢复。

仪表盘改派只为待审版本选择其他具备审阅能力的账号，列表移除当前审阅人与提交人，报表读取和受益关系继续由服务端核验。键盘从改派提交时在等待期间保留焦点并阻止重复触发。提交失败保留候选人和就地错误，成功显示带冻结版本号及新审阅人的回执。独立读回失败保留回执和只读重试。仍持有原操作焦点时，写入失败聚焦错误，读回失败聚焦重试，读取成功聚焦同版本回执。已到期版本保留历史，撤下改派、验证和审批动作并退出审阅待办；作者重新送审生成下一版本。沿用复核的 Props、Emits、Store 和命令接口。验收用两个独立审阅人核对改派前后待办、旧验证清除及新审阅人实际核验，以及到期搜索和重新送审。

已批准版本单独呈现原审阅人的当前资格。版本接口明确返回资格已失效时，保留历史审批决定，撤下该批准对应的发布与回滚操作，并提示作者重新送审。发布和回滚的服务端检查继续在提交时执行。收到发布或回滚冲突后重读版本；如果读回资格已失效，显示具体说明。键盘从确认框提交失败后，仍持有该操作焦点时转到具体反馈或版本重试。已生效的其他发布继续按各自资格和数据边界读取。

在已启用 #47 的矩阵空间，仪表盘入口、已发布目录、设计和审阅入口继续读取用户 Store 的有效动作。草稿负责人依据当前角色设计和送审，候选显示「业务复核人」，表单选择项来自该草稿预检。办理中心继续直达本次版本。版本面板沿用原 Props 和 Emits，通过版本读回区分提交人、指定复核人、历史签署、当前资格和可用操作。普通主管只在本人被指派时办理该次复核，只在本人完成业务签署且读回当前可发布时显示「发布」。复核和发布保留单独的确认和回执。未签到、缺独立数据签署、资格变化或读取失败时撤下不可用动作，就地说明当前状态。原签署失效时显示「请重新送审」，作者仍可在原仪表盘发起新一轮送审。普通角色的操作菜单沿用相应服务端资格隐藏回滚、下线或治理改派。查看者只进入已发布阅读，并保留逐卡受限及刷新反馈。

#47 使用既有目录、对话框、确认、就地反馈和 Store，窄屏沿既有纵向排列。已在正式使用的看板不向普通设计者展示会终止正式发布的归档入口，草稿维护沿现有状态与责任人规则。验收在桌面和 390px 核对三类角色入口、叠加角色回避、主管本人发布、失权后重新送审、正式查看的筛选与受限卡提示，以及读回冲突时原版本及焦点的处理。空间成员页权限展示使用当前空间的有效角色动作，成员角色标签、选择和已保存分配沿现有交互。

#### 内容开发、仪表盘版本对照与办理（#48）

顶部「报表」提供「报表目录」「仪表盘」及「内容开发」。正式目录默认显示当前可读的已发布内容。内容开发含「报表」「仪表盘」入口，按服务端有效动作及原菜单可见性展示当前账号可维护的内容。已有个人报表及交付入口按原资格开放。业务查看者只取得获准的正式视图。

仪表盘开发详情固定显示工作空间、名称及编号。当前发布显示内容版本及发布号，本次送审显示冻结版本及审批状态，未送审修改以草稿修订号标识。对照展示各自获准读取的配置、卡片增减及位置和宽度。复核使用批准时的基线、差异摘要及冻结定义。草稿、冻结版本和正式阅读采用相应执行模式，展示未发布、读取失败和受限状态。读取失败可重试，撤下失效的对照结果。

「管理 → 办理中心 → 待办」提供仪表盘「待我复核」「待我发布」。事项显示名称、内容版本及审批编号，链接携带原空间、对象及审批编号。精确复核仅展示指定冻结版本。预览、登记、批准和发布各有独立反馈。办理返回恢复原分类、筛选、页码和条目；事项退出原分类时显示本审批结果并保留原分类。原权限和失权后的重审规则沿用 #47。

仪表盘设计器提供「新建图表报表」，在同一设计上下文复用正式报表的数据源、执行预览、图表字段映射及保存。返回同一仪表盘的已发布报表库并保留原布局。草稿回执说明报表等待发布，合格候选仍只包括获准读取、已发布且数据契约获批的报表。支持重读候选，查看来源、展示类型及发布版本。没有合资格开发连接时说明所需个人连接并提供返回。

`ManagedDashboardsView` 管理对象、对照及目录焦点。`DashboardReviewDialog` 新增可选 `reviewId`，保留既有输出事件和 Store。设计器复用当前卡片和报表 Store，嵌入式报表编辑使用当前仪表盘上下文、草稿保存与返回事件。桌面并列显示主要内容，390px 纵向呈现，关键操作可键盘到达。用同一隔离仪表盘验证 v1 持续可读、指定及错配 v2 待办、独立签署及手动发布后原链接切换，以及报表草稿到正式可选和仪表盘实际取数。

回滚确认说明恢复所选历史布局和受众，卡片继续跟随兼容报表的当前正式发布。发布或回滚冲突后，版本读回成功时通过现有 `changed` 事件刷新目录，撤下已失效的发布状态。最新已批准版本曾发布且当前已无生效发布时，目录显示「已下线」。发布、回滚或下线请求成功后，在原版本弹窗显示命令返回的发布记录编号，并独立读回当前版本。读回失败保留写入回执、版本重试入口及原选择的版本编号，撤下旧详情和动作。重试只读，恢复后从新列表找回原选版本，原选版本已不可见时使用新列表首项。焦点仍属于原确认流程时，读回成功后移到带共享焦点样式的回执，读回失败时移到重试按钮；从重试恢复时聚焦可用的版本选择控件。用户主动移焦时保留其选择。验收覆盖确认期间下线、旧回滚失败后目录读回、已发布卡片使用当前报表取数，以及回滚成功后版本连续读取失败、重试防重和恢复原选版本。

开发与审阅目录中，最新批准尚未用于发布且审阅资格明确失效时，状态显示「审阅资格失效 · 待重新送审」，主操作为「查看审阅」，作者仍可打开「送审检查」。已用于发布的版本继续按发布状态展示。目录读取带回最新审阅的资格，详情成功回读后用 `reviewer-eligibility` 将同一审阅的资格更新到原行；关闭仍回到原操作。重新送审生成新冻结版本，使用独立审阅人的验证与决定，旧审批保留在历史中。验收使用资格在确认期间变化、刷新目录、重新送审并发布三条实际路径核对状态和焦点。

键盘登记期间保留登记按钮焦点并阻止重复触发。登记成功且回读同一版本后，如焦点仍在原按钮或随其卸载而丢失，将焦点送到具名验证回执，下一次 Tab 可到核对复选框。读取失败时同样条件下聚焦重试按钮，提交失败则保留原按钮及就地错误。用户已移开焦点时，迟到响应不得移动焦点。关闭复核弹窗后优先回到打开它的主按钮或更多菜单按钮；从待办链接直达时回到当前仪表盘的目录操作，目录项不可用时回到目录标题区。地址仍保留工作空间和分类。沿用弹窗原有 Props、Emits 和 Store；使用相同的桌面与窄屏交互。验收核对真实预览完成、键盘登记、回执与下一步焦点、关闭回焦、迟到响应和目录项已不可用的情况。

登记提交成功后的版本回读，保留当前冻结版本的只读内容和仍可使用的焦点，回读中禁用审批、切换版本及其他写操作，关闭预览并清除待登记编号。版本回读失败撤下旧版本和权限相关操作。如果焦点随区域撤下而丢失，聚焦「重试读取版本」。重试只读取版本，不重复提交登记。键盘重试后若原焦点随按钮卸载而丢失，成功时聚焦实际读回的同版本验证回执，无该回执则聚焦版本选择；失败时回到重试按钮。验收以隔离实例的写请求日志、版本读回和浏览器实际焦点核对这三条路径。

仪表盘目录标题区、复核说明及验证回执是程序回焦目标，使用共享 `ui-focus-target` 样式。键盘焦点可见时使用主题色实线 2px 和间隔 2px，随后 Tab 继续页面原顺序。目录项在另一页或当前结果缺席时，标题区获得焦点，目录筛选与页码保持当前值。样式不新增 Props、Emits 或 Store 依赖。验收用真实分页核对标题区及原按钮回焦，并在浅、深主题检查边线与下一步 Tab。

已发布报表目录和仪表盘目录的常驻刷新按钮在读取期间保持可聚焦，以 `aria-disabled` 标记等待并阻止重复触发。从错误区触发「重试读取列表」时，若焦点仍在该按钮，先移到常驻刷新按钮。实际读取成功、再次失败或返回空目录后保留该焦点及后续 Tab 顺序。用户主动移焦或切换分类时保留其选择。刷新及重试只读取当前分类、已提交的筛选和页码，读取失败撤下旧行与总数，搜索框里尚未提交的输入仍保留。两个目录共用刷新和重试的焦点规则，沿用页面 Props、Emits、Store 与读取接口。验收在 1024、736、390、320px 浅深主题核对重复键盘触发、连续失败、实际恢复、主动移焦、无匹配结果和打开阅读后返回目录。

导出、订阅、领取、送达、到期和实际获权分开表示。保留原任务编号与请求来源，未知结果不重复写入。停止或未来规划能力只显示既有未启用状态。

报表导出与订阅（图册 23 左页）使用共享页头和编号表格，分别显示格式、审批与领取状态、有效期，及订阅间隔、最近交付或观测和实际状态。导出使用服务端分页，申请仍从可访问的正式报表发起。`ReportExportsPanel` 的 `canRequest` 由外层根据报表查看和导出权限提供，只控制前往正式报表的链接。导出详情由现有 `export` 地址确定，独立于列表读取和重试，保留空间及分页；未确认、到期及权限版本不支持时不呈现下载或审批操作。预览读取失败可就地重试，写入回执和后续读取失败分开呈现。按当前接口提供 CSV、JSON、XLSX 和个人订阅，图册中的 PDF、团队收件人和全量多条件搜索需要独立业务能力。

报表导出的详情标题、预览结果标题及审批回执使用共享焦点样式。快照预览和详情重试在等待时保留原按钮，以 `aria-disabled` 表示并拦截重复读取。再次失败时保留原焦点，成功时在仍持有该焦点的情况下移到对应标题或原审批回执。取消审批确认回发起按钮；实际审批成功后关闭预览，若详情读回失败，保留审批回执并聚焦只读重试入口。保持页面打开时，按记录有效期更新目录和详情状态，撤下到期快照的预览、审批及领取入口，并关闭已打开的预览、清除其数据。失效入口持有焦点或预览关闭时回到同一快照详情标题。用户已移焦及切换对象时保留其选择。沿用 `ReportExportsPanel` 的 Props、Emits、Store、快照版本和权限。验收覆盖动作受控主管的真实预览、模拟读取失败、重试、取消零写入、审批后同一快照读取恢复，以及待审批和已批准快照在页面停留期间到期。

导出记录表格与正式报表目录共用行操作焦点滚动。Tab 聚焦「查看详情」或关闭详情回原行时，表格只在需要时调整自己的横向位置，在按钮两侧保留共享焦点轮廓所需的 5px。已有横向滚动、按钮仅部分可见时也须显示完整按钮和轮廓。可横向滚动的表格区域自身聚焦时，用左右方向键各立即移动 40px，避免紧接着按 Tab 时旧滚动动画把新焦点带出视口。沿用现有区域名称、路由、Props、Emits 和 Store。验收覆盖 1024、736、390、320px 浅深两主题、部分可见时聚焦、方向键后立即 Tab 和关闭回焦。

订阅计划、交付记录、指标告警用共享键盘分类，按当前分类读取，失败时撤下旧行、旧操作和总数。编辑期间不自动替换报表选项或表单内容。交付及告警详情保留工作空间，可直达和重试，切换时取消或丢弃旧请求。继续使用原快照有效期、冻结发布号、权限和告警恢复判断。受众与执行契约（图册 23 右页）在现有版本与发布、契约编辑和受众提案入口呈现。受众提案先独立核对当前正式发布、个人及组范围和执行账号编号，再编辑受众；失败不可提交，可重试，成功按基准发布号送独立审批。页面不读账号凭据。导出、订阅与受众组件无新增 Emits 或 Store 依赖。窄屏表格局部滚动，验收覆盖分类隔离、读失败、直达、到期、审批前后权限和受众基准。

#### 常见图表与仪表盘样板（#45）

报表设计器「展示」沿用现有配置区。类型列表保持原有八项及标签，补充横向条形、面积、散点、直方、漏斗和热力。饼图下方提供「实心饼图／环形图」样式，旧配置缺省时显示环形。样式保存在原报表配置，重开显示保存值。不同类型只显示所需字段，改类型时保留可用选择，清理不适用的设置。报表编辑器沿用已有属性、回执事件及工作空间 Store。新建图表用预览返回的唯一字段选择，已有配置可重开读回，旧值失效后由预览或保存反馈。

| 类型 | 字段和呈现 |
| --- | --- |
| 横向条形 | 类别轴在纵向，单个或多个数值指标在横向；按查询顺序展示，保留长类别提示和负值方向。 |
| 面积 | 横轴维度和一个或多个独立数值指标，原时间或类别顺序。缺失值保留间断，零值照实显示。 |
| 饼形、环形 | 同一类别和一个非负指标分别呈现实心与环形。配置不含样式时沿用环形。 |
| 散点 | X 和 Y 分别绑定不同的数值字段，按实际坐标显示每一行的数值对。 |
| 直方 | 查询先完成等宽且互斥的分箱，返回已排序的区间标签与一个非负整数频数。绘制相邻的等宽柱。 |
| 漏斗 | 阶段标签和一个非负数值，按查询返回的阶段顺序展示。各阶段值可直接核对。 |
| 热力 | 横向类别、纵向类别与一个数值指标，每组坐标唯一。色阶和数据表均可核对实际值，无记录的格留空。 |

同一 `ReportResult` 接收图表类型、保存配置和本次查询结果，服务报表预览、正式阅读及仪表盘卡片。表格和透视表保持现有展示，图表保持可查看原始数据的入口。空结果使用空态，缺失字段、重复类别或坐标、无效数值和不适用的类型显示可操作反馈。散点允许多行拥有相同坐标，保留原行对应关系供查看明细。沿用主题令牌、图例、键盘访问、避免不必要动画及编辑区现有响应式布局。桌面按已有卡片宽度布置，390px 按原顺序堆叠，图表和宽表各自限制滚动范围。

三张样板使用已获准报表组成。经营总览核对指标与同一日期筛选，专题分析核对跨卡参数和比较组水位提示，异常核查核对明细、单卡错误重试和权限限制。逐图回执须来自同一候选的实际报表预览、持久配置、正式报表和仪表盘卡片。原发布和交付限制沿用既有契约。

#### 阶段 4 交付页面联验（#14）

沿用「报表 → 报表导出」「报表 → 订阅与告警」「仪表盘」与站内通知。复用 A2 分类、列表、详情和空态。一般的配置、审批和授权管理沿现有权限及接口处理。隔离夹具可使用这些接口准备成员、计划和审批事件，页面验收核对使用者实际看到的状态、内容和拒绝反馈。

- **正式导出。** `ReportExportsPanel` 维持当前 `canRequest`、`export` 深链、无新增 Emits。区分待审批、已批准待生成、生成中、生成失败、可领取、不可领取和已到期。兼容记录保留原下载资格和入口。新正式文件仅在服务端确认本人可领取时展示「领取文件」，一次操作先申请凭证，再由同一会话兑换；凭证仅在本次请求内使用。收到失败或当前记录失效时清除领取操作并读回状态，保持原详情及重试入口。
- **报表订阅。** `ReportSubscriptionsPanel` 维持当前 Props、Emits 和外层许可，个人计划显示本人确认及到期状态，确认后读回同一计划。交付分类提供本人团队结果，按服务端期次状态展示，读取固定期次时重新核验权限。可从 `team_delivery` 打开本人 UUID 对应结果。拒绝、到期、读取失败及更换身份或空间时清除旧业务内容，保留允许的状态及重试入口。
- **仪表盘交付。** 现有仪表盘入口接入本人的交付记录，逐次核对具体文件或快照。结果按整板与指定卡片交付，展示可选卡受限状态、固定数据时间及领取期限。必需卡片失败时无可领取结果。导出按服务端凭证兑换文件，订阅展示固定卡片期次，均按当前权限处理拒绝。个人指标卡的告警按所属计划独立读取和保存处置，快照到期后仍可在具有资格的情况下核对原触发值、恢复值与处置。
- **通知直达。** `InboxView` 复用既有 Props、原空间确认和单条已读逻辑。新交付通知先解析当前通知的主体与链接期限，再按服务端返回的资源类别与标识跳转；结果页面重新检查当前权限。过期、拒绝或失败在原通知详情显示，保留历史状态、原焦点和允许的重试。通知详情不加载业务数值。

详情和列表分别提供加载、失败、空结果、到期与拒绝提示，离开详情和返回沿现有地址及焦点规则。窄屏局部滚动，主要操作可用键盘触发，重复点击在途操作不会重复写入或兑换。当前候选在本地隔离环境验证实际文件、两名成员各自的数据、撤权前后固定期次、整板与单卡、清理后告警和通知到期，页面证据覆盖桌面及 390px 窄屏。

### 4.4 管理、审批与诊断

<a id="management-menu-41"></a>

#### 管理菜单与办理中心（#41）

以用户确认的三项管理菜单预览为准。PC 从顶部「管理」下拉进入，页面使用 A2 全宽列表及横向分类。空间、申请和审计均按列表进入具体对象。窄屏使用现有全局菜单，分类可换行，表格仅在局部滚动。

- 「管理 → 空间管理」使用统一工作空间目录 `/spaces`，按[空间目录规则](#unified-workspace-directory)加载当前身份可管理的列表。详情页显示空间名，成员、用户组、角色与分配、资源授权、发布与交付策略、治理审批和菜单配置按各自许可提供。原空间、成员与申请深链受相同许可校验。迁移和治理恢复的专项直达遵守原资格。
- 成员页使用一套正式列表及成员详情。去掉嵌入的兼容用户管理及其提示，获准的空间成员维护由现有空间成员接口承接。目录角色、成员有效期和受管角色分配分别展示，未获准的管理动作隐藏。账号级创建、认证和安全操作按已有身份作用域处理。
- 办理中心 `/handling` 按现有获准且可见的 `/inbox`、`/business-operations`、`/tickets` 依次呈现待办、业务办理、数据库变更工单。共享分类组件仅挂载当前获准面板，地址用 `section=todo|business|tickets` 记录主分类，待办内部沿用 `tab`。默认进入获准的待办或首个可用分类。未获准直达显示可用入口及权限反馈。业务操作与数据库变更继续使用各自的申请、复核、执行、回执及权限。
- 办理中心内的待办在列表工具栏用「事项来源」选择待我处理的业务审批、通知、治理申请和有资格时的连接任务。页头只保留办理中心的三项横向页签，独立待办和通知按各自入口显示现有分类。业务待办行的「查看申请」一步按原工作空间和申请编号打开办理中心的业务详情。治理待办带原工作空间和指定申请编号打开原空间的治理详情。详情的「返回待办」恢复原来源、页码及触发条目，读取完成时优先回焦原条目的直达操作，再回退到条目标题。条目失效、撤权或空间、身份变化时按有效许可读回列表，并将焦点交给可用的列表或状态入口。待办摘要与通知已读各自维护；工单在独立页签使用原数据源。
- 顶栏继续接收 Store 生成的已获准入口；空间目录与办理中心由路由和当前主体的 Store 管理，无新增对外事件。现有办理页面嵌入中心时使用适配的标题层级，原直达继续工作。待办回链只携带经校验的原空间、主体、分类和目标条目标识，保留原对象身份校验及权限复查。
- 本地验收覆盖三项顶栏和各自落地列表、同空间与跨空间管理核对、兼容入口移除、不同资格下的页签及直接地址、两笔不同业务申请和治理申请直达、返回原条目、撤权和读取失败。核对 PC 宽度、窄屏、键盘及焦点，并保留同一候选的实际浏览器证据。

空间管理（图册 12、13）按获准的当前分类及其操作依赖读取，切换时丢弃旧请求，读取失败撤下旧记录及操作并可重试。成员在接口返回的当前空间范围内按用户名和访问状态筛选，显示基础角色、权限方案、有效期和现有托管信息。角色用编号目录和同页详情区分角色修订、已配置许可与运行阶段，现有调整、停用及独立复核入口保留。分配以连续表格区分成员与用户组、角色修订、已批准成员、期限及撤销状态。仅保留当前接口支持的单来源操作。成员和角色可键盘打开详情，关闭后回焦；窄屏表格局部滚动。

<a id="space-members-role-flow"></a>

空间管理的成员角色流程按[本期 Must 计划](../项目管控/开发路线图与当前任务.md#space-members-must-plan)实施。进入空间后先展示成员搜索、状态筛选和全宽成员列表。点「查看详情」呈现成员概要、角色分配和角色调整记录，返回列表保留筛选并回焦原成员。角色表只在表格区域局部滚动。显示当前系统记录的角色分配及其修订，直接分配标明成员来源，用户组分配标明组名与获批关系。经组分配须同时核对当前组成员与获批成员名单。角色分配按截止时间、撤销和成员状态显示其记录状态，和成员自身期限、本人运行时许可分别表述。有成员查看许可但无角色分配查看许可时，只呈现成员资料及已有获准动作。分配与申请读取失败分别撤下旧结果并原位重试。

从可调整的成员详情打开原治理变更对话框，固定当前空间及该成员，展示已有可用治理委派、可分配角色和授权截止时间。表单仍经「查看影响」和「提交独立复核」，申请人及受益成员回避，提交后显示「待复核」，分配表以实际读回为准。审批详情回链只对有原空间成员查看许可的单人成员分配提供，保留原成员编号与已有搜索条件，进入后重新读取当前分配；以申请编号核对新分配，区分待复核、已批准且分配已读回、读回失败及无当前有效分配。未知、失效或无权的成员与申请链接不显示其他对象的详情。申请链接可刷新及分享，在现有空间校验及申请读取许可下定位。

成员详情面板接收选中成员、已获准的分配和调整记录、分配读回状态及动作资格，发出关闭、重试、调整角色和查看指定申请事件。空间页面管理路由、成员筛选、读取取消和权限上下文。治理变更对话框新增可选的固定成员输入，保存事件返回实际提案回执，其余入口沿用原交互。关闭详情或弹窗回原触发控件，进入申请或回原成员时聚焦详情标题。验收覆盖桌面、代表性窄屏、浅深主题、原空间许可、独立审批与所授成员本人会话。

空间管理的共用页头刷新保留等待时的键盘焦点，标记不可重复触发。失败反馈中的「重试读取分类」持有焦点时，触发重试先把焦点交给同页常驻的刷新按钮，等待和读回后均可从该按钮继续操作。用户主动移开的焦点由用户控制。迁移与回退面板沿用自己的刷新与回执规则。

成员冻结、角色停用、撤销角色分配或委派、禁止功能操作的入口按各自动作许可显示。提交收紧时服务端按请求动作核对同一许可，并核对有效委派、目标和配置基线。成员冻结成功后重新读取成员与托管清单，原会话失去当前空间业务访问，个人安全设置及其他获准空间仍可进入。沿用现有弹窗和 Store。验收包括具有成员退出许可的管理员实际冻结、隔离成员旧会话拒绝、其他空间读回和托管清单。

键盘翻页后聚焦读回的结果页码；读取失败聚焦重试，空结果将焦点留在列表所在区域。通知已读写入成功且仍持有发起操作焦点时，聚焦读回的未读数，包括零条。写入失败时保留回到原按钮的路径，列表重读失败时聚焦重试。操作期间已移动到其他控件的焦点保留，过期的读取或离开的工作空间不得移动焦点。详情标题及结果摘要使用共享焦点样式。验收核对跨页批量写入只覆盖已确认的通知上限、晚到通知与其他空间和收件人保持未读，以及列表收缩后的焦点。

通知与业务待办的「刷新」和「重试读取」共用手动读取规则。读取期间保留触发按钮和键盘焦点，以暂不可用状态防止重复提交，重试期间同时保留原错误和进度状态。刷新成功时焦点留在刷新按钮，失败时转到重试。重试再次失败时留在重试按钮，恢复时通知聚焦已读回的未读数，待办聚焦页码摘要，待办为空时聚焦结果区域。用户主动移焦或切换授权范围后不夺回焦点。沿用 `InboxView` 的输入、事件及 Store。验收覆盖通知和待办两种列表、连续读失败、实际恢复、空结果、重复按键和主动移焦。

#### 4.5.1 登录反馈（2026-10-29）

登录流程使用表单内反馈，不使用全局Toast承载必填、认证失败、网络异常或登录成功。此次范围包含密码登录、MFA/恢复码、SSO交接和“忘记密码”说明；其他页面的全局消息保持原行为。

- 空字段在相应输入框下显示14px错误文本，关联 `aria-describedby` 与 `aria-invalid`；提交后将焦点移到第一个无效字段。输入修改后只清除对应字段错误。
- 用户名/密码认证401统一显示“用户名或密码错误，请重新输入”，不暴露哪个字段正确。MFA失败保留挑战上下文、清空因子并在因子输入框下提示；空因子可提交校验，不使用永久禁用按钮掩盖原因。
- 认证和网络错误放在提交按钮之前的表单内反馈区，保持到相关输入修改、切换认证方式或再次提交。网络/超时/服务故障明确说明服务问题；密码登录失败保留输入，成功及切换验证阶段按原逻辑清除密码。错误使用 `role=alert`，不重复Toast。SSO保留服务返回的可解释错误或中文兜底。
- 密码提交失败并恢复表单操作后，若发起提交的控件因忙碌禁用而丢失焦点，回到该输入框或登录按钮。等待期间主动移到其他控件时保留已有焦点。用键盘核对错误凭据及延迟失败后的继续编辑。
- 反馈采用共享 `.editorial-form-feedback` 样式：14px正文、12px内距、3px圆角、1px语义细边，错误使用danger/fill令牌，普通说明使用inset和正文令牌；16px图标仅装饰。无阴影、渐变、自动消失、位移动画。内容按实际高度撑开，窄屏自动换行，不预留大块空白。
- 登录/验证提交中防止重复请求，表单标注 `aria-busy`。成功按钮显示“登录成功，正在进入…”，通过礼貌状态区域播报；立即执行原安全跳转，不加展示延迟、不弹成功Toast。跳转完成前保持不可重复提交；跳转失败提供表单内说明与“进入工作台”重试入口，不再次提交凭据。
- “忘记密码”在表单内展开“请联系管理员重置密码”的持续说明，按钮带 `aria-expanded/controls`，不弹消息。
- LoginView不新增Props或Emits；状态为字段错误、认证错误、成功与重置帮助，仍依赖user Store。密码与MFA Store方法增加可选 `silentError` 参数，默认false；登录页传true，复用请求层已有静默能力，不改变后端API、认证判定、会话持久化或其他调用方的消息行为。
- 密码或 SSO 进入两步验证后，先解除提交状态，再把焦点移到已可编辑的因子输入框。SSO 挑战提示「单点登录已验证」，密码挑战保留原提示。因子验证失败后，保留挑战、清空因子并回焦，错误关联到输入框。返回密码登录后聚焦用户名。SSO 一次性交接完成或失败后移除地址中的 `sso=complete`，保留其他参数，刷新时由用户重新发起 SSO。验收用真实浏览器检查两种挑战的可编辑性、初始焦点和失败回焦。
- SSO 回跳失败使用密码表单的同一错误区域。收到 `sso=failed` 时显示一次解释并从地址清除该标记，保留其他参数。开始编辑用户名或密码、重新提交或切换验证方式时清除旧提示。验收覆盖未关联身份回跳、改用密码后只显示该次错误、刷新不恢复旧提示，以及提交失败后的键盘焦点。
- 从受保护页面发起单点登录时，保留站内原路径、查询参数与片段。原地址随本次单点登录状态暂存，由回跳恢复至登录表单。完成身份验证及适用的两步验证后返回原地址。回跳失败后改用密码也沿用该地址。无有效站内地址时进入当前身份的默认工作台，原地址继续经过路由的工作空间和权限检查。验收分别核对直接单点登录、单点登录后两步验证、失败后改用密码及工作空间确认。

验收覆盖：空字段焦点、错误凭据、网络异常、成功跳转、忙碌防重复、修改后清错、MFA/恢复码错误和SSO失败、浅深主题与窄屏、无重复Toast。真实认证与隔离模拟分开记录；不得使用现有账号连续猜错或修改真实权限完成验收。

#### 统一工作空间目录（#44）

#### 管理与平台管理职责（#44）

「平台管理 → 角色权限」展示全平台共享的业务 IT、业务主管、查看者以及各自页面与操作权限。读取内置角色目录，仅供查阅，页面没有工作空间选择器。「平台管理 → 工作空间菜单」单独选择配置目标，固定展示目标名称，沿用默认显示及按角色显示。选中空间时重新读取目标成员及动作回执，按照当前实际资格提供只读或编辑，选中目标不会切换页头业务空间。保存绑定显式空间及原版本，显示目标空间的保存回执，按原接口核对当前许可。目标改变或资格失效即撤下旧表单及回执。权限不足、读取失败、无选中目标和版本冲突分别反馈。矩阵空间菜单编辑只从平台管理进入，其他存量空间继续按现行授权处理。

矩阵空间的空间管理员可从本空间「成员」添加已有启用的平台账号、移出普通成员及为普通成员授撤业务角色。添加成功选中同一新成员，先建立空间成员资格，业务权限由角色分配获得。移出前确认目标账号和空间，成功后读回目录；原账号身份与历史记录继续保留。已有退出或停用记录的账号继续走对应重新加入流程。任免界面仅超管可用，空间管理员与业务角色授予分开。用户组及组授权的已有流程保留，成员详情仍能按原资格查看直接和用户组分配来源、期限及审批记录。默认工作空间切换到矩阵流程，其他已有空间沿用现行授权口径。

平台菜单组件接收所选空间编号作为路由来源，使用现有用户 Store 仅核对本人身份。空间授权面板接收目标空间编号和名称，通过事件回报关闭及变更，确认时复用服务器返回的资格、成员版本及状态。异步读取和写入的反馈绑定原空间和账号，权限不足及并发版本冲突在原界面提示。窄屏保留可换行分类和表单，表格区域局部滚动，弹窗关闭后回到触发控件或已更新成员。验收用隔离 PostgreSQL 和实际浏览器覆盖平台规则与菜单分离、双空间权限拒绝、超管无需加入的授撤和任免、空间管理员加人及移出、用户组来源、默认空间升级、新成员初始无业务权限、返回读回和窄屏操作。

角色分配对话框接收目标空间、可选初始成员及可见状态，原位显示保存后的角色和读回提示。父页在关闭后刷新流程记录并按原成员地址恢复，避免权限代次变化提前关闭正查看回执的对话框。组件使用作用域 API，避免以切换业务空间表达全局操作。

同一成员详情显示「当前角色」，内容按目标成员读取直接分配的角色，切换成员或空间时清除旧值。历史审批记录单列，直接角色读回失败可就地重试。已有技术维护移交入口在业务负责人模式下明确标明技术维护职责。

正式报表的详情和复核显示当前业务负责人及技术维护人。首次送审选业务主管，正式发布时登记。超管可在报表详情选择合格的接任人并保存。主管或超管在统一的复核界面审核冻结版本；已发布报表继续显示活动版本，业务审批和高风险数据审批按已有状态分开提示。读取负责人候选失败时就地重试，保存失败保留选择。报表组件按当前工作空间和报表编号读回，切换对象清理旧请求。验收使用 1440px PC 和 390px 窄屏，截图取自隔离候选的实际成员页、报表审核和换任后状态。

图册 20 的兼容用户管理在 `/users` 和空间管理的嵌入入口复用 `UsersView`，沿用 `embedded` 控制标题层级。用编号目录、带标签的用户名或邮箱搜索、分页和同页用户详情呈现既有角色、状态、最近登录、创建时间。角色资料独立读取，不阻断用户目录；写入所需的角色选项读取失败可重试。现有创建、编辑、职责、密码重置、启停和删除继续使用原接口及确认。目录失败隐藏旧记录和操作，重试及翻页沿用已提交条件。接口未提供全量角色／状态筛选及自定义排序，不在单页结果伪造全量筛选。

新建或编辑用户的弹窗每次打开读取基础角色。读取期间保留空的选择器和字段位置，单独显示读取状态。角色接口成功后，仅当默认角色或原角色存在于本次结果才回填。成功但无选项时显示「暂无可用角色」并禁用选择器和保存。失败就地显示原因及「重试读取角色」。关闭弹窗取消本次读取，清除选项和敏感输入，重开重新读取。读取、选择角色和重试均不触发保存。继续使用 `UsersView` 内部的请求状态和表单数据，无新增 Props、Emits 或 Store 依赖。

基础角色选项优先在字段上方展开，列表与字段同宽，长描述可换行。下拉收起时立即释放鼠标命中区域，选完角色可直接点击「取消」，不必等待收起动画结束。复验覆盖窄屏的鼠标点击、键盘收起与弹窗重开。

新建与编辑用户弹窗的保存按钮按「保存」和「保存中…」所需的最大宽度预留空间，提交中保留相邻取消按钮的位置。请求失败后在表单内显示错误，保留输入并恢复操作。复验覆盖窄屏和桌面的常态与提交中布局、重复点击及失败返回。

兼容用户编辑依据目录返回的 `can_edit_email` 决定是否可编辑全局邮箱。只具备当前空间角色编辑资格时，表单显示只读邮箱及原因，仅提交角色。确认写入后，在原目录显示「用户已更新」，权限更新导致原目录重新挂载时保留这条回执。列表读回失败单独提供重试，重试不重复提交。切换身份、工作空间或离开当前页面后清除回执。继续复用 `UsersView` 的 Props 和现有 API，回执只保留在当前浏览器页面。验收核对角色与邮箱实际读回、邮箱清空、无授权编辑、取消、目录重挂载及重试。

兼容系统设置用共享键盘分类切换资料偏好、身份安全、空间设置、用户组、数据库驱动及已获准的平台设置。`tab` 保留在地址中，未授权类别不挂载，继续沿用旧兼容和受控路由边界。用户组用编号目录、带标签的搜索、分页和同页详情展示版本、成员数量、说明、更新时间及现有成员编辑。成员只显示接口返回的编号，编辑器沿用已有成员选择器。组状态、组权限及兼容协议许可需要对应字段。修改密码用表单内反馈，失败清理当前密码，成功返回登录。三个页面无新增组件事件或 Store 依赖。窄屏仅表格区域横向滚动，验收覆盖兼容直达、角色差异、旧地址重定向、失败重试、焦点及浅深主题。

兼容空间设置的未知数据时效开关显示最近从服务端读回的状态。保存和重新读取期间保留开关焦点，以 `aria-disabled` 标记并拦截重复提交。保存失败保留已确认状态、显示就地错误，允许再次操作。已确认写入但读取失败时保留上次确认的显示，明确当前状态待读回，锁住再次写入，并提供只读重试。读取成功后以当前空间实际返回值更新开关和回执。从键盘发起且焦点仍在原操作时，保存失败移到错误，写后读取失败移到重试，成功移到回执；用户主动移焦或离开时保留其选择。继续使用当前工作空间、现有工具权限、Props、Emits、Store 和接口。验收用合成空间四档宽度浅深主题核对读回、读写故障和只读重试，再核对只读账号的兼容入口与外观偏好刷新。

用户组的保存按钮在提交时继续持有键盘焦点，以 `aria-disabled` 标记等待并拦截重复提交。写入确认后在当前目录呈现回执，按当前搜索条件及页码重新读取。权限更新使同一路由重新挂载时，保留搜索和回执，列表、已选对象及编辑器由当前权限重新确认。读取失败单独给出重试，重试只读取目录。旧版本被拒且权限上下文仍在时，在原表单显示原因并保留输入。权限重核清除旧编辑器时，在当前目录提示核对本次保存结果和最新版本，再重新编辑。离开页面、切换空间或身份后，原页面回执及搜索不带入新页面。沿用现有用户组接口、Props、Emits 和 Store。验收覆盖四档宽度浅深主题、在途键盘防重、两种版本冲突、读回失败、成员编辑、删除后的组授权收回。

身份分类展示已部署 OIDC 的发行者和当前身份关联，使用连续表格、已知版本及操作确认。发现接口或关联列表读取失败时清除旧列表，保留未提交表单供重试；保存与读回分别提示，读回前不重发变更。服务端凭据、回调和 Scope 不在现有页面编辑。运行分类显示现有审计队列、备份监测、活动告警、后台任务回执与留存设置。未知字段保留未知语义，实测零值照实显示。刷新可保留标注的上次快照，失败清除快照及其时间；配置仍按现有部署流程维护。图册里的通知渠道、Webhook 和交付设置缺平台接口，不显示虚拟编辑项。两面板继续供兼容设置复用，无新增 Props 或 Emits。验收覆盖分类直达、失败重试、读回、权限变化、旧链接和两主题窄屏。

同条件刷新运行状态时，将上次读取时间与上次快照说明放在保留内容之前。上一快照的概况、回执和留存区标记忙碌，旧回执的清理明细暂停展开或收起。刷新按钮在等待中保留焦点并阻止重复读取。失败清除旧数据与时间；键盘触发就地重试时，焦点移到常驻刷新按钮，成功后恢复明细操作并显示本次读取时间。兼容系统设置中的同一组件沿用该反馈规则。

自动备份在「最近成功」栏保留服务端最近一次成功时间。当前备份成功且有归档文件名时，回执显示文件名和实际大小；成功回执缺文件名时显示「归档未记录」。运行中显示「正在生成归档」，失败显示「本次未确认归档」。运行中和失败回执的空文件名及占位字节数不作为归档大小展示。活动告警按服务端状态显示，留存仍以部署配置为准。沿用原运行状态接口和组件依赖。验收覆盖从无成功备份到首次成功、实际失败保留上次成功、恢复和隔离归档留存。

## 5 组件契约

优先复用现有组件；下表的调整是设计目标，API/Store调用仍由原业务方负责。新增组件或改Props/Emits时，在实施前明确迁移调用点。

| 组件/模式 | Props或输入 | Emits/插槽 | Store与状态 |
| --- | --- | --- | --- |
| PageHeader | title、description?、eyebrow? | actions | 无Store；单h1，嵌入标题按原embedded规则降级 |
| PageState | title、description、tone?、loading?、heading? | actions | 无Store；loading=status，danger=alert，tone图标明确；加载优先 |
| ThemeSwitcher | compact? | 原主题选择 | 只用主题模块，不依赖权限Store |
| WorkspaceSwitcher | options、modelValue、label?、contextLabel?、loading?、disabled? | change(number) | 展示组件，无API；布局执行原空间切换与权限加载 |
| NotificationIndicator | unread、known?、loading?、failed?、qualified? | click | 无Store；未知不能当零，失败有具名状态 |
| InboxButton | 原输入 | 原通知导航 | 用户Store与摘要API；身份/空间绑定，失效清理，不自动已读 |
| EditorialNavigation | groups（已获准的id/label/path分组）、activePath、contextKey? | navigate(path)、openChange(boolean) | 无Store/API；布局传入权限代次，变化时关闭导航；移动抽屉复用基础组件焦点与滚动锁定 |
| CardActionMenu | 沿用现有菜单数据、disabled/busy | 原动作事件 | 不扩权限；Enter/Space打开，方向键选择，Esc回焦 |
| 数据表/目录 | 列、数据、排序、分页及选择由原调用方提供 | 原筛选/打开/分页 | 不二次聚合或截断精度；长标识符可查看 |
| 表单控件 | 原值、label、hint、error、disabled、busy | 原更新/提交 | 标签常驻、错误就近；提交失败保留输入，错误摘要可定位 |
| 对话框/抽屉 | 原open、对象和busy | 原关闭/确认 | 焦点约束、回焦、滚动锁定；对象变化清理旧状态 |
| EChart | 原option、尺寸、主题 | 原图表事件 | 主题令牌与reduce-motion；不改变数据计算 |
| GlobalSearch | 原关键词与结果 | 原搜索与跳转 | 每次输入使旧请求失效；不足两字清空加载，失败不冒充空结果 |

原glass-card/glass-panel/liquid-button等类名目前是实现遗留，不再定义A2材质。实施时统一改共享映射或迁移用途类，不能逐页覆盖。Element Plus样式继续统一在vendor级联层，utilities保留尺寸布局权，禁止未分层副本。日期弹层保持前移组/年/月/后移组一行，触控仍能操作。

按钮：主操作朱红实底，次操作透明或实底细边，行内打开用文本，危险操作暗红文字+明确动词。每个任务区一个主要操作；取消不与主要提交同等突出。禁用/忙碌不可激活，busy不能阻断区域内仍合法的其他按钮。图标有名称，装饰图标aria-hidden。选中有aria-current/selected/pressed，展开有expanded/controls。

浮层尺寸：确认对话框约440–560px，详情抽屉约480–640px且不超过视口减24px；编辑复杂对象可使用宽工作面，不强行塞窄抽屉。关闭目标44px。拖动、悬停和右键能力必须有可发现替代入口。

## 6 动效、反馈与状态

### 6.1 动态规范

| 按下/释放 | 70ms压低表面、160ms恢复 | 不闪光、不产生形变；业务成功另有回执 |
| 页面进入 | 180ms轻淡入 | 无离场等待，无整页移动，不因筛选/主题重播 |
| 抽屉 | 进入220ms、退出160ms | 小幅横向与遮罩同步，立即可操作，支持打断 |
| 标签切换 | 120ms选中标记 | 内容位置稳定，不用滑动整张数据表 |
| 图表更新 | 最高200ms | 大数据/实时连续更新可关闭；不得改变数值 |
| 加载 | 稳定占位、小指示器与说明 | 不制造虚构进度；短请求不闪烁大遮罩 |

统一减速曲线cubic-bezier(.2,.8,.2,1)。无循环装饰、瀑布式入场或鼠标跟随光效。减少动态时禁用位移、缩放、过渡及图表动画，保留全部最终状态。Monaco内部控件沿用原生反馈，外部业务控件统一。

### 6.2 必须覆盖的状态

| 状态 | 内容与动作 |
| --- | --- |
| 加载 | 说明正在处理对象；原位置占位；可取消按既有能力 |
| 空数据 | 当前获准范围无记录；合法创建/返回入口 |
| 无匹配 | 保留筛选，调整或清除条件 |
| 请求失败 | 原位置原因与重试；未知写入结果先核实 |
| 无权限 | 不暴露受限内容；查看个人权限或安全返回 |
| 未配置/停用 | 明确缺项及现有合法配置入口，不画成已启用 |
| 处理中/取消中 | 防重复提交，保留上下文，不能过早报完成 |
| 待审/已批准待发布 | 固定对象版本、下一步与真实回执 |
| 截断/部分失败/未知时效 | 与结果同屏显示限制和来源 |
| 冲突/失效 | 说明版本或权限变化，刷新核对，不自动重提 |

切空间、身份、权限代次、冻结及退出必须清理旧结果、弹层、选择和请求；迟到响应不覆盖新上下文。菜单隐藏不等于撤权。日期、时间按应用约定显示时区，单位、空值及错误码的用户说明不能丢失。

### 6.3 数据加载（Loading）专项规范

本节补齐A2加载态的设计目标与实施验收要求。**规范已明确，不代表页面代码已统一实现或完成验收。** 适用于首次取数、刷新、筛选、分页、异步选项、详情、图表、查询执行和提交；既有请求、权限、取消、幂等及结果核实契约优先，不因视觉需求改变业务语义。

#### 6.3.1 状态与展示优先级

加载不是“数组为空”。必须由实际请求状态驱动；请求尚未完成前，不显示“暂无数据”“共0条”“无权限”或成功。返回成功且确认结果为空后，才进入空状态。

| 状态 | 进入条件 | 内容及退出要求 |
| --- | --- | --- |
| 未开始 | 等待用户选择来源、参数或明确执行 | 显示操作指引，例如“选择数据源后继续”；不播放无限加载 |
| 首次加载 | 当前上下文没有可展示的有效结果，请求进行中 | 保留页面框架，在目标区域占位；结束后原位切换为结果、空、错误或受限状态 |
| 同条件刷新 | 同一身份、空间、权限代次、对象和请求参数再次读取 | 仅符合6.3.3时可保留旧结果，并明确“正在更新”；不可伪装成最新结果 |
| 条件切换加载 | 搜索、筛选、排序、分页、对象或数据源变化 | 数据区换成稳定占位；保留新条件，不把旧行、旧页码或旧统计挂在新条件下 |
| 部分完成 | 多个独立区块中一部分已有有效响应 | 已完成区块可读；其余区块独立显示加载或失败，不用整页遮罩覆盖 |
| 执行中／取消中 | 后端或现有执行状态机确认进入相应阶段 | 明确当前阶段；收到终态或核实结果后退出，不因请求被abort就宣称服务器已停止 |
| 失败／结果未知 | 接口失败，或写入/执行是否完成无法确认 | 退出普通Loading；读失败按能力重试，结果未知进入核实路径，不显示普通“重新提交” |

权限撤销、冻结、身份或空间失效优先于任何保留旧结果的规则：立即清理受影响内容及选项，停止该上下文的加载呈现，进入既有安全状态。旧请求迟到后不得恢复内容；失败响应也不能覆盖更新一代的成功结果。

#### 6.3.2 A2视觉与反馈时序

| 项目 | 统一要求 |
| --- | --- |
| 骨架材质 | 静态暖灰/暖石墨条，使用共享表面令牌；无扫光、渐变、脉冲和假文字，不显示假金额/假曲线 |
| 骨架尺寸 | 文本条高12px、标题条高16px、圆角3px；按真实列宽排列，不能随机跳变宽度 |
| 列表骨架 | 默认6行，行高按该列表既有密度；若已知末页不足6项或已有稳定页高，沿用其几何尺寸；骨架行不计入结果数量 |
| 图表骨架 | 保留图块标题与已知单位，图面使用单一静态占位；没有结果时不绘制虚构坐标值、趋势线或指标0 |
| 加载指示器 | 控件内16px，区域状态20px，独立整页状态24px；使用强调色、1.5–2px线宽，不用巨大居中旋转图标 |
| 加载文案 | 14px正文或12px辅助说明，明确对象，如“正在加载任务记录…”；避免只有“Loading…”或“请稍候” |
| 遮罩 | 默认只作用于数据/详情区，保留工具栏与合法取消入口；不得用模糊掩盖旧敏感内容，不用整页遮罩替代局部忙碌状态 |
| 结束反馈 | 数据到达立即展示，保持表头、字段、按钮和外框位置；不增加列表逐行入场或整页位移 |

以下为产品交互默认值，可在有明确场景理由时于本节登记例外；不是响应时间承诺，不恢复性能基准、压测或p95要求，也不修改现有请求超时：

1. **请求开始立即**更新内部busy状态、区域aria-busy和防重复提交。点击提交的按钮立即改成“保存中…”等准确文案，不等待视觉计时。
2. **读取不足150ms**：保留稳定区域，不闪出旋转器、大遮罩或“暂无数据”。首次加载的中性占位区域立即保留，装饰性指示器延后出现。
3. **读取达到150ms**仍未结束：显示对应静态骨架或局部指示器，并提供加载对象文案。显示后没有强制最短停留时间，不能为动画拖延成功、失败或安全清理。
4. **等待达到5秒**仍未结束：补充“仍在加载，可继续使用其他区域”等说明；提供已有的取消或返回能力。仅在阶段真实可得时显示“正在连接／执行／读取结果”等阶段，不编造原因或剩余时间。
5. 超时依据现有API/执行限制判断，不因超过5秒就显示失败。不能在仍执行时叠加可重复触发的“重试”；读请求须先终止/失效前一代，写入或未知执行须先核实。
6. 防抖等待和后台静默轮询不反复启动整块骨架。前台每次有效请求有独立代次与计时器，结束、取消、切换、卸载都清理计时；不重放已完成请求的延迟Loading。

减少动态效果时，旋转器改为静态标记配状态文字，骨架仍为静态；终态信息完整。强制色模式以轮廓和文字识别状态，不能依赖浅色填充消失后仍可辨认。

A2 页面预留垂直滚动条位置，列表长度变化时保持页面和筛选栏宽度。已发布报表目录在读取和成功时共用同一表头与固定列宽，读取中将表格标记为忙并清除旧行。加载提示置于表格外，窄屏横向滚动由表格区域承担。实际数据行数决定数据区高度。验收以同一屏宽和主题下的页头、筛选、表头位置、列宽以及控件可见性为准。

#### 6.3.3 旧数据、交互与焦点

同条件刷新只允许暂留仍有效的**读取结果**。调用方必须能确认身份、空间、权限代次、对象与请求参数均未变化；明确显示“正在更新，以下为上次结果”及已有的结果时间。无法证明上下文一致或现有状态机已经清理结果时，使用占位，不额外复制旧数据来维持画面。

保留旧内容期间，禁用依赖当前结果的行操作、批量选择、导出和提交；刷新入口禁用重复触发。原页面合法的导航、修改筛选、搜索输入及取消仍可用。静默轮询只有在原业务契约允许时保留操作，并继续由提交前版本/权限检查约束；不得把所有轮询升级为阻塞加载。

条件切换时清理旧选择，表头与工具栏不消失，页码按既有逻辑同步；新结果确认前总数显示“正在确认”，不显示假0。输入和筛选保持用户新值；旧请求失效后，新请求的加载与终态独立处理。

刷新失败不得继续将旧结果当作当前有效结果。已用useReportRun等逻辑清空结果的SQL、报表和受管内容继续清空；其他明确允许留存的只读目录只能以“上次结果（更新失败）”呈现不可操作的参考，附错误和重试，不能残留最新/成功标记。不跨权限边界显示此参考。

加载不自动抢焦点，结束后也不将焦点跳到第一行。尽量保留工具栏与触发器DOM；被清理的数据行若持有焦点，将焦点安置到具名结果区域或原工具栏。局部禁止操作不能吞掉Esc、取消或可用导航；禁止给含取消按钮的整块区域设inert。

#### 6.3.4 按场景应用

| 场景 | 首次或条件变化 | 刷新与可操作范围 | 结束／异常 |
| --- | --- | --- | --- |
| 报表、来源、连接、任务目录 | 保留页头、范围、筛选、表头；数据区6行骨架；真实总数未知时不写0 | 同条件刷新可按6.3.3暂留旧行；新筛选/翻页用占位；搜索和导航可用 | 成功0项显示空数据或无匹配，失败原位重试，不隐藏当前条件 |
| 异步下拉选项 | 控件宽高不变；内部16px指示器；弹层显示“正在加载选项”，不能提前显示“无选项” | 可保留同上下文已选值，等待时禁止选择未确认的新项；依赖父项变化立即清空不再有效的值 | 成功无项“暂无可选项”；失败“选项加载失败”并提供具名重试入口；重试不提交表单 |
| 详情弹层／抽屉 | 立即显示标题、关闭入口与稳定内容区；字段区域用占位 | 关闭始终可用；仅当前对象有效字段可操作，保存等待定义与权限确认 | 加载失败在抽屉内重试/关闭，不误报对象不存在；切对象旧字段立即失效 |
| SQL查询与结果 | 保留编辑器和上下文，结果区提示“正在执行查询…”；不编造表行 | 沿用原执行/取消规则，防重复运行；不改变编辑器输入、撤销和选中逻辑 | 已取消、失败、完成、结果未知分开；未知提供核实；不凭中断网络报告服务器取消 |
| Redis与元数据 | 保留当前来源、键/对象导航框架；具体键值或字段区占位 | SCAN加载更多保留已确认项，只在末尾加载；不把游标当总量，不显示虚构百分比 | 结束依据接口；键已过期/对象不可见与空值、请求失败分开 |
| 报表阅读与运行 | 保留标题、版本、参数和来源；结果表/图区域加载，依既有逻辑清理旧结果 | 参数可编辑程度沿原规则；新参数使旧请求失效，不能把旧结果放在新参数下 | 显示结果时效、截断与限制；失败保留参数，重试必须使用当前有效版本 |
| 仪表盘 | 每个图块保留标题与已知布局，高度不坍塌；各块独立加载 | 已完成区块可读；不要为了等待最后一块冻结整个看板；新全局参数使所有相关区块失效 | 部分失败就地重试失败区块；必需卡片受限继续显示限制，不将部分成功当完整成功 |
| 按钮提交／保存／审批 | 按钮立即busy，图标16px与具体动词；为原文案和进行中文案预留足够宽度 | 禁止重复提交，不全面禁用无关功能；关闭/离开遵循原未保存或执行中确认 | 成功有真实回执才报完成；失败保留输入；未知结果显示核实，不盲目重提 |
| 后台任务／导出 | 接单成功显示“已加入队列”，任务区域展示后端阶段，不持续锁住发起页面 | 离开页面与后台任务取消分开；取消仅在已有能力允许时出现 | 百分比仅用真实进度；有已完成量无总量时只显示数量；完成、可领取、已送达分别表示 |
| 空间与权限确认 | 清理原空间内容；布局保留品牌和本人合法入口，主区说明“正在确认工作空间权限” | 正在切换时防重复切换；个人安全等独立入口依既有资格可用 | 失败进入明确恢复/重试，不能回显旧空间数据；权限未知不等于无权限 |
| 通知与摘要 | 未确认显示加载/未知语义，不能显示“0条未读” | 同上下文摘要刷新可保留原数字并明确正在更新；不自动标已读 | 失败显示未知或刷新失败；权限失效清空原数字，不泄露受限摘要 |

原工作空间确认页（图册 21）在读取成员资格后，只允许选择已获准的原空间。无可用原空间时，选择控件与确认按钮禁用，并提示不能改用其他空间解释该链接。确认按钮与提交共用同一校验，覆盖成员资格、链接来源、加载和提交状态。核对过程中确认页按登录主体保持挂载，以保存正在核对的链接和失败提示；主体变化时重建。业务页面仍按授权身份重建。权限核对失败显示原因，原空间仍有效时可重试。组件继续使用路由和用户 Store，无新增 Props 或 Emits。检查覆盖无资格、可进入、加载失败重试和同页更换链接。

确认页使用共享页头和并列的原空间、进入本页前的当前空间对照，窄屏依次堆叠。仅从已读取的成员记录显示空间名称、资格和已有角色，未提供的环境类型与加入日期省略。链接内部的显式空间参数与确认地址冲突时停止进入。确认失败时保留选项；重试重新核对资格。取消入口按原先空间的可见首页返回，无法核对时保留个人设置入口。未确认前不读取对象。

点击确认后，先按原链接的空间编号读取有效权限，等待期间保留当前工作空间及其权限快照。只有当前链接的最新核验通过且身份、空间和成员资格仍一致时，才提交切换并开放目标页读取。同页换链或离开确认页取消原权限请求，先前请求的结果不得切换空间。返回进入前的空间也先核对再切换。Store 增加按指定空间核验并提交的方法，仅对现有有效权限 GET 使用显式空间，其余业务请求仍绑定当前空间。验收使用两实际空间、真实迟到权限响应和同页换链，核对旧目标零读取、保留当前空间以及再次确认后从新链接取数。

键盘触发原空间确认后，确认按钮在核验期间保留焦点并标记为不可重复操作。权限服务失败且原空间仍可重试时，按钮恢复后可以直接按 Enter。权限快照变化期间，留在同一个确认页时保持用户所在控件的焦点；成功换页后按目标页的原焦点规则处理。

核验权限收到 403 或 404 后，重新读取成员资格。如果最新列表确认已失去原空间资格，撤下旧空间名称和角色，禁用确认，保留原链接和可用的取消操作。如果仍有资格，则显示原权限错误并保留重试；名单读取失败时提供名单重试。原焦点仍在即将禁用的确认按钮时，转到缺少资格的说明或名单重试按钮。已移开的焦点保持原位。

治理恢复页（图册 21）使用共享页头、恢复规则、当前选中空间及编号申请目录。申请状态、两名独立核验完成数和申请截止时间取自回执，冻结原因、治理人姓名与核验人姓名缺字段时省略。申请有效期 10 分钟，双人核验后获得最多 15 分钟的有限治理，接收人须重新登录。读取失败撤下旧记录和核验动作，可原位重试。申请写入和刷新回执分开反馈；同一请求重复提交使用相同请求标识，待确认时先核对记录。核验打开后聚焦密码字段，失败清空凭据并重新核对申请状态；同一弹窗仍打开且可继续核验时，等密码字段解除禁用后再把键盘焦点送回该字段。未具备前端已知核验条件时不提供核验入口，服务端继续执行预登记、MFA、回避和代次校验。`RecoveryView` 使用原用户 Store，无新增 Props 或 Emits。验收使用合成接口覆盖空记录、读取失败和过期展示，并在隔离浏览器核对密码错误后的清空与回焦、两次独立核验回执及窄屏。

治理恢复是按登录主体读取恢复名单和申请的独立入口。页头定期刷新当前工作空间权限时保留正在办理的申请与核验弹窗；登录主体变化时重建并清除输入。业务页继续随权限版本重建。验收同时覆盖核验弹窗打开时的权限刷新，以及恢复页读取失败后的撤下与重试。

对于任务类型等本地静态枚举，不添加无意义Loading；仅远程获取的来源或选项需要选项加载态。任务类型、状态的选择本身不触发保存或后台任务创建。

#### 6.3.5 组件与状态来源约定

优先复用现有PageState、Element Plus选择器/按钮loading、请求状态机和共享令牌。页面级状态、局部读取和业务提交分别负责自己的busy，不以单一全局布尔值控制全部页面。

| 对象 | 输入或拟定契约 | 责任与禁止项 |
| --- | --- | --- |
| PageState（现有） | title、description、loading、heading，actions插槽 | 用于权限确认或整块无有效内容状态；加载说明与取消动作分离，不承担请求 |
| 共享加载呈现（LoadingState / v-data-loading） | LoadingState：label、variant:table/detail/chart/inline、rows（默认6）、announce（默认true）、actions插槽；指令：busy布尔值、data-loading-label、data-loading-variant | 负责稳定占位、150ms读取提示和5秒等待说明；无Store/API，卸载清理计时；不缓存、恢复或判定旧数据有效性 |
| 选择器（现有el-select） | loading、disabled、options、modelValue、可访问名称及实际error | 所属业务提供请求结果；加载选项不伪装为可选数据行，错误重试使用独立按钮/具名入口，空项仅成功后显示 |
| 提交按钮（现有） | busy/disabled与具体进行中文案 | 业务方负责同步防重、幂等和结果核实；展示组件不发请求、不自动重试 |
| 任务进度（现有业务状态） | 后端phase/progress/terminal状态 | 无总量不计算百分比；收到终态停止动画和轮询，不按前端时间推演成功 |

共享加载呈现已采用LoadingState与局部指令实现，不引入依赖。展示模式无业务Emits，重试/取消由actions插槽中的调用方绑定原函数；只有实际存在的动作才显示。

新增展示用途令牌统一映射现有A2语义源：--db-loading-fill对应--db-surface-inset，--db-loading-edge对应--db-border，--db-loading-text对应--db-text-secondary，--db-loading-accent对应--db-accent。时序令牌--db-loading-indicator-delay=150ms、--db-loading-long-wait=5000ms；由共享逻辑读取，页面不散落独立阈值。上述令牌已进入共享样式；页面实际效果仍以人工验收为准。

实施约定（2026-10-28）：共享 `LoadingState` 提供独立读取/执行提示（label、variant、rows），共享 `v-data-loading` 接管现有局部读取区域（绑定实际busy布尔值，data-loading-label提供对象名称）。指令立即阻止旧结果交互并隐藏未确认内容，保留区域几何尺寸；状态说明放在busy区域之外。读取未显式建模的页面通过useReadActivity记录并发读取数量，卸载后不恢复busy；调用方仍负责权限与响应代次校验。两种展示共用时序控制器和CSS令牌，不接管API或业务状态机。默认采用清晰占位，不自动推断同条件刷新资格。原生提交按钮继续使用已有同步busy与防重逻辑；取消入口必须位于受保护数据区之外。实施与浏览器验收状态另行记录，不能以此条约定视为通过。

补齐实施范围：业务工作台、订阅/告警、业务操作、访问申请、治理恢复与迁移、身份/连接器设置、查询设置、Redis值详情及报表/仪表盘弹层均使用同一加载呈现。加载提示与内容必须互斥或由局部指令保护；未知总数不显示0。轮询只在首次或主动刷新呈现占位。`LoadingState`支持紧凑inline模式用于选项/子树；表格区域保留表头，加载说明优先显示，不被长骨架挤出视口。根据用户本轮分工，代码、测试、构建和本地前端重启由代理完成，浏览器视觉与交互验收由用户人工完成并单独记录。

#### 6.3.6 无障碍与键盘

实际受影响的数据区域设置aria-busy；装饰骨架与旋转图标aria-hidden，不渲染成可聚焦的假行或假按钮。在busy区域外提供持久、简短的role=status/aria-live=polite说明，避免辅助技术因区域busy延迟播报；同一区域不叠加重复live region。现有PageState整块状态若单独承担播报，局部包装不再重复播报。

查询工作台的结果标题区保留一个状态节点，忙碌标记只用于正在更新的结果正文。结果正文的 `LoadingState` 保留说明和静态标记，已有标题区负责状态时传入 `announce=false`。错误详情使用原就地提示。按键触发取消后，原按钮保留焦点，通过 `aria-disabled` 标记取消正在处理，使用原状态机阻止重复取消。若焦点仍在取消按钮，确认终态时移到结果标题，结果待确认时移到「核实状态」。用户自行移开焦点后，结果更新不抢回焦点。

只在阶段变化时播报“正在加载任务记录”“任务记录已更新”“读取失败”等，不在每个轮询、计时秒数或骨架行变化时重播。需要立即处理的错误可用alert，不用alert播报普通加载。关闭下拉/抽屉、Esc和Tab操作可用，重试入口有对象名称；异步完成不自动重新打开用户已关闭的弹层。

## 7 无障碍、图表与主题

键盘可完成导航、筛选、编辑、菜单、对话框、分页及分栏替代操作。提供跳到主内容，焦点2px边线+2px间隔，不能被固定页眉遮挡。复合控件遵循原语义，不把所有链接改成按钮。只在适当status/alert区域播报，避免全页反复朗读。

图表配色以朱红、墨绿、赭黄、灰蓝、褐紫、深灰构成低饱和序列；图例、刻度、提示与编辑器使用共享令牌。颜色之外提供线型/标记/标签和可访问数据表。数据密度、日期范围、量纲及原始精度保持，不为图形美观自动补齐或聚合未知值。

技术资产详情和业务资产口径共用现有对话框与目录详情样式。打开弹窗时列表保持原宽度、筛选、页码和滚动位置。弹窗限制在视口内，标题和关闭按钮始终可见，长内容在弹窗正文内滚动。焦点留在弹窗内，支持关闭按钮、Esc 和点击遮罩关闭，关闭后回到原列表入口。验收覆盖桌面弹窗居中、列表边界稳定、技术详情下钻与返回、口径跳转、键盘回焦、窄屏弹窗内部滚动和原对象直达。

对象详情沿用结构快照、表及列标注、本人收藏、键及索引、DDL、血缘与获准数据预览。标注提交期间保留保存按钮的焦点，以 `aria-disabled` 标记并拦截重复写入。写入确认后，在同一对象详情保留保存结果，独立刷新列表与详情；原编辑弹窗关闭后，若焦点随该流程丢失，则聚焦保存结果。用户已移焦或切换对象时保留其选择。详情标签采用共享分类控件，进入预览才读目标数据。详情或预览切换取消旧请求，失败撤下旧结果、计数和旧动作，允许原位重试；预览空结果单独说明。窄屏仅表格区域横向滚动。验收覆盖同空间直达和旧链接、前进后退、迟到响应、失败和空结果、收藏与标注读回、标注保存焦点及两主题窄屏。

血缘面板按对象定位和深度读取，只显示服务端图谱中与当前对象相连的关系。读取失败可重试，图谱未返回当前对象时不展示其他对象的关系。影响说明使用已返回的下游对象及服务端影响统计，按业务名称展示上游、下游、下游表、视图、报表及图谱对象总数。省略服务端未返回的统计和没有依据的列影响。保留现有解析入口和具备申请许可的工单预填。沿用原对象 Props 和 `createTicket` 事件。窄屏关系与统计折行。验收使用实际外键关系核对上下游和影响统计，并验证工单保留原工作空间和对象。

设计图主要展示桌面浅色正常或关键受限状态；每页加载/错误/空/权限与窄屏、深色仍按本规范实现并验证，不能把48幅画面声称为全部角色、主题、视口和状态组合。现有业务弹层、查询辅助组件、未挂载兼容组件沿用对应模板，实施时仍须全量清点，不删功能。

### 8.2 本轮与后续关口

设计交付：正式规范、路由/子页映射、24张双页高保真评审图及本地索引。用户随后授权按A2开始代码变更。当前进入共享样式、导航、目录与工作台迁移；不新增业务能力、依赖或切换真实权限。

按共享令牌→基础控件→全局框架→目录/工具/治理/个人页面→组件预览统一迁移。修改前源码指纹与副本保留在本地证据目录；不能以“规范已更新”报告A2上线。

<a id="ui-change-workflow"></a>

### 8.3 统一UI修改流程

所有非明确例外的布局、视觉、状态与交互修改依次完成：

1. 审查本规范、实际源码、适用AGENTS与业务契约，记录差异和范围。
2. 先修改规范，明确组件输入/事件、状态、响应式、例外和检查标准。
3. 用户批准对应实施范围后统一应用共享组件与全部调用点，不用单页补丁绕过。
4. 实际UI审查并保存当前源码关联证据；构建、业务验证和视觉确认分别记录。

Monaco内部原生控件是明确外观例外；数据密集网格可12px只读正文但必须可读。任何新增例外先登记，不能自行把普通页面排除。
