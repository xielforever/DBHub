## 2 现行结构入口

同一对象须叠加其后的全部迁移，不能单独执行下表某个文件来创建“当前结构”。表中列主要起点和重要补充，完整顺序在迁移目录；不在本文复制另一套CREATE TABLE。

账号与权限矩阵的增量迁移（#43）为平台账号增加受版本保护的开通状态及存储一次性凭据摘要、用途、到期与消费的记录。账号开通在事务内显式区分旧自动入空间的创建路径。账号操作与凭据发放序列化，旧会话继续通过既有认证版本失效。空间矩阵标志对存量空间默认关闭。菜单配置按原空间主键与配置版本存储稳定角色编号到菜单设置的映射，兼容读取空配置或缺失单元并继承旧显示。实际 DDL、唯一约束及到期索引以新增迁移为准。

#47 为 `sys_iam_workspace_state` 新增默认关闭的仪表盘矩阵标记。通过受限维护函数按工作空间显式启用，事务内追加三个内置角色的新版本、移转有效分配的角色版本引用、推进权限代次并留审计。复核保存签署时的资格依据，用于重新授权后识别旧签署；历史记录保留。复用原工作空间、角色及分配索引，无新增索引需求。

权限职责调整（#44）为 `sys_workspace_members` 新增布尔列 `matrix_admin`，默认 `false`。该列记录矩阵内的管理职责，既有业务数据身份和直接业务角色继续由原字段决定。成员资格写入复用同一空间的成员主键、权限代次和事务审计。默认工作空间的矩阵开关由新增迁移显式启用。按原有效许可映射普通成员的角色，保留成员状态、过期限制和既有组授权记录。迁移沿用现有主键、外键及索引。

常见图表（#45）通过 [0104](../../backend/internal/db/migrations/0104_report_chart_types.sql) 扩展 `sys_reports_chart_type_check` 的允许值。沿用 `chart_type` 列和 `chart_config` JSON 字段、原有索引及正式报表冻结结构。历史报表保留原字节，新增样式和热力图第二维由保存接口写入持久配置。

## 3 必须保持的数据约束

- 空间内对象及引用链保持同一空间，个人连接、历史、任务和文件再检查当前主体。复合键、外键、RLS与后端检查共同生效，不能仅凭前端传入workspace_id放行。
- 驱动制品、模板/来源修订固定引用；模板修订追加，既有绑定不浮动升级。定义不保存认证材料；个人绑定与受管报表账号分开。删除被引用对象按迁移和仓储规则拒绝或受控处置，不一概级联清除。
- 内容版本与批准摘要不可原地改写，发布/下线/回退追加事件并检查预期发布号。历史操作者允许按已定义外键置空，姓名及真实签名快照保留；删除或冻结作者不删除正式内容历史。
- 命令防重键绑定原空间、主体、操作及内容指纹，授权/配置/凭据代次分别检查；版本不能倒拨。查询登记编号不能因TTL、失败、重启或历史清理而重新获得执行机会。
- 收紧、治理差异及审计按各自事务原子写入；当前收紧在恢复和回退后仍有效。新角色/许可表存在不代表已启用，当前兼容边界按[数据执行契约](../架构设计/数据接入与执行契约.md#7-功能治理与迁移的有效规则)维护。

## 5 秘密、留存与升级

密码、私钥及口令字段使用既有AES-256-GCM加密，主密钥通过受控配置注入，不能写入代码或元数据库；主密钥丢失后无法仅靠数据库备份恢复凭据。JWT、刷新令牌、一次性码和密钥不写入文档或日志。

审计与查询历史按明确部署留存配置清理，默认不自动清理；未知结果和防重键不自动删除，不可变审批、内容版本和发布记录不纳入普通历史清理。文件/期次快照按其原期限处理，不能用普通清理改写批准或恢复过期业务数据。

数据库连接使用情况见[系统架构](../架构设计/系统架构总览.md)：元数据库有独立连接池，普通目标请求持有独占连接，本文不规定“所有目标长期池化”或复制未生效的空闲/生命周期参数。

升级新增迁移，不改写已应用历史文件，不通过复制本文片段初始化已有库。变更说明须包含受影响DDL/函数/索引、存量兼容、事务及回退边界；在隔离数据库验证升级和恢复。备份、密钥、审计卷与当前收紧的恢复要求见[部署运维指南](../部署运维/部署运维指南.md)。统一数据范围、团队交付等后续规划尚未交付时，不预建另一套策略或工作流表。

## 工作台脚本存储

迁移 `0098_workbench_scripts.sql` 对应 [#34 编码与验收计划](../项目管控/开发路线图与当前任务.md#workbench-34-must-plan)。`sys_sql_snippets` 由迁移 0028 纳入空间范围。0098 沿用脚本标识序列和正文存储，新增目录、显式类型和逐人只读授权。

| 持久对象 | 增量结构和索引 |
| --- | --- |
| `sys_sql_snippets` | 清理旧片段后增加必填 `script_type`，接受 `mysql`、`postgres`、`redis`，同时收口旧 `visibility` 列及对应索引。新增可空 `folder_id` 和必填 `version`，正文继续映射到原文本列，版本从 1 开始并递增。目录引用以 `(workspace_id, user_id, folder_id)` 匹配同一所有者、同一空间的目录。为按空间、所有者、目录和更新时间分页列脚本建立索引。 |
| `sys_script_folders` | `id, workspace_id, user_id, parent_id, name, created_at, updated_at`。`parent_id` 为空表示顶层，父目录复合外键限定同空间同所有者。空间、所有者、上级和名称用于同一层级重名检查与目录读取。文件在根目录时 `folder_id` 为空。 |
| `sys_script_read_grants` | `workspace_id, script_id, reader_user_id, granted_at`。使用空间、脚本及读者作为唯一键，脚本和有效成员引用同一空间。索引按空间、读者、脚本支持「分享给我」。授权按当前空间有效成员主体记录，撤回时同步写入既有审计。 |

默认绑定以原 `connection_id, database_name` 为基础。服务端记录足以核对原目标的非敏感连接标识和来源定义修订，连接被移除后原绑定作为失效状态保留。显式解除时清理关联字段。Redis 库名保存实际固定逻辑库。个人连接改绑到其他来源或固定逻辑库变化时保留正文，要求重新确认。脚本字段及列表响应均按用途控制连接信息，凭据沿用原连接存储。

目录创建时可以选本人已有目录为上级。目录可重命名，父级关系在本期固定。脚本可在根目录及本人目录间移动。同级目录名以去除首尾空白和忽略大小写后的值去重。逐人授权记录脚本所有者和获邀成员版本，外键绑定到脚本和当前空间成员，成员资格失效后原授权不再有效。绑定记录单独保留最近明确确认的连接编号和配置签名，用于区分无绑定和绑定失效。

新脚本检查当前空间和主体。对于显式类型记录，读取由所有者或当前有效授权决定，更新、移动、授权由所有者决定。RLS 同时约束空间和对象可见性，核对旧的宽松策略合并后仍有效隔离。接口检查和写入在同一受控事务内完成。按当前版本保存，冲突保留已提交版本和待编辑内容；移动更新目录引用和版本，分享继续指向同一脚本标识。授予与撤回操作按唯一键去重。

当前尚未投入生产，用户已确认工作台旧脚本可清理。采用新增一次性迁移，复用脚本表和标识序列。同一迁移先加入类型字段，以尚无显式类型识别旧片段，清理后再设置类型必填并切换到逐人访问。停用旧片段的写入入口与数据库升级按同一候选统筹，迁移版本继续用 `schema_migrations` 记账。原查询历史、执行回执、连接及源定义各按现有保留规则处理。

升级预演在隔离元数据库布置旧私有与旧共享片段，同时布置查询历史及回执作为保留对照。核对清理前后数量和范围、新脚本及授权可用、重跑升级保留新写入。按既有备份和恢复流程验证回退，回退需保留新版本脚本数据的可恢复性。
