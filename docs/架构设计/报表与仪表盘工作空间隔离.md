# 报表与仪表盘的工作空间隔离

> 2026-10-18 · P0 隔离前置已实现，迁移 0028–0035；实际部署要求和验证证据见[实施与验收](../开发指南/仪表盘第一阶段实施与验收.md)。适用于[仪表盘第一阶段](../项目管控/仪表盘第一阶段设计.md)及其引用的报表、数据源和执行账号。

## 1. 组织与身份模型

工作空间是业务组织和授权边界。平台登录用户可以加入多个工作空间，但每次请求只处于一个有效工作空间。成员角色为管理员、开发者和只读用户，角色从当前成员关系读取，不使用全局 JWT 角色替代。

平台运营管理员负责空间生命周期、容量和成员邀请治理，默认不读取组织报表、结果、SQL或执行凭据，不因平台角色成为组织审批人。需要业务权限时须按组织规则显式加入并授权；不能使用隐藏身份切换。

现有“全局发布”统一解释为所属工作空间内共享。数据源模板、JDBC 驱动发布仍需有明确归属；首期不开放组织间共享对象引用。以后可发布经过治理的公共驱动制品目录，但不包含其他组织的数据源地址、账号、密钥或报表。

| 对象 | 组织约束 |
| --- | --- |
| `sys_workspaces` | 稳定 ID、名称、状态、容量/安全策略及策略版本；空间停用阻断其业务执行 |
| `sys_workspace_members` | 稳定成员 ID、工作空间、平台用户、角色、状态、成员版本；用户在每个空间独立授权 |
| 数据源/修订、连接、驱动、模板、报表账号 | 必须属于同一工作空间；个人对象另检查成员所有权，不因组织共享暴露个人凭据 |
| 个人/正式报表、仪表盘、版本、审批、受众 | 整条引用链工作空间一致；不能授权其他空间的用户组或未入组用户 |
| 用户组及成员 | 空间内唯一标识，成员变更递增组版本；不支持跨空间或首期嵌套组 |
| 审计、任务、队列、回执、刷新、访问申请、收藏、元数据和导出 | 有工作空间归属并按身份裁剪，不能成为旁路查询入口 |

## 2. 请求与授权

新接口显式使用 `/api/v1/workspaces/{workspace_id}/...`。服务器用登录身份验证成员资格，生成只读工作空间上下文；客户端传入的 ID 仅是选择请求，不是授权凭证。缺上下文、空间停用、成员无效或资源不属于该空间均拒绝。

每次管理、读取、预览、执行、取消、轮询、下载和结果交付都验证当前组织及成员。队列任务携带不可变空间和成员标识，重启恢复后重新验证，不继承过期的角色快照。切换工作空间清空前端结果与执行队列；旧空间的迟到响应不得进入新空间页面。

管理员管理权限不包含数据读取权。读取卡片需同时满足空间/成员有效、仪表盘受众、报表受众、当前发布、契约及执行身份状态。审批、归档、移交和访问申请也不得关联别的空间资源。

工作空间管理员管理的是本空间成员，不能删除其他空间身份、重置平台账号密码或终止用户在其他空间的会话。全局身份删除/密码重置走账号自身或受限平台身份流程；不能沿用旧全局用户管理接口对多空间用户直接操作。成员邀请不默认赋予其他空间角色。

动态用户组是数据授权主体。已经承载数据权限的组若新增操作人本人，必须由另一位合格组织管理员审批；不能先给空组授报表权，再自行加入组绕过个人提权自审规则。成员移除或停用立即生效。组授权的审批也识别审批人当前是否为受益成员，并保留完整审计。

本人入组可通过组织内 `POST /groups/{id}/membership-access-requests` 进入站内申请，由另一管理员使用明确的组成员变更处理；申请完成与组版本递增在同一事务提交，不经过报表发布。普通成员编辑接口也检查操作人是否是新增受益人，不能绕过申请直接给自己加组。组成员权限由已批准动态组委托给组织管理者，但不允许个人自批。

未知与跨空间资源使用一致的 404/不可访问响应，不泄漏名称、计数、列、状态、账号或不同审批错误。无权限申请入口可返回统一受理语义，但不为跨空间目标创建真实申请，也不显示其存在性。

平台管理和空间管理使用不同能力；不得把全局 `admin` 检查直接作为业务仓库方法的授权结果。单个管理员无法自行完成涉及自己的新增授权时，应提示配置另一位合格组织审批人，不默认赋予数据读取权。

## 3. 存储、执行与隔离防线

所有受管表及关联表增加非空 `workspace_id`。关联使用 `(workspace_id, resource_id)` 组合外键/唯一键；仓库方法必须接收服务端工作空间上下文，禁止根据资源 ID 反查后自行切换空间。

PostgreSQL 元数据层为组织表启用行级策略作为第二道防线，业务连接使用非表所有者、无 BYPASSRLS 的角色；按事务 `SET LOCAL` 设置已验证空间，缺失时拒绝。后台审计投递和维护使用受限职责接口，不能把具有全表能力的维护连接提供给普通请求；跨组织维护操作逐空间执行并记录运营审计。数据库超级用户、迁移账号不用于日常 Web 请求。

连接池归还时不遗留空间状态；必须通过事务局部设置，异常、超时和重用连接都做隔离验收。RLS 不能替代应用层对象授权，更不能约束外部数据库里尚未受限的业务账号；目标账号继续使用限定视图/表权限。

执行缓存键、连接池身份、幂等命令、队列、回执、任务和审计关联至少包含空间及实际操作者。不能只按前端报表编号或用户名复用凭据/结果。执行账号读取先限定空间再解密，不能提供“查任意账号 ID 并返回连接”的内部便捷旁路。

源地址、数据库名和执行账号不得由客户端覆写。目标网络许可继续生效；工作空间自己的目标限制只能进一步收紧平台允许范围，不能由组织管理员绕过平台网络许可。

工作空间设置查询和存储配额，资源准入同时受用户、账号和全局限制。多实例配额需在持久控制层统一登记/恢复并验证，单机内存计数不能被描述为跨实例隔离；完成前仅允许经验证的单实例部署容量，不宣称集群准入能力。

## 4. 成员退出与空间生命周期

移除/停用成员立即撤销登录工作空间资格、终止新任务并拦截后续结果。活动报表/仪表盘移交给同空间有效责任人，移交不赠予数据权限；不能为了离职交接保留原成员数据访问权。

共享驱动、模板、数据源和报表执行账号由工作空间持有，不随创建者退出级联删除。工作空间管理员移除的是本空间成员关系；用户在其他空间仍有成员关系时不因此删除其平台登录账号。

成员记录是稳定的组织主体，不因用户退出立即删除。仅有归档历史时可停用成员并删除/解绑平台登录身份，保留无登录能力的历史成员标识及必要名称快照；归档对象由空间管理员负责管理。不可变历史 JSON 与审批摘要不重写。

空间停用阻断执行和发布，保留受限运营入口与审计；恢复空间不自动恢复被单独停用的成员、账号或报表。空间删除采用停用、留存期限、受控清除流程，不提供普通管理员一键级联删除审计和凭据的能力。

## 5. 既有数据迁移与旧 API

1. 创建明确的默认工作空间，将既有数据及成员全部回填到这个空间；迁移不能根据名称猜测多个组织归属，也不能把已有共享对象复制为所有新空间可读。
2. 保留历史 SQL、内容版本、manifest JSON 和原批准摘要；组织键与成员映射通过新增关系表达。原 `user_ids` 在默认空间中仅在用户仍是有效成员时解释，不通过改写不可变 JSON 变更历史批准。
3. 现有资源所有权逐步映射稳定成员标识；活动所有权必须有有效责任人，归档历史允许保留失效历史成员。原不可变作者快照用于追溯，不能当作当前授权。
4. 全面清点现有报表、个人连接、源目录、执行账号、用户/组管理、审计、全局搜索、血缘、查询历史、事务、取消、导出、工单、后台任务及旧仪表盘接口；在组织隔离前不能开放这些接口给不同组织。
5. 旧无空间路径仅允许对已明确映射的单一兼容空间访问；用户拥有多个空间、无法确定作用域或请求跨空间对象时明确要求指定空间。不得静默回退默认空间，不信任任意 `X-Workspace-ID` 头，不以接口隐藏代替检查。
6. 新建组织默认为空，没有默认空间的成员、源、账号、组、报表或审批权限。新组织的首次管理员仅有该空间管理能力，数据权限仍显式配置。
7. 在迁移后验收通过前，关闭多组织注册/入驻和跨组织服务声明；保持原单空间服务运行。此开关是产品上线门槛，不是让用户确认后绕过隔离的审批。

## 6. 开放给不同组织前的验收

| 场景 | 必须满足 |
| --- | --- |
| A 用户猜 B 的源、账号、报表、组、看板或审批 ID | 统一不可访问，无名称、计数或元数据泄漏，无目标 SQL |
| 伪造 URL/请求头中的空间 ID | 无有效成员关系则失败，不能把其他空间角色带入 |
| 混用跨空间父子引用、用户组和模板 | 业务层拒绝，组合外键再次阻断 |
| 切换空间、撤销成员或空间停用时已有查询在途 | 后续发送/交付被阻断，迟到结果不进入新页面 |
| 查询审计、执行回执、下载、取消、全局搜索或血缘 | 组织隔离和对象权限一致，不能通过旁路读取或操作 |
| PostgreSQL 连接池跨空间复用、异常回滚和后台作业 | 不残留上次空间上下文；缺上下文默认拒绝，普通角色无 RLS 绕过能力 |
| 平台管理员和单空间管理员 | 无隐式其他组织数据权，管理身份不等于报表读取身份 |
| 用户离职且存在历史归档 | 访问立即失效，活动资源须移交，归档历史不强迫维持登录身份 |
| 升级迁移及多空间老客户端 | 历史批准摘要不变，无默认空间回退造成的权限扩大 |
