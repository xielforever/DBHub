## 1 工作空间与数据身份

| 范围 | 必须保持的规则 |
| --- | --- |
| 当前主体/空间 | 登录用户每次请求只使用一个经服务器验证的空间；空间、成员、期限、撤权和冻结均有效 |
| 对象及整条引用链 | 连接、定义修订、执行账号、内容/版本/审批、组/受众、任务、回执、交付和审计均限制原空间，不能混用跨空间ID |
| 管理身份 | 平台管理、空间治理、业务复核和业务读取分别授权；管理员没有他人个人凭据或隐含数据读取权 |
| 新旧权限 | 旧基础角色和职责仅作已确认兼容来源，不将新角色名映射为最高旧数据角色；当前收紧在切换/回退后继续有效 |
| 前后端与数据库 | URL/请求头只是空间选择，不是授权；后端对象检查和元数据库组合引用/RLS相互补充，缺上下文拒绝，业务连接不得绕过RLS |
| 输出与后台 | 查看、预览、执行、取消、轮询、下载、通知返回及后台执行都检查当前资格；切空间清结果并忽略迟到响应 |

未知或跨空间对象不泄漏名称、数量、状态、列或账号。旧无空间路径仅用于明确映射的兼容空间，不在歧义时回退默认空间。元数据事务局部空间上下文不能残留到复用连接，迁移/超级用户不作为普通请求身份。外部业务库仍由受限账号、视图和原行列上限约束，元数据RLS不能代替目标库数据规则。

新空间不复制其他空间的成员、来源、账号、组或内容；初始治理资格不附带业务数据权。空间管理员不能借旧用户API重置平台身份密码、删除其他空间身份或终止其会话；成员退出只影响本空间，平台身份操作独立授权。用户组限定本空间，首期不支持跨空间或嵌套组。

## 2 开发、审批与发布

个人分析使用本人连接；正式报表绑定共享定义修订和受管只读账号，查看者不必提交个人数据库口令。旧个人/共享报表仍使用查看者本人的匹配连接，不因内容共享自动升级为受管执行。服务端固定来源、数据库、SQL/参数定义、图表、契约、执行账号边界及拟受众，不能由查看参数覆盖执行目标。

保存草稿、冻结内容版本、审批记录和正式发布指针分别维护。草稿可继续修改，不改变在途批准对象或线上版本。每次重新送审按原规则生成新版本/记录，不修改既有批准摘要。

原流程采用独立复核、真实只读预览及手动发布；提交者和新增授权受益人不能自审，组授权亦识别直接受益。无合格复核人保持阻断，不自动转给无数据资格的管理员。批准针对已核对的固定范围，批准不等于已发布。正式报表的真实预览验证15分钟内有效；账号/凭据代次、受众、参数或基准变化使原验证失效。普通正式查询仍受获批1000行/30秒、2MiB及用户、空间和系统更严格限制，导出使用另行批准的策略。

发布、下线和回滚核对当前资格、预期发布号、账号/来源状态、受众/组版本及依赖影响，冲突则拒绝。回滚仅恢复曾发布的获准定义，不回滚业务数据库，也不复活撤权、冻结或停用账号。内容安全下线和撤权不因依赖看板存在而被阻止。

正式查看DTO只返回展示必需信息，不默认公开SQL、连接地址、数据库账号、审批内部说明或凭据；开发/复核视图另按资格返回。执行账号不进入个人工作台，不能通过任意SQL借用；同一账号身份仅可独立维护凭据，更换来源或数据库身份须重新建立相应账号/批准边界。正式资源不依赖作者的个人连接存续，删除作者先处理责任归属，历史版本、批准及发布记录不级联清除。

## 3 数据口径、结果与时效

获批data_contract随内容版本冻结；服务器在选择账号后补齐执行边界并计算契约哈希，不回写原冻结定义，客户端不能自报可信哈希。

| 契约内容 | 保留规则 |
| --- | --- |
| 业务含义 | semantic_key、meaning、scope_key/description、time_window明确口径和统计范围；文字声明不等于统一数据条件已执行 |
| 字段与展示 | result_schema固定列名/顺序、类型、NULL、水位及维度/指标映射；不能通过新增未声明字段绕过输出边界 |
| 单位与比较 | unit、currency、timezone、comparison_key明确倍率、币种、时区、范围与窗口；相同列名或相同单位不足以证明可比较 |
| 执行与哈希 | 来源修订、数据库、独立账号身份及freshness纳入边界；密码、显示名、受众、发布号和执行完成时间不冒充业务语义 |
| 时效 | watermark_column由获批SQL返回一致业务水位，按批准时区及未来偏差验证，未来偏差不得超过60秒；unverified、无行/NULL、水位未知分别提示 |
| 结果 | 精确数值、NULL及截断如实表达；结构、字节、行数或口径不符时不能画成完整/零值结果 |

带结果契约的 PostgreSQL 报表预览、复核和正式取数按驱动返回的列类型识别原生 `DATE`。有限日期以 `YYYY-MM-DD` 参加校验并返回，保留原日历日期。等格式文本及允许的 SQL NULL 沿用原契约。结果声明为 `date` 时，带时间戳的值和无效日期继续触发契约拒绝。带时区时间戳沿用原时间戳格式。

同哈希只是兼容必要条件，合格复核人仍确认SQL、样本和语义。改变币种、倍率、范围、窗口、结构、来源或账号身份形成新契约；同账号密码轮换不等于业务口径改变。历史报表不自动补造可信口径/水位，缺契约的历史内容不能直接加入新正式看板。

#45 的常见图表沿用冻结的展示配置、已批准的声明字段和原查询顺序。散点的两条数值轴、热力的两维和色阶、直方的区间和计数、漏斗的阶段和数量都按已声明字段映射。直方分箱和漏斗阶段由查询定义。正式报表和仪表盘只展示各自获准结果，沿用尺寸、状态及口径校验；具体配置见[报表接口](../接口规范/API接口规范.md)。

业务数据年龄、结果年龄和执行完成时间分别展示，不能用NOW()替代源水位。比较组还检查业务窗口、范围及执行后水位差，不承诺跨源数据库快照一致，不在浏览器重新聚合来冒充业务口径。unverified内容加入看板须有允许未知时效的显式批准并满足当前空间策略，不能默认放行。

## 4 仪表盘执行与依赖

仪表盘引用获批逻辑报表ID及预期契约，当前跟随兼容的正式发布，不开放固定历史报表执行。回滚看板只恢复布局/引用，不回滚报表或业务数据。兼容SQL修复和受众变动可继续跟随，不兼容契约阻断受影响卡片，须按新草稿重新确认。

一轮刷新在一致性元数据边界固定发布清单、批准摘要、账号代次、契约和每卡执行编号；执行/结果读取继续核对当前状态。每卡独立执行及取消，同一刷新不保证目标数据库快照一致；结果只在原用户、空间和该轮上下文中使用。

查看资格取空间成员、看板受众、报表受众和当前执行条件的交集。至少有一张必需卡片及有效可完整查看受众；必需/可选卡片受限、超时、失败、截断与未知时效如实显示。发布预检、复核和提交均重查覆盖及版本；过期预检不是授权凭证，撤权不能被依赖阻止。

原仪表盘每对象最多一份待审版本，重新送审先按规则撤回旧申请；改派重查资格并使原预览失效。审批过期、归档和生命周期代次按仪表盘专属规则处理，不能套用到所有报表。定时/手动刷新均服从当前限额，不将仪表盘完成等同文件或周期交付完成。

当前仪表盘沿以下既有约束，不把演示业务水位阈值写成全局默认：

| 对象 | 有效约束 |
| --- | --- |
| 编排 | 草稿0–8张，送审1–8张且至少一张必需；同一报表不重复引用 |
| 审批与验证 | 待审7天超期；真实预览验证15分钟，绑定依赖、成员/组及审阅指派代次，发布仍重查当前状态 |
| 执行与刷新 | 逐卡1000行、30秒、2MiB结果上限及更严格策略；页面最多并行2卡，服务端另有共享准入；刷新清单180秒有效 |
| 页面内旧结果 | 5分钟后提示待刷新；普通网络/数据库超时最多在本页内存保留30分钟并持续标旧；已知撤权、换人或切空间立即清除 |
| 业务水位 | 最大数据年龄和比较组水位差来自获批契约与空间策略；演示15分钟/5分钟不是全局门槛 |

## 5 受众变更与访问申请

当前“仅调整受众”复用原不可变版本、独立审批、只读验证和显式发布，不直接修改旧批准受众。复制当前正式定义时只能调整拟受众/关联申请，SQL、契约、来源和执行身份保持基准；其他变化走完整开发审批。基准发布号、批准摘要、组版本及关联申请变化时拒绝原样发布，不能静默合并后来授权。

申请只面向原空间和获准目标；普通用户申请本人范围，受限名称不因申请泄漏。pending、processing、approved_pending_release与fulfilled分别表达待受理、处理中、已批准待发布和实际生效；接单、通知及批准都不等于获权。发布后重查目标当前成员及权限，才按目标登记实际结果，部分成功不能写成全部完成。

拒绝填原因，未完成申请可撤回；超期、父对象归档/下线或目标失效阻断后续授予，已批准未发布也不例外。已完成申请的撤回不是撤权；收紧、退组、冻结或下线走相应独立操作并立即影响后续执行。

报表申请生效授予独立报表访问权，不仅限申请发起的看板；看板受众变更不自动授予子报表权。带数据授权的组扩员仍遵守独立复核，不能经空组授权再自行入组绕过自审。

## 6 导出、订阅和通知

正式报表导出沿现有版本策略、独立审批、只读执行、完整性/行数/字节上限、精度及公式文本保护，保留CSV、JSON、XLSX。预览页不是完整导出；不因本次收敛放大原账号、报表或文件上限。执行、审批、预览与领取仍查当前资格，元数据/审计故障不得放行。

当前导出申请先生成受限审批快照，获批后才可按当前资格领取；不等同阶段4“批准后生成新正式文件”的目标。已有文件和个人订阅快照保留原7天策略与原主体边界。新24小时文件、10分钟本人领取、个人/团队周期复核及逐收件人策略属于后续阶段，不替换存量规则，也不当作已启用。团队及仪表盘交付须独立实现/验收，不能复用负责人结果发给所有人。

个人订阅固定定义和期次，执行前、生成与领取检查当前权限。默认本期结果读取该期快照并显示真实数据时间；刷新当前数据是另一动作，不改写原告警发生值。计划暂停、退出、撤权或失效不靠旧通知链接绕过，未知结果和旧回执不自动重跑。

站内通知随原业务事务产生并去重，不包含SQL、业务行或凭据。已读、待处理、业务完成分别表达；链接打开后仍查原空间和当前资格。运维告警仅向获准平台管理身份按故障/恢复变化去重，待办实时按当前业务状态计算，已读不视为业务完成。可选Webhook仅按已配置和明确范围工作，不因本次合并新增邮件、短信或外部发送承诺。

## 7 冻结、恢复与范围

成员冻结立即收紧本空间访问、后续任务和交付，不因资产尚未移交而延期。资产归空间托管，当前只具备最小登记；完整资产清单、候选接任、接受/拒绝、在途改派、必要复核和重新加入属于阶段3。接任不转赠个人凭据、数据权、角色或旧签名，历史成员及审批快照不删除或重写。

空间停用阻断业务执行和发布，恢复不自动恢复单独撤销的资格；最后治理人冻结后的最小独立双人恢复，仅接续治理。普通回退不恢复目标库事务、过期文件、旧会话或已撤权限。

本次停止重复设计，统一复用现有内容/版本/审批/队列/回执；不扩展任意工作流、通用语义模型、跨空间实时引用/嵌入、通用联邦查询或公开分享。统一部门范围由阶段 2 承接，新内容审批及交接由阶段 3 承接，新交付由阶段 4 承接。具体启用以当前路线和明确授权为准。

## 8 已确认的后续内容与交付规则

以下规则已确认，分别在阶段2—4交付和验收，**不表示当前已启用**；兼容对象继续执行原真实节点、独立性、签名和期限，不补造新审批。

| 范围 | 有效规则及启用边界 |
| --- | --- |
| 分类与派生字段（阶段2） | 分类与输出分别建模并关联版本。旧normal先为内部候选、sensitive为敏感候选，confidential逐字段复核；未知分类阻止新发布，不把normal自动公开，不解除原masked/hidden或库侧掩码，派生字段不自动降级，凭据秘密禁止输出 |
| 敏感明文核查（阶段2） | 默认脱敏。例外绑定当前记录、字段、用途和独立批准，最多100条；申请最长24小时有效，批准授权最长8小时，并服从当前资格和更严格期限；到期/撤权立即停止，不进入文件或通知。高敏例外默认不启用，凭据秘密无例外 |
| 审批资格（阶段3） | 候选人须在责任范围内并合法覆盖本次目标人群及全部允许参数，不要求全空间数据。高风险业务与数据复核由不同人完成，提交人/受益人回避；发布人与提交人独立，当前合格业务复核人可兼发布。失权、无候选、预览/基线变化时暂停、重新指派或重提，不自动通过 |
| 正常下线及应急（阶段3） | 正常下线按独立业务节点、依赖和原因处理；应急停止显式授权、独立于源取数，不因流程或数据故障阻止停止。常规变更按新修订送审；显式应急恢复仅针对曾批准定义，重新检查当前受众、数据、字段、账号、契约及依赖，不得扩大当前边界，否则走常规审批；恢复形成新发布事件 |
| 资产接任（阶段3） | 先冻结再托管；无合格接任继续托管，计划退出保障治理接续，紧急冻结不等交接或最后管理员交接。接任须具备当前开发/数据资格，按需要复核，分别处置在途任务；不复制原角色、组、凭据或签名。重新加入是新授权，不恢复旧订阅或链接 |
| 新正式导出（阶段4） | 原独立审批保留。审批证据/预览、获批正式文件、领取凭证分开；新正式文件批准后生成，24小时有效，本人领取凭证10分钟，复核人仅有受限审批预览，不默认领取完整文件；原7天文件不追溯改期。平台、空间、内容和源行数上限取最小，并保留16MiB等既有字节约束，CSV/JSON/XLSX均保留 |
| 个人订阅（阶段4） | 新计划90天复核，不静默续期；固定内容、参数及活动版本，逐期重查。当前活动号换版、负责人失权或源不兼容时暂停待确认，不静默换版或永久执行旧号 |
| 团队订阅（阶段4） | 专用subscribeReview独立复核，冻结批准名单，30天复核/到期；新增组成员不自动加入。每位收件人按当前范围独立执行和领取，失权者跳过，负责人失权暂停；负责人只看送达状态，不读取他人数值。收件资格与计划创建权分开 |
| 期次、入口及凭证（阶段4） | 逐人期次快照保留7天、通知入口24小时、文件领取凭证10分钟，是不同对象；本期结果读原期次，刷新当前另取数。告警保留原发生值及处置证据；快照过期后只保留合法审计元信息，不保留可读业务数据 |
| 仪表盘交付及历史依赖 | 文件、周期快照、逐组件交付、固定历史引用均须专项实现与验收，未具备完整执行约束前禁用；必需卡片受限不能静默交付不完整结果，报表能力完成不能替代该项验收 |
| 跨空间复制（后续受控能力） | 只复制定义，建立目标空间新对象并重新绑定来源、账号、受众、数据规则和审批；不复制凭据、原签名或授权，不开放实时跨空间引用、嵌入、联合授权或任意联邦查询 |

内部字段10000行自动校验仅为分类和完整执行约束验收后的可选策略，不是阶段1默认放行；100000行是已有服务最大边界，不是所有内容默认额度。已下载本地文件不能由服务端追回，权限收紧仍阻止后续生成、读取和领取。

### 8.1 P2-04 分类与默认输出

数据集输出策略固定数据集和行列策略版本，明确登记各候选列的分类、旧标注、源输出限制及派生来源。当前分类为内部、敏感、高敏和凭据秘密，旧 `normal` 与 `sensitive` 仅供判断，旧 `confidential` 必须逐字段记录复核依据。新策略须覆盖行列策略允许清单，未知字段无法生成输出计划。派生字段级别不得低于任何输入，继承最严格的旧输出限制。

编译时先保留原行列策略上限，再按输出策略决定列投影。已批准内部字段沿用固定视图的值。敏感、高敏或原受掩码字段投影为 SQL NULL。凭据秘密及原隐藏字段直接拒绝，禁止通过普通路径返回。管理校验只返回版本和掩码列摘要，当前变更不接入真实业务输出。

受控明文由专门授权、独立于申请人的数据复核人审批。审批计划绑定数据集明确登记的复核人和其当前组织范围，复核人与申请人均需保持当前资格。旧管理员及报表复核角色本身不授予审批权。`report.reveal` 的真实许可和实际业务入口另行启用。

申请只绑定申请人当前的受管身份、数据集、行列与输出版本、用途及最多 100 个记录键和记录版本。独立审批须覆盖申请人可用组织范围，授权最长 8 小时，且不超过申请期限及当前有效期。过期、收回、版本或复核范围变化后旧许可失效。批准后只为申请人的交互核查生成固定范围的明文计划，限定已批准且未受原掩码约束的敏感字段。高敏、凭据秘密、隐藏字段、文件和通知沿既有禁止边界。阶段 2 逐项验收业务执行和各输出渠道，P2-05 和正式入口验收按[数据接入与执行契约](数据接入与执行契约.md)核对。

### 8.2 阶段 3 正式报表复核与正常发布

在已纳入角色矩阵的正式报表流程中，业务负责人按具体报表登记，技术维护资格按原技术负责人和空间许可核对。新报表首次送审指定有主管角色的当前空间成员，负责人随获批版本首次正式发布登记。后续业务审批由当前业务负责人或平台超管办理，继续核对回避、数据范围、预览证据和冻结版本。超管可按当前负责人版本直接指定接任人；换任校验主管资格，递增业务负责人代次，原主管未生效签署及旧预览失效，已发布版本及历史签署保留。高风险独立数据复核、技术维护人、受众和账号范围按现有规则校验。

首发、输出涉及敏感或高敏字段、扩大受众或数据及参数范围、变更执行来源或账号须由两人分别完成业务复核和数据复核。边界未扩大的内部字段修订由业务复核。未知分类继续阻止发布。当前隔离验收使用受管 PostgreSQL 批准视图，参数须纳入登记的等值、枚举、数值及日期区间。受众范围与全部允许值域一并冻结和核对，无法证明覆盖时保持阻断。

数据复核资格按工作空间和数据集单独授权，与受控明文审批资格独立。两类复核人须能覆盖该批准定义的完整受众和数据边界，提交人和本次受益人回避。发布人与提交人独立且须具备当前发布资格，合格业务复核人可兼任。业务复核沿用实际脱敏预览及 15 分钟有效期。数据复核绑定同一冻结版本、受众、预览证据、策略和发布基线，签署时及发布前再次验证。失权、到期及审批依据变化时停留或拒绝发布，由原流程撤回、退回或重新送审。

隔离登记明确启用本策略的报表。业务复核和数据复核复用原报表版本、审批记录和发布号，原批准历史保留原真实签名。正常发布与下线、恢复分别验收。真实授权和启用须另行办理。

### 8.3 阶段 3 仪表盘复核与正常发布

本地隔离试验的必需和可选卡片均使用经阶段 3 复核发布且具备获批数据契约的受管 PostgreSQL 报表。继续校验卡片口径、列类型、空值、指标和水位，敏感字段默认脱敏。脱敏投影与原契约不兼容时阻断。全局筛选的全部允许值须落在各映射报表的批准范围内，运行时逐卡继续执行报表限制。必需卡片须覆盖全部看板受众，可选卡片按看板与报表受众及数据范围的交集授权。

首发、任一卡片敏感或高敏、新增或更换数据依赖、扩大受众、数据或参数范围属于高风险。复用原仪表盘冻结版本、复核指派、逐卡真实预览、审批及发布记录。一名独立数据复核人须在同次签署中具备全部引用数据集的当前授权和覆盖，业务复核人、数据复核人各自回避提交人及受益人。发布人与提交人独立。缺签、失权、预览过期、指派变化或获批依赖边界变化阻断正常发布。下线、恢复和周期交付依其自身范围办理。

<a id="dashboard-role-matrix-47"></a>

在明确启用 #47 的工作空间，业务 IT 获得仪表盘入口、查看、设计及送审资格，按当前责任人和草稿状态操作。业务主管获得入口、查看、业务复核及正常发布资格。查看者获得入口和查看资格。正式阅读还须属于获批受众，各卡逐次核对来源报表资格、数据范围和参数。菜单配置与数据授权分别校验。

送审、候选、改派、签署和发布使用同一空间的仪表盘复核资格。业务复核由被指派且独立于提交人的合资格账号完成。正常发布只接受该审批中实际签署且当前仍具备资格的业务复核人手动提交，并核对同一冻结版本、审批与有效发布号。角色叠加仍按版本回避，提交人不能审批或发布自己的版本。须数据复核时核对独立签署，业务签署人以本次业务复核记录确定。原复核人失权时保留旧签署及正式版本；待审申请可以按现行治理职责改派，已批准未发布版本由作者重新送审并选择新的合资格人，重新完成所需复核。重新获得角色时旧批准不能自动恢复发布资格。普通主管不获得独立的改派管理、回滚、下线、恢复及应急资格。

授权按工作空间显式启用。安装增量迁移时所有空间维持原有效动作。已获准且已启用矩阵的目标空间按现有三个内置角色追加有效版本，将仍生效的对应授权迁移到新版本，保留原授予对象、来源、有效期、撤权、冻结和审计。既有成员随其有效角色生效，无需重分配。已有用户组、并集规则、历史审批及未启用空间的权限继续使用当前契约。真实启用以明确授权的目标空间为准。

### 8.4 阶段 3 正式报表与仪表盘下线及恢复

本轮沿用阶段 3 已纳管对象及本地隔离环境。正常下线先登记原因、当前发布号和依赖影响，之后由具备当前对象覆盖的独立业务复核人确认。发布或依赖基线变化时重新申请。下线追加事件，取消未完成访问申请并停止原发布的后续查看、执行和交付。引用报表下线后，仪表盘按必需和可选卡片的原规则处理。

应急停止和应急恢复分别按空间、对象、人员及有效期明确登记，由不同人执行。停止无需正常下线签署，无需验证源可用性或实时取数。停止事件记录原因与此前生效的发布号。仅能快速恢复该发布对应的原获批冻结版本。恢复须重新校验当前受众及用户组、数据和参数边界、字段保护、执行来源与账号、数据契约和卡片依赖。无法证明仍在停前及获批边界内时保持停止，由原报表或仪表盘流程重新送审。恢复追加新发布事件，原撤权、冻结和交付留存限制持续生效。归档的生命周期恢复只恢复草稿可编辑性。完整退出托管和责任人接任由 P3-04 办理；真实权责登记及启用另行授权。

### 8.5 阶段 3 成员退出托管与接任

首批在本地隔离环境核对已纳管正式报表和仪表盘。退出先在原空间冻结，再登记对象、草稿和正式版本、审批及依赖。计划退出须有其他人员持续履行治理职责。紧急冻结直接使用原收紧流程，执行屏障未确认时继续核实原任务回执。

符合当前受众、数据、账号和卡片依赖约束的既有发布继续供原获准受众使用。原成员的访问、个人任务和交付立即受限。源、账号、契约或依赖失效时沿 #23 办理。个人连接、凭据、导出、订阅及旧链接保留既有主体与期限，退出后不得供接任人使用。受管源和执行账号作为依赖记录。

托管发布的查询、仪表盘卡片、报表导出和个人订阅按当前权限取数，并逐次核对原发布的审批快照。当前查看者须仍在原审批受众内，当前有效组织范围须包含于该查看者原获批范围，原审批的来源、执行账号、字段保护和依赖版本仍须可核验。卡片同时遵守报表路径和仪表盘逐卡批准范围。边界扩大或无法核验时，结果请求返回冲突，已排队的订阅停止交付。接任保留原发布时继续执行这项检查，正式停止沿 #23，扩大边界须重新审批。

空间治理人按对象提名。具备当前开发资格和对象所需数据范围的候选人可接受或拒绝。接受后由独立治理复核人确认，复核人回避提名人、候选人和退出人。最终更新责任人及草稿代次，复查成员、数据、对象版本与依赖。原审批及正式版本保留。新修订和边界变化沿 #21 或 #22 送审。原负责人未完成的送审保留原记录及签署人，由接任人重新送审。其他对象的待处理职责沿原流程重新指派。未知写入按原回执确认。

同一平台账号重新加入须经过全新、独立批准的原空间授权。首批从新只读成员身份开始，后续资格按正常授权流程申请。加入后使用批准后新建的登录会话。原成员、冻结和资产历史保留，个人连接、旧受众、流程、订阅及链接仍绑定冻结前的成员身份。真实授权及启用另行批准。

### 8.6 P4-01 批准后生成正式导出文件

首批仅验证本地隔离环境中显式登记、已经按阶段 3 发布且绑定受管 PostgreSQL 数据集的报表。申请沿用独立导出审批，保存加密的受限预览及冻结的申请参数、发布、账号、范围和导出有效上限。批准与唯一生成任务同事务提交。后台任务按原申请人当前资格及冻结参数重新执行，每次核对活动发布、受管账号、组织及字段策略、托管原审批边界与有效上限。原范围和策略变化时不生成文件。拒绝、过期申请及执行结果未知不得自动生成或重跑。

任务复用现有后台工作器、执行回执、受管查询及快照编码。正式文件与审批预览独立加密保存，保留真实生成时间、校验值、CSV/JSON/XLSX 和 16MiB 上限。新文件记录 24 小时期限，首批隔离验收截至文件生成及持久化。本人短期领取与撤权由 #27 验收，到期、清理和告警由 #28 联验，仪表盘交付由 #29 独立验收。存量文件仍按原主体及原七天期限处理。

### 8.7 P4-02 个人与团队订阅复核

首批按报表登记，用本地隔离受管 PostgreSQL 已发布报表验收。个人导出复用 P4-01 已有的独立审批和受限预览。新个人订阅先冻结活动发布、参数、账号及数据策略，经本人显式确认后方可进入原调度，每次确认有效 90 天。修改计划需要再次确认，换版、权限或数据边界变化暂停运行。现有个人计划沿兼容规则。

团队订阅由单独获准的创建人提交，可选当前报表受众中的用户和组。送审时记录展开名单，批准时再次比对。同一数据集明确授权一名独立复核人覆盖整个名单的当前数据范围和冻结参数，申请人和拟收件人回避。批准保存固定名单、逐人批准范围和策略证据，复核有效 30 天。名单、参数、发布或范围变化以及续期通过提交新申请处理，旧申请保留历史。新增组成员不会自动加入已批准名单。

本项验收到复核和批准记录。团队逐人取数、领取、撤权验收从 #27 接续，日期触发的清理与告警随 #28，仪表盘独立验收随 #29。团队导出流程后续另定。

### 8.8 P4-03 逐收件人执行、领取与撤权

本地隔离受管 PostgreSQL 正式报表沿用 #25 的获批文件和 #26 的团队批准。个人正式文件由原申请人申请最长 10 分钟的领取凭证。凭证绑定原空间、已登录的本人会话、批准版本和文件校验值，仅兑换一次。读取、兑换与输出前均重查主体、当前权限及文件期限。兼容文件按原主体和期限使用原下载入口。

具备独立资格的空间授权人只能在冻结名单内逐人登记或撤销本计划的收件资格。计划负责人和拟收件人回避授权。每个期次以本人当前身份取数并保存独立脱敏快照，当前数据必须仍在原批准范围内。范围收紧后新期次可以按缩小范围运行。范围扩大暂停该收件人，其他合格收件人继续；需要更大范围时重新送审。负责人失权暂停整个计划。只向负责人显示交付状态。旧快照须证明其内容仍在当前范围内才允许本人读取，撤权后重新授权仅对新期次生效。

隔离验收使用显式触发的团队期次，复用后台工作器。文件期限和快照期限在领取时校验，到期清理、期限联动和告警由 #28 验收。仪表盘交付随 #29。

### 8.9 P4-04 期限、周期与告警

本地隔离受管 PostgreSQL 正式报表按已批准的团队计划间隔自动入队。同一批准版本的同一自动周期最多一期，重启只处理当前周期，跳过错过的历史周期。负责人失权、当前发布或复核失效时停止新期次，实际取数继续按 #27 逐人检查。手动触发现有入口保留。

正式文件 24 小时、凭证最长 10 分钟、订阅快照 7 天、交付通知资源入口 24 小时分别校验。到期先拒绝读取，维护任务分批清理文件、凭证和到期期次业务载荷，保留原批准、校验值及处置回执。兼容文件保持原期限，正常到期不产生故障告警。新交付的站内消息只包含通用状态与资源引用。通知入口失效后，本人仍可按当前授权从独立的正式文件或期次入口读取尚未到期的数据。

个人指标告警继续按原阈值、去重及恢复流程处理。触发和恢复各自保留当时的最小指标值与事件，处置意见保留，清理快照不改写告警证据。当前授权覆盖原发生数据范围才可读取值，既有个人 Webhook 纳入兼容验证。团队只发送本人交付状态通知。仪表盘交付由 #29 独立验收。

### 8.10 P4-05 仪表盘交付

隔离登记的已发布仪表盘支持整板或指定卡片交付。获批内容绑定仪表盘发布、各选中卡片的活动报表发布及契约、账号代次和冻结参数。重新取数只执行当前获批发布。领取固定期次时重新证明当前看板、卡片、主体和范围仍覆盖该结果，保留该期真实水位和证据。无法核验依赖或权限时拒绝。必需卡片失败阻止整板交付，可选卡片受限仅记录状态。整板导出保留卡片独立边界，将每卡所选格式和清单作为一个归档；指定卡片使用所选原格式。沿用正式文件审批、24 小时文件、最长 10 分钟本人会话一次兑换、聚合字节上限和逐卡行数上限。

个人计划由本人确认，复核有效 90 天。团队计划由一名独立复核人覆盖本次全部卡片数据集、冻结参数及收件范围，复核有效 30 天。导出也由一名具备同等覆盖的独立复核人批准。团队创建、复核和逐人收件授权资格分别登记。收件人逐次按当前范围独立执行，负责人只见状态。撤权阻止后续出件与旧期领取，收紧可在获批子范围出新期，扩大须另审，重授只适用新期。自动队列同周期去重并跳过错过的周期，期次快照 7 天，通知引用 24 小时。

个人指标告警仅使用本计划中一张获批指标卡的授权脱敏结果，触发、恢复和处置均关联原期次。快照到期清理后仍保留可授权核对的最小告警证据。团队只向各收件人发送自己的送达状态。

## 9 当前功能安全验收原则

逐项标准、独立案例、原始数据保真、当前页面与责任人验收统一按[路线图A01—A52](../项目管控/开发路线图与当前任务.md#阶段1验收标准)执行。普通查看、预览、导出、订阅及通知不能授予额外数据权；缺环境、未执行和无法证明保持待验收，技术测试或某次运行数量不代表真实启用授权。
