# 后端架构设计 (Backend Architecture)

本文档详细描述 DBHub 后端的内部架构、分层设计及核心模块实现。

外部数据源连接器的渐进改造方案见[数据源连接器抽象设计](数据源连接器抽象设计.md)。当前已实现中立连接器契约、原生适配器与可选 Java JDBC 服务；`internal/target` 保留为原生驱动实现。业务入口通过 `internal/connectorruntime` 使用统一能力与执行边界。

## 1. 代码组织结构 (Standard Go Layout)

当前 Cloud 后端的主要目录如下，其他业务 API 包省略：

```
backend/
├── cmd/
│   └── server/             # 程序入口 main.go
├── internal/               # 私有应用代码
│   ├── auth/               # 认证、令牌与会话
│   ├── datasource/         # 连接配置与测试接口
│   ├── queryapi/           # 数据工作台、策略与 Redis 操作
│   ├── assetapi/           # 数据目录与元数据采集
│   ├── ticketapi/          # 工单审批与执行
│   ├── config/             # 环境变量配置
│   ├── db/                 # 元数据库仓储与模型
│   │   └── migrations/     # 数据库迁移脚本
│   ├── connector/          # 中立契约、native 与 jdbc 适配器
│   ├── connectorruntime/   # 业务运行时、能力与配置解析
│   ├── target/             # 保留的原生驱动实现
│   ├── sqlparse/           # SQL AST、参数与误写检查
│   ├── netx/               # 目标直连与代理传输
│   ├── sshx/               # SSH 隧道
│   ├── httpx/              # HTTP 解析、错误与响应封装
│   ├── logx/               # 日志初始化
│   ├── middleware/         # HTTP 中间件 (Auth, Logger, CORS)
│   └── server/             # 路由与依赖组装
├── pkg/                    # 可复用公共库
│   └── crypto/             # 加密工具
└── go.mod                  # 依赖定义
```

## 2. 核心模块详解

### 2.1 连接管理器 (Connection Manager)

负责管理用户到目标数据库的物理连接。

- **当前连接方式**: 普通目标请求按需建立独占连接，请求结束后关闭；显式事务持有专用连接。尚未实现按数据源长期复用的统一连接池。DBHub 元数据库使用独立 pgxpool，不属于目标连接池。
- **生命周期**: 建连时使用连接超时；普通请求结束释放目标连接与传输；显式事务由事务接口结束，当前空闲 5 分钟后清理。
- **安全性**: 密码在内存中短暂驻留，仅在建立连接时解密。

### 2.2 SSH 隧道服务 (SSH Tunnel Service)

允许用户通过跳板机访问内网数据库。

- **实现原理**: 使用 Go 的 `golang.org/x/crypto/ssh` 包建立 SSH Client，并通过 `Dial` 方法进行端口转发。
- **当前生命周期**: 目标连接创建 SSH Client，关闭目标句柄时清理；尚未实现跨请求共享 SSH 会话池。

### 2.3 SQL 执行引擎

- **参数化执行**: 应用参数通过驱动参数绑定传递；用户 SQL 同时受 MySQL/PostgreSQL AST 校验、角色权限和误写防护约束，不强制所有语句显式 Prepare。
- **结果集处理**: 驱动逐行读取并按行数限制收集结果，HTTP 返回整包 JSON；当前尚未提供前端流式结果接口。
- **执行可靠性**: 普通 SQL 执行在发送前登记请求和执行状态，保留未知结果并禁止自动重跑；范围见[执行可靠性](../开发指南/SQL工作台执行可靠性.md)。

### 2.4 认证与授权

- **JWT 认证**:
    - Access Token (短效，15分钟)
    - Refresh Token (长效，7天)
- **RBAC 模型**: 基于 Casbin 或自定义中间件实现基于角色的接口访问控制。

## 3. 错误处理规范

所有业务错误必须统一封装，包含错误码和对用户友好的错误信息。

```go
type AppError struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
    Err     error  `json:"-"` // 内部错误堆栈，不暴露给前端
}
```

## 4. 日志规范

使用结构化日志 (Structure Logging / slog)。

- **Info**: 常规请求日志 (Request ID, IP, Latency)。
- **Warn**: 业务异常 (如登录失败、权限被拒)。
- **Error**: 系统异常 (如数据库连接断开、Panic)。
- **敏感信息过滤**: 日志中严禁打印密码、私钥、Token 等敏感字段。
