# 共享数据源与个人凭据方案评估

状态：首期已实现，核对日期：2026-10-17。交付与验收见[共享数据源与个人连接](../开发指南/共享数据源与个人连接验收.md)。本文保留方案依据，第 5 节描述改造前的基线。

## 1. 结论与使用范围

推荐采用“共享驱动与数据源定义、个人连接使用个人数据库身份”的模型。这个方向与成熟数据库管理工具的做法一致，适合 DBHub 向多名使用者开放。

本次按一个 DBHub 实例内、已登录且受邀的用户评估。“全局发布”表示本实例已登录用户可发现，不表示匿名公开。它解决多用户配置复用和执行身份隔离；如果以后向互不信任的多家公司提供服务，仍需增加组织边界，把数据源目录、成员、审计和资源配额限定在相应组织内。

建议批准的首期范围：管理员发布公共驱动配置和不含凭据的数据源定义；用户创建个人数据源，或从目录添加个人连接，并配置自己的数据库账号密码。普通用户不安装任意 JDBC 二进制，不共享凭据和运行结果，不自动获得其他用户的数据库身份。

本文保留设计建议。下面的产品行为来自官方仓库文档与配置阅读，没有部署对照产品进行功能验收。

## 2. 成熟产品参考

| 产品与官方资料 | 已核实的做法 | 对 DBHub 的启示 |
| --- | --- | --- |
| CloudBeaver：[预配置数据源][cb-preconfigured]、[创建连接][cb-create]、[数据库认证][cb-auth] | 管理员可预配置连接，用户选择后输入自己的凭据；连接区分 Private 与 Shared。产品也允许为共享连接保存所有获授权用户共用的凭据，保存范围与认证入口有关。 | 共享连接定义与执行身份可以分离。DBHub 按本次需求只提供个人认证，避免增加“使用发布者账号”的选项。 |
| CloudBeaver：[驱动管理][cb-drivers]、[连接访问权限][cb-permissions] | 驱动下载、上传与管理由管理员执行；文档标注图形驱动管理的版本范围。预配置连接可授予指定用户或团队。 | 驱动安装与使用权限分开。个人驱动配置引用已批准制品，公共目录需要后端可见性校验。 |
| pgAdmin：[当前服务器对话框文档][pg-server-current]、[9.10 发布版文档][pg-server-910]、[导入导出][pg-export] | 管理员可共享服务器；其他用户不能修改共享主机、端口和维护库。当前开发分支文档明确发布者密码、SSH 凭据及相关私有文件不共享。导入导出文档明确密码字段不可导入导出。 | 共享目标由发布者维护，凭据由使用者维护。密码、私钥等材料不进入发布和导出载荷。9.10 文档用于交叉核对共享服务器和修改限制，不将开发分支的全部细节归为该发布版已验收能力。 |
| Apache Superset：[公开配置][superset-config] | `DB_CONNECTION_MUTATOR` 可按用户调整建连参数；存在按身份或用户分区缓存的配置项，相关选项并非默认全部启用，部分标为 testing。 | 连接身份、缓存和后台任务必须一起设计。这些扩展点不代表 Superset 开箱即有 DBHub 所需的通用个人凭据流程。 |

CloudBeaver 的[旧连接模板文档][cb-templates]明确说明该功能在 25.1 被移除。不能依据过期文档复制产品入口。DBHub 已有的数据源模板承担驱动字段和 URL 规则定义，属于内部配置契约；无需因此再增加一套面向普通用户的模板市场。

官方文档站在本次云环境的网络策略下无法直接访问，因此核对了维护方在 GitHub 发布的文档源文件。未核实的 DataGrip 行为不作为结论依据。CloudBeaver 文档包含版本及商业版差异，本文只引用上述明确写出的行为。

## 3. 建议的产品模型

| 对象 | 保存内容 | 所有权与可见性 | 是否包含凭据 |
| --- | --- | --- | --- |
| 驱动配置 | 产品、可信制品版本、驱动类、连接字段与 URL 规则、已验证能力 | 管理员可全局发布；用户可建立个人配置，引用已安装且允许使用的制品 | 否 |
| 数据源定义 | 库存等业务名称、目标地址、端口、库名、环境、TLS 与驱动配置修订 | 管理员可全局发布；个人新建默认私有 | 否 |
| 我的连接 | 数据源修订引用、平台用户、数据库用户名、加密密码、个人别名、个人检查结果 | 仅本人使用，后端从当前登录身份确定归属 | 是 |

JDBC 二进制是运行在服务端的代码。首期允许个人添加驱动“配置”，新增 JAR 仍走管理员校验和部署流程。独立类加载器不能代替进程或容器的执行隔离；如果以后开放普通用户上传 JAR，需要独立的制品审查和运行隔离设计。

个人数据源使用同样的定义与个人连接模型，不额外增加一种执行路径。发布个人数据源时，仅发布不含凭据的定义；个人连接继续留在本人名下。发布到全局由管理员执行，普通用户以后可增加申请发布流程，首期不必建设审批系统。

全局数据源只能引用全局可用的驱动配置；发布时校验依赖的可见性和就绪状态，避免目录可见却无法使用其私有驱动。私有定义不能因为被某个全局对象引用就自动公开。

平台用户名和数据库用户名可以不同。DBHub 不替用户创建目标数据库账号，也不能仅凭账号名称证明其实际归属；数据库负责验证凭据，DBHub 负责确保这份凭据只被其保存者使用。

### 3.1 库存数据源示例

1. 管理员安装并登记经过校验的 GaussDB 驱动版本，配置对应连接规则。
2. 管理员发布“库存数据源”，填写目标地址、库名、TLS 和环境，不填写供其他用户使用的数据库账号。
3. `test` 在“数据源目录”看到“库存数据源”，选择“添加到我的连接”。
4. `test` 输入自己的数据库用户名和密码，测试后保存个人连接。
5. 后续查询、结构浏览、采集和导出都通过这条个人连接执行。
6. 管理员如果也要操作库存库，同样建立自己的个人连接；管理发布内容不隐含使用其他用户凭据的权限。

GaussDB 在此仅作为需求示例，目前仓库没有完成其真实驱动与产品兼容验收。具体产品形态、版本、SQL 方言和元数据范围需要单独验证，不能因为 JDBC 接入成功就标为完整支持，也不能自动套用 PostgreSQL 方言。

### 3.2 界面保持简单

“数据源”页面使用“数据源目录”和“我的连接”两个页签即可。驱动配置保留在设置中，普通用户无需理解制品、模板修订和内部会话等实现对象。

- 目录：查看说明、环境及可用功能，添加个人连接。
- 我的连接：配置个人认证、测试、打开和移除。
- 未配置身份时提示“配置数据库账号”，不直接尝试连接，不回退到发布者账号。
- 移除我的连接只删除本人的绑定及其关联私有内容，不删除公共数据源。
- 只读用户可以配置自己的认证信息，其执行能力继续受只读角色限制。

## 4. 必须同时解决的边界

### 4.1 可发现、可连接和可操作分别校验

目录可见只表示允许发现或添加连接，不代表目标数据库已授权。每次操作至少验证：当前用户有效、能访问这份定义、个人连接属于当前用户、绑定修订仍允许使用、驱动就绪、操作符合 DBHub 权限。

数据库再根据实际登录账号限制对象和操作。DBHub 的角色限制继续生效；例如平台只读用户即使填写具备写权限的数据库账号，平台也拒绝写操作。

所有入口使用同一个个人连接解析服务，覆盖 SQL、Redis、连接测试、结构浏览、采集、预览、导出和工单等路径。后台任务在执行时重新检查用户与绑定状态。客户端不能指定另一个 `user_id` 选择凭据，平台管理员的管理权限也不应默认绕过个人连接归属。

### 4.2 共享目标变更需要用户确认

发布者修改目标地址后，如果直接把已有个人密码发送到新地址，会改变用户原先同意的凭据使用范围。因此建议：

- 数据源定义采用稳定逻辑 ID 和不可变修订，个人连接绑定明确修订。
- 名称、描述等展示信息可单独维护。
- 地址、端口、数据库、TLS、代理路径、驱动或 URL 规则变更时发布新修订；用户查看差异并确认、重新测试后切换。
- 不在后台自动重绑个人连接或携带凭据测试新目标。
- 停用某修订阻止其后新的操作准入；不把已经发出的操作描述为已撤销或已回滚。
- 首期可用停用处理撤回需求，不必增加复杂的灰度或自动升级流程。

### 4.3 元数据和结果按个人连接隔离

两个账号即使连接同一库存库，可能看到不同 Schema、表、列或数据行。因此首期以个人连接作为结构快照、检查结果、查询历史、导出和任务的归属边界。数据库权限或凭据变更后，需要使旧检查与相关缓存失效；已采集快照应标为历史，并在再次提供时按明确策略处理，不能作为当前授权的证明。

首次交付可不缓存业务查询结果。确需缓存时，键至少包含个人连接、定义修订、认证修订、数据库和影响结果的请求参数；涉及平台策略时还需纳入策略修订。不能只用公共数据源 ID 和 SQL 复用不同用户的结果。

公开目录只展示经过发布的目标说明。若以后提供统一的业务数据目录，需要独立的内容发布与访问规则，不能直接展示管理员采集的完整结构。

### 4.4 报表、分享与无人值守任务

共享查询或报表定义，不自动共享执行身份和结果。接收者重新运行时必须解析其本人的个人连接；无法关联到可用连接时提示配置，不能使用创建者凭据执行。

无人值守任务需要明确的执行主体和凭据来源。首期不引入共享服务账号；不能满足个人身份校验的执行入口应拒绝运行。匿名访问和既有公开分享路径需要单独核查，不能因为公共数据源可见就允许其代用任意人的连接。

### 4.5 密码存储与网络边界

复用现有加密存储能力，接口只返回是否已配置；列表、日志、发布、复制和导出均不携带密码。产品管理员不能通过普通管理接口读取或代用他人密码。拥有服务进程、密钥或宿主机控制权的运维身份仍处于信任边界内，不能把应用加密表述为对平台运营者不可解密。

用户自建数据源和连接测试必须遵守平台允许的网络目标及参数规则。个人配置不能放开任意本地文件、执行属性、SocketFactory 或服务端内部地址访问，也不能靠浏览器隐藏字段替代服务端校验。

## 5. DBHub 现状与改造成本

| 现有实现 | 可复用部分 | 必须调整的部分 |
| --- | --- | --- |
| `sys_jdbc_drivers`、`sys_datasource_templates` 与锁定的 JDBC 制品 | 已校验制品、不可变驱动引用、模板追加修订、能力判定 | 驱动配置的个人/全局范围；公共与个人引用的可见性约束 |
| `sys_connections` | 用户归属字段、加密密码、个人配置检查与配置变更保护 | 定位为个人连接，增加对公共/私有数据源定义修订的引用，停止共享执行凭据 |
| 数据源列表与详情 | 现有 CRUD 和测试接口框架 | 当前所有登录用户可见连接；需拆分目录和个人连接的查询与权限 |
| `queryapi.loadOwnedConnection` | 统一运行时入口、原生/JDBC 适配 | 当前明确允许登录用户共用连接凭据；需按当前用户严格解析个人连接，名称本身不提供归属保证 |
| 结构快照与检查结果 | 目前以 `connection_id` 保存，可继续用于个人连接归属 | 所有读取、搜索和汇总路径必须限制个人连接集合；认证变更失效、采集互斥范围需重新核对 |
| 执行回执与事务 | 已有用户维度的防重主键、事务归属与会话清理 | 把个人连接修订与身份快照纳入发送前校验，不因换密码或换定义而重派旧请求 |

整体属于中到高复杂度的权限与数据模型改造。主要工作在所有消费路径的身份一致性、元数据与分享边界、迁移和验收；连接器接口、数据库执行和密码加密不需要全部重写。

现有 `sys_connections` 可作为“我的连接”的基础，公共数据源定义另行建模。不必一开始再拆出通用凭据保险库、凭据共享授权和多身份切换系统。

旧共享连接不能把原有密码自动复制给所有用户。升级时建议转成原创建者的个人连接；需要公开的目标仅发布去除凭据后的定义。原共享使用者重新配置自己的身份。依赖旧连接的报表、任务及历史元数据必须明确迁移归属，无法确定时保留为不可执行的待配置状态，不能静默继承发布者权限。

## 6. 首期交付与验收建议

首期建议包括：

1. 个人/全局驱动配置，引用受信任制品；仅管理员安装驱动和全局发布。
2. 个人/全局数据源定义及不可变修订。
3. 从目录添加个人连接，单用户对同一逻辑数据源先支持一份绑定；以后有明确需求再支持多账号别名。
4. 统一个人连接归属校验，SQL、Redis、测试、结构、导出、工单等实际可用路径全部覆盖。
5. 个人检查、结构快照、历史和导出隔离；既有分享与任务路径完成身份核查。
6. 去凭据发布、目标变更确认、认证修订和旧数据迁移。

可信 JAR 浏览器上传、组织管理、共享服务账号、凭据保险库、跨用户结果共享、自动升级、多身份连接池和业务结果缓存按需求另行设计。本期未实现的操作继续按能力禁用，不扩大 SQL 编辑器按钮范围。

验收至少使用两名普通用户、一个管理员，以及同一数据库中权限不同的两个真实账号，验证：

- `test` 能看到发布的库存定义，未配置凭据时不能执行。
- 为 `test` 添加个人身份后，目标库确认实际登录的是 `test` 配置的数据库账号。
- 修改个人连接 ID、请求 `user_id`、事务 ID、导出/任务 ID 不能代用他人的身份或读取结果。
- 两个账号只能看到各自数据库权限内的对象和查询结果，管理员的结构快照不会自动共享。
- 个人添加与发布都不泄露凭据；发布载荷和导出文件不包含密码或私钥。
- 地址、驱动、TLS 等新修订发布后，旧个人身份不会被自动发送到新目标；停用后的新请求被拒绝。
- 更换密码、并发测试、队列等待、凭据删除及权限撤销遵守配置修订校验，旧请求不被重新执行。
- 只读角色仍然禁止写操作；普通用户不能安装任意 JAR 或绕过目标地址规则。
- 旧共享连接迁移后，其他用户无法继续借用原创建者的凭据执行。
