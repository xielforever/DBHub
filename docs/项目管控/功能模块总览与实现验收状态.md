## 1 状态口径

| 状态 | 含义 |
| --- | --- |
| 已实现 | 当前工作区代码已实现所列能力；旧证据只证明其对应版本，不能单凭旧证据判断当前实现或验收 |
| 待验收 | 已有实现仍需当前页面、逐项证据、约定外部环境或独立责任人验收；缺环境不能记为通过 |
| 后续规划 | 尚未交付的目标增量，不因入口、许可或旧功能存在而视为完成，不自动开始实施 |

阶段 0 有效规则已确认并承接，阶段 1 的实施与验收结论以[路线图](开发路线图与当前任务.md)为准。阶段 2 按确认范围完成隔离技术验收，覆盖明确绑定受管 PostgreSQL 数据集的正式报表发布、查看、独立导出、订阅和实际通知。阶段 3 已按确认的本地隔离范围完成验收及关口核对，覆盖报表与仪表盘复核发布、下线恢复、退出交接和托管发布的原审批边界。阶段 4 的受管报表及仪表盘交付子项已通过本地后台和接口专项验收，阶段关口另行核对。真实权限未切换。2026-10-26 补充了四类角色定向页面及 JDBC PostgreSQL 路径验证，完整任务矩阵、外部范围和独立验收见路线图。

## 3 空间管理与独立入口的边界

空间管理保留六类子页，不能因页面存在就认定全部目标已交付：

| 子页 | 已实现 / 待验收 | 后续规划 |
| --- | --- | --- |
| 空间与成员 | 当前成员、立即收紧、冻结及最小托管；已补定向页面检查，完整逐项验收仍待完成 | 阶段3资产明细、候选接任、接受/拒绝、复核、在途任务及重新加入 |
| 菜单配置、角色管理、角色分配 | 菜单、自定义角色、多角色/组来源、期限、委派、独立治理和来源解释，仍待剩余验收 | 新能力按明确许可登记，不授未来能力通配权 |
| 资源授权 | 当前只读入口、原资源约束及说明 | 阶段2身份、完整范围、分类/脱敏/受控明文；阶段4团队交付规则 |
| 审批发布策略 | 原流程说明及兼容入口 | 阶段3新多节点策略；阶段4相应交付复核 |

[资源与策略接口](../../backend/internal/db/iam_views.go)仍返回editable=false，新规则按钮禁用；[托管状态](../../backend/internal/db/migrations/0048_iam_runtime_bridge.sql)仅允许awaiting_handover。两处均不能标为完整新能力已完成。

| 独立或顶栏入口 | 已有范围及待验收重点 |
| --- | --- |
| 工作空间选择与范围内搜索 | 切换重算资格并清旧上下文；待验当前跨空间、迟到响应及可发现范围 |
| 本人通知 /notifications | 原对象返回仍查原空间及当前资格，通知不授额外数据权 |
| 个人设置与安全 /profile | 既有资料、密码、MFA等能力；待验无空间/无菜单及约定身份环境 |
| 平台管理 /platform | 既有平台范围的独立入口；平台身份不附带空间数据/审批资格，约定SSO等环境仍待验 |
| 治理恢复 /governance-recovery | 最小独立治理恢复；当前资格、双人核验和恢复页面仍待相关验收 |

以上不额外计入11项菜单。业务工作台、技术概览、指标口径和代理入口的合法能力及旧链接，分别回到内容、数据管理、目录/报表和我的连接，见[当前路由](../../frontend/src/router/index.ts)。
