# 仪表盘第一阶段设计

> 2026-10-18 · 设计提案。本文与概念图用于评审，尚未实现仪表盘新版功能。基于正式报表提交 `c6251f7`；报表执行、审批和账号边界见[正式报表验收](../开发指南/正式报表发布与执行账号验收.md)。

## 1. 定位和第一阶段范围

仪表盘将多份已发布报表组合为一个业务页面，帮助使用者先判断整体情况，再查看明细。每张卡片的数据仍由对应报表产生；仪表盘管理布局、引用、受众和自身的发布版本。

默认面向已登录的内部业务人员，沿用现有开发者、管理员、只读用户及用户组。先交付可管理、可发布的基础看板，不增加通用 BI 编辑器。

| 优先级 | 范围 |
| --- | --- |
| P0 | 我的开发、已发布目录；管理员待审列表；名称搜索 |
| P0 | 从本人有权查看的正式报表中添加卡片；每页 1–8 张，同一报表只能添加一次 |
| P0 | 复用指标、表格、折线、柱状和饼图；保持报表获批的图表配置、单位、数据顺序和数值精度 |
| P0 | 上移/下移、移除、四种宽度预设；桌面栅格、移动端图表单列；预览、显式保存草稿 |
| P0 | 冻结版本、单级管理员审批、指定用户/组、显式发布、下线、回滚、责任人移交 |
| P0 | 手动刷新全部、单卡重试、独立加载/错误状态、最后成功时间和版本变化提示 |
| P0 | UUID 幂等、并发版本检查、执行限流、撤权检查、可靠审计和依赖影响展示 |
| P1 | 拖动布局、收藏、全屏查看；在报表先支持声明式参数后，再设计统一筛选和参数映射 |
| P2 | 定时刷新、订阅、导出、大屏轮播及受权限约束的结果缓存；另行评估负载和数据交付边界 |

第一阶段不提供仪表盘 SQL 编辑、跨报表计算、浏览器二次聚合、任意组件/HTML、跨图联动、匿名链接或新的执行账号配置入口。保留 `/dashboard` 为平台“概览”，新增 `/dashboards` 为业务“仪表盘”，两者用途清晰区分。

## 2. 现状与复用范围

当前 `/dashboards` 前端跳转到报表，导航不显示入口。仓库仍保留早期 `sys_dashboards`、CRUD、收藏及 JSON 布局界面，查看逻辑依赖个人报表和个人连接；它们不具备新版正式发布的审批和执行边界。

实施时应新增受管仪表盘模型及接口，恢复前端入口后连接新模型。旧对象不自动发布，不将旧 `shared` 状态解释为审批通过；旧接口兼容与弃用单独处理，不能借旧接口修改新对象。第一阶段通过新建草稿重新组合正式报表，不自动迁移旧个人报表引用。

复用现有 `ReportResult`、`reportChart`、ECharts、结果表格、用户组、审计、持久执行回执和受限报表执行路径。仪表盘不保存 SQL、密码、连接对象或查询结果，也不维护另一套数据库账号。

## 3. 页面与操作

### 3.1 目录

- 只读用户默认进入“已发布”；开发者增加“我的开发”；管理员增加“待审批”。
- 页面主操作只有“新建仪表盘”；列表支持名称/描述搜索和分页。
- 条目展示名称、描述、责任人、状态和更新时间。发布版本与开发草稿状态分别显示，例如“已发布 v3 · 草稿有修改”。
- 普通查看者看不到待审草稿、审批备注、SQL、执行账号或管理按钮。

### 3.2 编辑

使用独立编辑页，顶部保留“添加报表”“保存草稿”“提交审批”，预览放在次级操作中。添加报表打开选择抽屉，只列出本人当前可查看、账号和数据源可用的正式报表；不要求填写数据库账号。

选中卡片后展示紧凑属性区：报表名称与引用发布版本、宽度、上移/下移、移除。“整行/半行/宽列/窄列”对应桌面 12/6/8/4 栅格；高度按报表类型给定，暂不开放任意像素位置和尺寸。卡片顺序也是移动端阅读顺序。

第一阶段不做自由拖拽。所有排序操作提供按钮和键盘路径；移动端以卡片列表和属性抽屉编辑，不压缩桌面属性栏。离开未保存页面时提示；409 冲突保留本地草稿并要求核对，不自动覆盖服务端。

### 3.3 查看

独立查看页显示仪表盘名称、发布版本、当前刷新进度及每卡最后成功时间。主操作是“刷新数据”；单卡错误时才出现“重试”，有权限的卡片可“查看报表”。管理操作集中在角色对应的管理入口或“更多”，不混在日常查看工具栏中。

进入页面先取服务端授权后的布局，优先查询首屏卡片，再按顺序补齐。数据逐卡显示，一张失败不会阻塞其他卡片。每卡执行独立查询，可能跨数据源；页面不宣称所有卡片处于同一个事务快照。

没有报表权限的卡片只显示通用“内容不可访问”占位，不展示报表名称、图表配置、字段、数据库错误或版本明细。整个仪表盘无权访问时不返回布局。

## 4. 版本、审批与报表依赖

默认采用**固定报表发布版本**，避免仪表盘获批后因底层报表更新而静默改变数据口径。固定的是查询和展示定义，业务数据仍在每次查看或刷新时实时读取，不是冻结结果快照。

1. 开发者保存私有草稿；卡片引用具体 `report_id + report_publication_no`。
2. 送审时生成不可变仪表盘内容版本。服务端补齐报表版本、批准清单摘要及依赖记录，不信任客户端传入的批准摘要。
3. 另一位管理员检查布局、组合后的数据范围和拟发布受众；预检确认所有引用仍是当前正式发布、账号与数据源可用。审批者需拥有被引用报表的查看权限，不能借仪表盘预览绕过权限。
4. 批准绑定仪表盘内容摘要、报表依赖清单及受众。批准与发布分开，发布前再次检查依赖；草稿后续修改不影响当前发布。
5. 底层报表发布新版本、回滚或下线后，旧引用不再执行，卡片显示“报表已变化，等待维护”，其他卡片仍可使用。责任人通过“更新引用”生成新草稿，再审批发布。
6. 仪表盘回滚也只能恢复仍满足当前依赖与授权条件的历史发布；不能借回滚恢复已下线报表或执行报表历史 SQL。

这是第一阶段的明确取舍：报表更新可能需要同步维护引用它的仪表盘。管理端必须展示反向依赖及影响数量，发布报表前提示影响；本期不引入自动跟随版本或独立历史报表执行能力。

同一数据库身份仅轮换密码，不改变报表发布编号，仪表盘无需重新审批；停用账号或数据源立即影响后续执行。版本、审批和发布记录追加保留；删除责任人前须移交，历史操作人保留名称快照。

## 5. 权限和执行边界

| 场景 | 服务端规则 |
| --- | --- |
| 查看目录/布局 | 用户有效，仪表盘已发布且命中其用户/组受众 |
| 执行卡片 | 同时满足仪表盘授权、报表授权、双方预期发布编号，以及报表账号和数据源可用 |
| 私有草稿预览 | 草稿责任人；引用报表的查看权限仍须独立满足 |
| 审批预览 | 有权审批且不是提交者；只执行其本人可查看的引用报表，不切换为作者或管理员的数据库身份 |
| 管理权限 | 管理员可管理对象和审阅元数据，管理角色本身不等于报表数据读取授权 |
| 下线仪表盘 | 阻止通过该仪表盘继续执行；用户已有的独立报表授权不被撤销 |

仪表盘授权不向下批量授予报表权限。管理员审阅时展示拟发布受众的覆盖情况；用户组在运行时动态检查，不能依赖发布时算出的成员快照。受众只拥有部分报表权限时，允许查看其有权卡片，其余显示通用占位；全部不可用时显示统一空状态。

仪表盘标题和描述本身也是送审内容，可对仪表盘受众展示；卡片标题来自有权读取的报表元数据，不接受任意自定义标题来泄漏受限报表名称。

卡片执行请求仅提交仪表盘发布编号和执行 UUID。服务端按 `dashboard → active release → frozen tile → report release → approved report account` 解析，拒绝 SQL、报表 ID、连接、账号、事务或参数覆盖。必须在现有执行核心加入仪表盘范围检查，在入队、SQL 发出前和结果交付前同时验证双方权限与版本；仅在 HTTP 入口检查不够。

## 6. 刷新、异常、幂等和资源预算

| 情况 | 预期行为 |
| --- | --- |
| 刷新全部 | 每轮产生页面代次，每卡一个 UUID；前端最多同时发出 2 个查询，剩余排队；后端继续执行既有用户、账号及全局准入限制 |
| 重复点击 | 刷新期间禁用相同操作；迟到响应必须匹配页面代次、仪表盘与报表发布编号才可展示 |
| 网络响应丢失 | 保留原 UUID 核对回执；已有执行返回既有 40901 回执，不再次发送 SQL；回执不存结果行，不能假装可以重放结果 |
| 用户明确重试 | 新建执行 UUID，重新校验权限并运行；不自动循环重试或在后台反复查询 |
| 单卡失败 | 单独展示可理解的失败状态，成功卡片继续可用；失败不等于空数据 |
| 普通网络/数据库超时 | 已交付的数据可在当前页面内存保留，明确标为上次成功数据和时间；不把旧数据计入本轮成功 |
| 已知撤权、下线、版本冲突、账号停用 | 立即清除相应旧结果；仪表盘被撤权则清除整页，停止后续请求 |
| 离线或后台切换 | 暂停未发出的请求，标识未完成；返回页面需用户手动刷新，不自动发起新一轮 |
| 页面切换/退出登录 | 取消尚未发送的任务，对运行中查询尽力取消，销毁图表及结果内存；不使用 localStorage、IndexedDB 或跨用户结果缓存 |
| 数据截断/精度不适合图表 | 复用现有报表规则：显示截断或精度提示，不以部分结果绘图；表格保留准确文本 |

已展示的数据不能追溯收回；离线页面也无法即时获知撤权。服务端保证撤权后的新检查不交付结果，前端在获知权限变化时清除已知失效内容。

首版每页最多 8 张卡片、每卡最多 1000 行和 30 秒或更严格系统限制。全页查询可能分多轮完成，不承诺全页 30 秒返回。继续复用 ECharts Canvas 和结果表格，最多 8 个图表实例；图表按可见区域初始化，不增加 WebGL 或新布局库。

行数上限不能限制超大单元格。实施卡片执行前，应补充结果字节预算：建议每卡默认最多 2 MiB、以更严格配置为准，读取或编码时超限即明确失败，不能先无限缓冲再截断。需保留既有数值保真语义。页面客户端并发 2 只是体验预算，不能代替后端限流；多实例配额不在本次设计中宣称已实现。

草稿维护、送审、审批、发布、下线、回滚和移交采用 UUID 幂等记录；同号同内容返回原操作标识，同号不同内容返回 409。草稿用 `draft_version`、发布用 `expected_publication_no` 比较并加行锁，竞争操作只允许一个生效。执行回执指纹应额外绑定仪表盘、卡片和双方发布编号，不能与独立报表执行混用。

## 7. 数据模型建议

新增受管对象，避免沿用旧表的作者删除级联和全局 `shared` 语义。以下为逻辑模型，实施时再确定迁移编号。

| 对象 | 保存内容与约束 |
| --- | --- |
| `sys_managed_dashboards` | 稳定 ID、责任人、工作草稿、草稿编辑版本、最新内容版本、当前发布指针与发布序号；责任人删除需先移交 |
| `sys_dashboard_versions` | 冻结名称、描述、卡片顺序/宽度、依赖清单及规范化内容摘要；禁止修改/删除 |
| `sys_dashboard_report_refs` | 由冻结版本生成的报表和发布引用，供完整性检查与反向影响查询；不能由客户端独立修改 |
| `sys_dashboard_reviews` | 一次性审批结果、审批者快照、受众、批准摘要、意见；禁止自审 |
| `sys_dashboard_validations` | 同一审批者的依赖预检记录及摘要，15 分钟有效；不保存结果行，不代表跨报表数据快照 |
| `sys_dashboard_releases` | 追加发布、下线、回滚事件，操作者快照及发布编号 |
| `sys_dashboard_commands` | 操作者、UUID、操作类型、请求指纹和安全结果标识；复用已有命令防重模式 |

布局只保存受限声明数据，例如：

```json
{
  "name": "库存总览",
  "description": "库存金额、仓库分布与低库存明细",
  "items": [
    {"tile_id": "e6c65750-1bc4-4c65-9d4e-2522533c879a", "report_id": 101, "report_publication_no": 3, "width": "wide"},
    {"tile_id": "d3b7e480-157d-4c33-8389-711c26499552", "report_id": 102, "report_publication_no": 2, "width": "narrow"}
  ]
}
```

服务端限制名称/描述长度、最多 8 张卡片、唯一 tile UUID、唯一报表引用、正整数发布编号、宽度枚举和请求体大小；拒绝未知字段及任意 URL/脚本。发布响应按当前用户逐卡裁剪，不能直接把内部布局或冻结依赖对象序列化给查看者。

## 8. 接口建议

所有路径位于 `/api/v1`，与旧 `/dashboards` CRUD 分开。以下接口均为拟新增能力。

| 方法与路径 | 用途 |
| --- | --- |
| `GET/POST /managed-dashboards` | 列出自己的开发/管理员管理范围，或创建草稿；创建要求 UUID |
| `GET /managed-dashboards/{id}` | 责任人或管理员读取管理元数据 |
| `PUT /managed-dashboards/{id}/draft` | 责任人保存完整布局，校验草稿版本与 UUID |
| `POST /managed-dashboards/{id}/submit` | 冻结内容版本及依赖，校验草稿版本与 UUID |
| `GET /managed-dashboards/{id}/versions` | 管理历史内容、审批结果和布局/依赖差异 |
| `POST /managed-dashboards/{id}/preview/tiles/{tile_id}/execute` | 责任人预览已保存草稿卡片，绑定草稿版本和执行 UUID |
| `POST /dashboard-reviews/{id}/preview/tiles/{tile_id}/execute` | 管理员预览冻结待审卡片；仍检查本人报表权限 |
| `POST /dashboard-reviews/{id}/validate` | 管理员校验当前依赖和受众，返回短期预检标识；不执行新 SQL 定义 |
| `POST /dashboard-reviews/{id}/decision` | 非提交者管理员批准/退回；责任人可撤回；批准要求有效预检 |
| `GET/POST /managed-dashboards/{id}/releases` | 发布历史，以及按预期发布编号发布/下线/回滚 |
| `POST /managed-dashboards/{id}/transfer` | 管理员移交责任人，校验草稿版本与 UUID |
| `GET /published-dashboards` | 当前用户有权访问的正式目录 |
| `GET /published-dashboards/{id}` | 当前正式布局及按用户裁剪的卡片状态，不返回 SQL/凭据 |
| `POST /published-dashboards/{id}/tiles/{tile_id}/execute` | 仅接受仪表盘预期发布编号与执行 UUID；从冻结引用解析报表并逐层授权 |

不新增“客户端批量传入任意报表运行”的通用接口。依赖预检与发布需要一致性锁/版本检查；预检成功后引用发生变化必须拒绝发布，不能将检查与提交间的竞态留给浏览器。

## 9. 审计、可访问性与本地设计评审

新增仪表盘草稿维护、送审、预检、审批、发布、下线、回滚、移交、查看及卡片执行审计。卡片审计同时关联访问用户、仪表盘 ID/版本/发布号、tile ID、报表 ID/版本/发布号、实际数据库账号和执行 UUID；报表与仪表盘审计用同一关联标识，不重复发送查询，不保存 SQL、密码或结果行。继续沿用可靠审计写入与积压可观测能力。

视觉层按以下标准做本地专项评审，不使用并行代理：

| 视觉层 | 编码与检查重点 |
| --- | --- |
| 指标 | 仅展示报表已计算的单值，标明单位；状态不能只用颜色；不能在仪表盘计算增长率 |
| 趋势 | 时间顺序、单位和缺失点保留；不把 NULL 转零；移动端保持趋势与日期可读 |
| 仓库比较 | 柱状图零基线、直接标注数值；配置来自获批报表，不在仪表盘替换图形或重排结果 |
| 明细 | 数值精度、列标题、截断提示和数据时间可见；窄屏仅表格区域可横向滚动 |
| 状态和控制 | 加载、无数据、超时、不可访问、版本变化互相区分；可键盘操作；移动端触控目标至少 44px |

正式实现需满足正文对比度 4.5:1、交互/图形关键元素对比度 3:1，支持可见焦点和减少动画。图表提供可访问名称与准确结果表格，不依赖悬浮才能读取关键数值。URL 只保留仪表盘标识和页面模式，不放凭据、结果或未经声明的参数。导出不在第一阶段范围。

## 10. 实施顺序和验收条件

按三个可验收批次推进：受管模型与权限/生命周期；逐卡执行与依赖守卫；目录、编排、审批和桌面/移动端查看。复用既有报表的实现模式，本轮不抽象通用审批平台。最后进行真实多用户、真实数据库的完整流程验收。

必须覆盖以下场景：

1. A 组合已发布报表并送审，另一位管理员批准发布；A 不能自审；无个人数据库连接的受众 B 可查看。
2. B 有仪表盘授权但无某报表授权时，不触发该卡查询，也不泄漏卡片名称或数据；无仪表盘权限不能通过卡片路由执行。
3. 保存新草稿不影响线上版本；两人并发保存、审批、发布分别只有一个预期版本成功；同 UUID 重试不重复创建或执行。
4. 报表更新、回滚、下线后旧卡片停止；用户不能用仪表盘历史引用运行报表旧版本；更新引用并审批发布后恢复。
5. 排队时撤销仪表盘权限、交付前移除报表组成员、停用用户/账号/数据源，均拒绝相应执行或结果。
6. 刷新期间切换仪表盘或版本，迟到结果不覆盖新页面；前端并发不超过 2，直接调用接口仍受后端准入控制。
7. 一张卡超时、查询失败、字节超限或结果截断时，其他卡正常；旧结果、空结果和失败明确区分；精确数值沿用报表专用路径。
8. 发布依赖预检后报表变化，发布失败；回滚也重新检查依赖，不通过历史状态绕过撤权。
9. 作者停用或移除个人连接不影响已发布仪表盘；删除作者前强制移交，历史发布与审计保留。
10. 桌面 1440×1000 与移动端 390×844 可用；键盘可完成添加、排序、保存和查看；页面无横向溢出，表格局部滚动；页面脚本错误为 0。
11. 审计存储失败时遵循已有拒绝执行规则；审计可追踪实际查看者、仪表盘、报表版本及数据库账号。
12. 旧仪表盘对象和旧共享链接不会自动进入新目录，旧接口不能修改受管仪表盘。

以上为实施后的验收目标。本次仅完成仓库现状核对、功能/技术设计、概念图和演示数据一致性检查，未声称这些仪表盘场景已经通过运行测试。
