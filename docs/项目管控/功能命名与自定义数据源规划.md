# 功能命名与自定义数据源规划

状态：N1/N2/J1 首版已实现，2026-10-17。本文保留产品方向和后续扩展规则；当前实现、限制和证据以[连接器与 JDBC 自定义数据源验收](../开发指南/连接器与JDBC自定义数据源验收.md)为准。

## 1. 产品方向

DBHub 以数据源为入口，提供结构浏览、数据操作和管理能力。模块名称不绑定某一种查询语言；进入具体操作时仍使用准确术语，例如 SQL 编辑器、Redis 键、TTL 和事务。

自定义数据源的目标是：管理员登记 JDBC 驱动、定义可复用模板，使用者无需修改 Go 的数据库类型分支，就能创建该模板的数据源实例。实际启用哪些操作取决于已实现并验证的能力，不把“能连接”视为“所有功能都兼容”。

## 2. 功能命名

### 2.1 导航与页面

| 原名称 | 当前名称 | 职责与边界 |
| --- | --- | --- |
| 运营总览；对应路由标题又叫仪表盘 | 概览 | 平台整体状态，与用户创建的仪表盘区分 |
| 数据源管理 | 数据源 | 创建、配置、检查和打开具体实例 |
| SQL 工作台 | 数据工作台 | 按所选数据源能力呈现 SQL、结构浏览或键值操作 |
| 数据资产 | 数据目录 | 展示采集的结构、业务说明、负责人、标签和收藏 |
| 报表中心 | 报表 | 查看和管理报表 |
| 仪表盘（`/dashboards`） | 仪表盘 | 用户创建的报表组合，保留此名称 |
| 工单中心 | 变更工单 | 数据变更审批与执行 |
| 代理管理 | 连接代理 | 配置目标连接使用的代理，不扩称为尚未实现的完整网络管理 |
| 用户与权限 | 用户与权限 | 保留 |
| 操作审计 | 操作审计 | 保留 |
| 系统设置 | 系统设置 | 保留；后续按角色提供驱动管理与数据源模板设置 |

“数据工作台”是产品入口，“SQL 编辑器”是其中一种操作视图。不把 SQL 编辑器强行改成含义模糊的通用命令框，也不通过改名暗示已经有 Redis 或任意 JDBC 的操作界面。

### 2.2 操作与状态文案

| 原文案 | 当前文案 | 说明 |
| --- | --- | --- |
| 新建连接 | 新建数据源 | 创建一份持久化的数据源配置 |
| 编辑连接、删除连接 | 编辑数据源、删除数据源 | 与列表、弹窗和确认信息统一 |
| 连接名称 | 数据源名称 | 例如“生产订单库” |
| 工作台中的“连接”选择器 | 数据源 | 与主入口用词统一 |
| 数据源卡片“查询” | 打开 | 进入该实例实际支持的操作视图 |
| 测试连接 | 测试连接 | 保留，描述一次真实连接检查 |
| 最近测试 | 最近检查 | 显示时间、结果和版本，不描述为持续在线状态 |
| 同步字典 | 采集结构 | 采集库、Schema、表和字段等元数据，不表示搬运业务数据 |
| 字典同步结果、同步时间 | 结构采集结果、采集时间 | 与“采集结构”统一 |
| 运行、格式化 | 运行、格式化 | SQL 视图保留第一阶段的基础操作 |

数据源的持久配置称“数据源”；驱动建立的临时会话仍称“连接”。因此“连接超时”“连接失败”“测试连接”继续使用连接一词。

### 2.3 命名落地规则

- 导航、路由标题、页面标题、面包屑、浏览器标题、空状态、提示、确认框与无障碍标签统一更新，不只替换侧栏文字。
- 第一轮保留 `/query`、`/connections`、`/assets` 等 URL、路由标识、API 路径、权限码和数据库表名，避免把改名变成兼容性迁移。
- 菜单名称和页面标题使用同一份前端名称定义，解决当前概览标题与导航不一致的问题。
- 历史验收报告、截图和提交记录保留当时名称；当前产品规范引用新名称，并注明旧名称映射。
- 新名称不扩展权限，也不增加 SQL 工具栏按钮。尚未实现的驱动管理和模板设置不提前显示为可点击入口。

## 3. 区分驱动、模板和实例

| 对象 | 作用 | 示例 |
| --- | --- | --- |
| JDBC 驱动 | 一组可执行的驱动制品与依赖，定义如何连接目标 | 某个固定版本的 Oracle JDBC 驱动及驱动类 |
| 数据源模板 | 定义产品名称、连接参数、URL 规则、驱动版本、元数据方式和候选能力 | “Oracle 服务连接”模板 |
| 数据源实例 | 使用模板填写地址、数据库、账号和环境，形成实际连接配置 | “财务生产库” |

JDBC 是接入方式，不是数据库产品。新建入口可以叫“自定义 JDBC”，保存后的卡片应显示模板名称和实际产品；不能只显示“JDBC”而丢失产品信息。

内置的 MySQL、PostgreSQL、Redis 也可逐步由模板描述表单。默认接入方式由模板决定，普通使用者不必先理解驱动架构；只有需要自定义接入时，才进入 JDBC 配置。

## 4. 自定义 JDBC 流程

### 4.1 管理员准备

1. 在“系统设置 → 驱动管理”登记或导入一个 JDBC 驱动版本，记录制品、依赖、驱动类、版本、JDK 范围和校验值，验证可加载。
2. 在“系统设置 → 数据源模板”创建模板，选择已就绪驱动，定义连接字段和 URL 规则，选择已有的元数据与 SQL 方言适配。
3. 用测试实例验证模板实际能力后发布。没有 SQL 方言适配的模板可以明确发布为连接检查与已验证元数据功能，不承诺 SQL 操作。

第一版驱动可以通过部署制品导入，先把登记与版本引用做完整；是否提供浏览器上传属于后续制品管理交付。数据源使用者无需为每个实例再次上传驱动或填写驱动类。

模板保存为草稿不代表可用；已发布模板须引用可加载驱动，并能校验其连接配置。对于未实现 URL 解析或字段映射的驱动，先完成对应模板适配，不能直接把任意字符串交给驱动。

### 4.2 使用者新建数据源

入口统一为“数据源 → 新建数据源”：

1. **选择模板**：内置 MySQL、PostgreSQL、Redis；或“自定义 JDBC”中的已发布模板。
2. **填写配置**：数据源名称、环境，以及模板声明的地址、库名/服务名、认证和扩展参数。
3. **测试连接**：分别反馈驱动状态、连接结果、服务端身份、版本与当前可用功能。
4. **保存数据源**：保存对模板和驱动的具体版本引用；未测试的配置标为待检查，不能显示为已验证。

若尚无合适模板，管理员可从该流程进入“新建数据源模板”；其他角色看到缺少模板的明确提示，可使用已发布模板。驱动类和 URL 规则集中管理，不散落在每个业务实例中。

测试与保存仍是不同动作，第一轮不通过改名强制改变现有数据源允许先保存配置的行为。保存前修改配置须使旧测试结果失效；草稿测试不能替换已保存实例的检查记录。

### 4.3 模板字段

| 字段组 | 管理员配置 | 使用者填写 |
| --- | --- | --- |
| 标识 | 稳定模板 ID、显示名称、说明、产品标识、数据模型（关系型/键值） | 数据源名称、环境 |
| 驱动 | 连接器 ID、已就绪的驱动版本、驱动类 | 无需重复填写 |
| 地址 | URL 模板、允许的 JDBC 前缀、端点与数据库/服务名映射 | 主机、端口、数据库或服务名；模板允许时也可输入 JDBC URL |
| 认证 | 用户名、密码及其他认证字段的类型与必填规则 | 对应凭据，独立输入和加密保存 |
| 扩展参数 | 字段类型、默认值、必填项、可选值和敏感标记 | 例如字符集、应用名称等模板允许的属性 |
| 传输 | 当前适配器已验证的直连、TLS 等模式 | 选择已支持模式；未实现的代理/SSH 不提供可用选项 |
| 元数据 | 已有通用或产品专用元数据适配、Catalog/Schema 映射 | 需要时选择实际采集范围 |
| SQL | 已实现的方言 ID、参数方式、已验证约束 | 无需手填解析器或声明安全能力 |
| 功能 | 从实现支持的能力中选择需要启用的子集 | 查看可用功能及限制，不能自行开启未实现能力 |

URL 模式与结构化模式由模板声明；后端解析并校验目标，保存一种明确的规范配置，禁止两套冲突配置同时生效。凭据独立传递，不能写进 JDBC URL、预览、日志或回执。

例如以下是模板设计样例，尚未在 DBHub 实测：

```text
模板名称：Oracle 服务连接
接入方式：JDBC
驱动类：oracle.jdbc.OracleDriver
驱动版本：选择实际已导入版本，不使用“最新”浮动引用
URL 模板：jdbc:oracle:thin:@//{host}:{port}/{service_name}
实例字段：host、port、service_name、username、password
SQL 方言：未配置时不启用 SQL 操作
元数据：仅启用已验证的通用读取项
```

这种配置化能力可以减少新增产品时的重复表单和 Go 类型分支，但不会自动生成某个产品的 SQL 解析器、DDL 读取或事务实现。

## 5. 数据工作台按能力呈现

| 实例实际能力 | 打开后的行为 | 不应出现的误导 |
| --- | --- | --- |
| SQL、方言与角色约束已支持 | SQL 编辑器与结果区，可运行；格式化按其能力提供，只读角色落实只读约束 | 不能因 JDBC 而增加一排高级按钮 |
| 元数据支持、SQL 尚未支持 | 结构浏览，按能力提供表、字段等信息，说明 SQL 不可用的原因 | 不能只弹“SQL 语法错误”，也不能显示可运行的假编辑器 |
| 键值操作已支持且对应视图已交付 | 键浏览、值和 TTL 等实际已实现操作 | 不显示 SQL 运行和格式化 |
| 仅连接检查 | 数据源详情与检查结果，明确尚无可用操作视图 | 不默认跳转 SQL 页，也不标为产品完整兼容 |
| 驱动未安装或不可用 | 显示驱动未就绪及可处理入口 | 不把“驱动缺失”当作数据库离线 |

当前 `WorkspaceView.vue` 按能力加载 SQL、Redis 键值或结构浏览视图；Redis 键值界面已纳入独立浏览器验收。

格式化能力也单独判断。支持执行某产品的 SQL，不代表当前格式化库已经支持相同语法；不支持时明确说明，不能按 PostgreSQL 或 MySQL 猜测。

结果区继续区分成功、失败、取消中和结果未知。语言从 SQL 工作台改为数据工作台，不改变执行回执、防重或未知结果的含义。

## 6. 逻辑模型与版本引用

下表描述逻辑模型。当前首版具体字段、约束、索引见迁移 0021、数据库模型及 API 规范；尚未支持的高级字段不在表单中提供。

| 对象 | 最少需要的信息 | 不变量 |
| --- | --- | --- |
| 驱动版本 | 稳定驱动 ID、版本、制品/依赖校验值、驱动类、JDK 范围、就绪状态 | 导入新版本不覆盖旧版本；加载失败不能标就绪 |
| 模板修订 | 稳定模板 ID、修订、产品/模型、连接器和驱动版本、字段定义、URL 规则、方言与元数据适配、发布状态 | 修订发布后不可原地改变其含义 |
| 数据源实例 | 现有配置归属、具体模板修订、参数、独立凭据、配置修订 | 不使用浮动的最新模板或最新驱动 |
| 检查结果 | 实例配置修订、实际产品和版本、驱动信息、开始/完成时间、结果与能力诊断 | 配置或绑定版本变更后失效，不用模板显示名称推断产品已验证 |

迁移 0021 已实现驱动与模板目录、固定修订引用和参数；`type=jdbc` 只是接入兼容字段，产品、驱动、方言由模板定义。

模板或驱动升级需要显式迁移具体实例并更新其配置修订，重新测试；不自动改变既有实例的连接行为。驱动或模板被停用时禁止新建对应会话，并明确显示不可用原因；被引用版本不可直接删除。对已有执行和事务沿用清理与结果未知规则，不重派操作。

## 7. 权限与既有保护

| 操作 | admin | developer | readonly |
| --- | --- | --- | --- |
| 登记驱动、发布或停用模板 | 可 | 不可 | 不可 |
| 查看并选择已发布模板 | 可 | 可 | 查看可见模板摘要 |
| 新建、编辑、删除数据源 | 沿用现有授权 | 沿用现有创建者授权 | 不可 |
| 测试保存配置 | 沿用现有授权 | 沿用现有授权 | 沿用现有授权 |
| 测试编辑草稿、复用保存口令 | 沿用现有授权 | 沿用现有创建者授权 | 不可 |

前端入口和后端授权同时落实。普通模板列表不返回驱动制品内部路径、凭据或敏感属性默认值；驱动详情仅对管理角色开放。

自定义 URL 与属性加入目标身份校验：改变驱动/模板修订、端点、库/服务、用户、TLS、代理或可能重定向连接的属性时，不能悄悄把原密码发往新目标。对于无法可靠解析目标的配置，禁止复用旧口令测试。

这项规则面向新增 JDBC 模板；当前原生接入的口令复用和保护范围继续以现有 API 契约为准，不能通过文字规划暗中改变。

## 8. 分阶段实施

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| N1：命名统一 | 导航、标题、按钮、提示与说明统一；保留原 URL 和 API | 没有连接/数据源混用；概览与仪表盘不再同名；不出现未实现入口 |
| N2：连接器与能力入口 | 落地原生接口包装、能力判定及“打开”目标导航 | SQL、仅元数据和未交付视图有明确区别；原生可靠性回归 |
| J1：JDBC 与自定义模板 | 驱动登记、模板配置与发布、实例创建/检查、通用元数据 | 至少一个新增产品真实验证；与已有产品做同库对照；权限和版本绑定有效 |
| J2：产品能力扩展 | 按需实现 SQL 方言、策略、格式化、产品元数据和事务 | 每项能力分别验收；不因模板发布自动获得全部能力 |

本次已完成 N1、N2 与 J1 首版；J2 的新产品 SQL 方言留待实际需求。第一版登记部署清单中已安装的驱动，不提供浏览器 JAR 上传；模板直接发布不可变修订，没有草稿/审批流程；实例只填写结构化字段，不允许直接透传 JDBC URL 或任意属性。通用未知产品只提供结构浏览，未验证完整范围时不提供采集。

命名验收覆盖桌面和移动端、菜单与标题、空状态、提示、辅助技术标签；创建流程验收覆盖未知模板、驱动缺失、重复提交、保存前改配置、旧响应覆盖、权限不足和引用版本停用。

完成状态与证据见当前验收文档。历史兼容矩阵继续证明原生驱动的实际范围，不能因“自定义 JDBC”入口出现而扩写支持清单。
