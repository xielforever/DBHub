# 项目开发文档防失控指南 (Documentation Governance Plan)

> **核心原则**：代码未动，文档先行。文档不仅是记录，更是契约。

为了防止 DBHub 项目在开发过程中出现“不可控、难维护、难协作”的问题，特制定本指南。所有开发人员（包括 AI 助手）必须严格遵守。

## 1. 文档驱动开发 (DDD - Documentation Driven Development)

开发流程必须严格遵循以下 **SOP (标准作业程序)**：

### 阶段一：设计与契约 (Design & Contract)
❌ **严禁跳过此阶段直接编写代码**

在开始任何 Feature 开发前，必须先产出或更新以下文档：
1.  **数据库变更**：更新 `docs/数据库设计/数据库模型设计.md`。必须包含完整的 DDL SQL 和索引设计。
2.  **API 契约**：更新 `docs/接口规范/API接口规范.md`。必须包含详细的请求/响应 JSON 示例、错误码和认证方式。
3.  **UI/UX 规范**：如果是前端功能，必须在 `docs/界面设计/UI设计规范.md` 或相关任务文档中明确组件层级、状态变化和样式 Token。

### 阶段二：自我审查 (Self-Check)
作为独立开发者，您既是作者也是审核者。在编码前，请进行“冷思考”：
- **设计自洽性**：这一版数据库设计真的能支持未来的需求扩展吗？
- **复杂度控制**：我是不是在过度设计？有没有更简单的实现？
- **依赖检查**：引入这个新库真的有必要吗？

建议使用 **[RFC]** (Request for Comments) 的形式在 Issue 或文档中记录关键技术决策，作为“给未来自己的留言”。

### 阶段三：编码 (Implement)
编码即文档的延伸。
- **一致性**: 变量名直接复用文档定义，减少认知转换成本。
- **TODO 管理**: 将未完成的思绪用 `// TODO: ` 标记，避免遗忘。

### 阶段四：验收 (Verified)
- **Postman/Curl 测试**：保存测试用例，作为接口的“活文档”。
- **Golden Sample**：在文档中保留一份“完美”的 JSON 响应示例。

## 2. 文档质量红线 (Quality Gates)

任何“含糊其辞”的文档都是导致失控的源头。我们执行以下红线标准：

### 2.1 数据库文档红线
- ❌ 禁止：`user_id: 用户ID`
- ✅ 必须：`user_id: BIGINT, NOT NULL, FK -> sys_users.id, 索引: idx_conn_user`

### 2.2 接口文档红线
- ❌ 禁止：`Authorization: 需要登录`
- ✅ 必须：`Authorization: Bearer <JWT_TOKEN>`，并给出具体的 Curl 示例。
- ❌ 禁止：`data: 返回用户列表`
- ✅ 必须：给出完整的 JSON 结构体示例：
    ```json
    {
      "code": 0,
      "data": [
        { "id": 1, "username": "admin" }
      ]
    }
    ```

### 2.3 前端文档红线
- ✅ 必须：明确组件的 Props（类型、是否必填、默认值）和 Emits。
- ✅ 必须：明确组件依赖的 Store 状态。

## 3. 防失控检查清单 (Control Checklist)

每次提交代码前，请自检：

- [ ] **是否新增了配置项？** -> 更新 `docs/开发指南/环境搭建指南.md`。
- [ ] **是否修改了数据库？** -> 更新 `docs/数据库设计/数据库模型设计.md`。
- [ ] **是否引入了新依赖？** -> 检查 `go.mod` 或 `package.json` 并更新文档。
- [ ] **是否修改了 API？** -> 同步更新 Swagger 或 Markdown 文档。

## 4. 目录指引与维护责任人

| 文档目录 | 对应内容 | 维护时机 | 责任人 |
|----------|----------|----------|--------|
| `docs/架构设计/` | 系统全景、前后端架构 | 架构调整时 | 架构师 |
| `docs/数据库设计/` | 表结构、ER图、索引 | 建表/改表前 | 后端开发 |
| `docs/接口规范/` | API 定义、错误码 | 写接口代码前 | 后端开发 |
| `docs/界面设计/` | 样式 Token、组件规范 | 开发 UI 前 | 前端开发 |
| `docs/开发指南/` | 环境、Git流、编码规范 | 流程变更时 | 负责人 |
| `docs/部署运维/` | Docker 配置、发布脚本 | 上线发布前 | 运维/开发 |
