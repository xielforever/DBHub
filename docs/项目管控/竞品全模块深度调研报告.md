## 1. 调研对象与产品分层

数据库工具市场不是一个赛道，而是**四层产品栈**。DBHub 的菜单必须先回答"做哪几层"，再谈功能取舍。

| 层级 | 定位 | 代表产品 | 核心用户 |
| --- | --- | --- | --- |
| L1 SQL 客户端 | 连库、写 SQL、改数据、改表结构 | DBeaver、Navicat、DataGrip、Chat2DB（社区版） | 开发/DBA |
| L2 数据库 DevOps/管控平台 | 统一入口、变更工单、SQL 审核、权限/脱敏、审计、监控 | 阿里云 DMS、CloudQuery、Bytebase、NineData、Yearning/Archery/SQLE | 开发 + DBA + 安全/管理 |
| L3 数据治理/数据中台 | 数据资产目录、数据地图、血缘、标准、质量、分类分级 | 阿里 Dataphin、DataHub、OpenMetadata、Apache Atlas | 数据团队/治理委员会 |
| L4 BI/数据分析 | 查询结果图表化、报表/仪表盘、分享订阅、告警 | Redash、Metabase、Superset、DataEase、Chat2DB Pro 看板 | 分析师/业务 |

**关键判断**：用户提到的"数据资产/地图"属于 **L3**，"SQL 工作台查询报表展示"属于 **L4**，加上 DBHub 已在做的 L1/L2，目标形态实际是一个 **"L1+L2 为骨、L3/L4 选择性内嵌"的轻量一体化平台**——这正是阿里云 DMS、NineData、CloudQuery、Chat2DB Pro 的共同形态：**SQL 工作台是操作入口，数据资产是组织方式，报表是结果出口，工单/权限/审计是安全底线**。

## 2. 行业全量功能地图（13 个模块域）

下文每个模块统一按「模块价值 → 竞品基准做法 → 典型二级功能 → DBHub 现状 → 差距」展开。

### M1 首页 / 工作台（Workbench Home）

- **竞品做法**：
  - DMS 首页不是运营看板，而是**个人工作入口**：资产列表、最近访问的库表、我的权限/我的工单、我 Owner 的资产、待办审批 [2]。
  - Chat2DB/Navicat 为最近连接、最近查询脚本。
- **典型功能**：最近访问数据源/库表、最近 SQL、我的收藏、待办工单、个人快捷入口。
- **DBHub 现状**：`仪表盘`是**平台运营视角**（数据源数、查询量趋势、类型分布、库查询排行，ECharts 动态），无个人视角内容。
- **差距**：运营仪表盘本身是加分项（多数开源客户端没有），但**缺"我的工作台"个人视图**；两者可共存为仪表盘内的两个页签。

### M2 数据源 / 实例纳管（Connection & Instance）

- **竞品做法**：
  - DMS 称"实例管理"：录入实例、环境类型（dev/test/prod）、管控模式、实例 DBA/Owner、访问控制、变更窗口、字典同步、禁用/删除 [2]。
  - CloudQuery：连接池参数（最大连接数/等待/空闲超时）、连接管理员、测试环境标记、隐藏模式、连接概览（库/schema/表数量、SQL 执行总数图表）。
  - NineData：数据源分组、环境标签。
  - Chat2DB：数据库分组/文件夹。
- **典型功能**：环境/分组/标签、Owner、连接池设置、SSH/SSL、连通性探测、只读从库标记、纳管后元数据同步。
- **DBHub 现状**：连接 CRUD、连通测试（含中文失败提示）、SSH 隧道、颜色标签、团队共享、3 种库类型（mysql/postgres/redis）。
- **差距**：
  1. **无"环境"概念**（dev/test/staging/prod）——这是后续工单、审批、高危拦截、报表分组的基础字段；
  2. 无连接分组/文件夹（连接一多列表失控）；
  3. 无连接详情概览（库表数量、查询量、活跃用户，CloudQuery 的做法）；
  4. 不支持 MongoDB 等更多类型（竞品 18~60 种；短期可不做但要在菜单上留扩展位）。

### M3 SQL 工作台（SQL Console / IDE）—— 当前主战场

- **竞品做法（交集即行业基线）**：
  - 对象树：库 → schema → **表/视图/函数/存储过程/触发器/事件/索引/外键**，右键菜单（打开表、设计表、导数据、复制建表语句、ER 图）（DMS、DBeaver）[1][5]。
  - 编辑器：语法高亮、自动补全（表名/列名/关键字）、SQL 格式化、SQL 诊断/审核预检、执行计划（EXPLAIN）、多标签、**查询取消（KILL）**、SQL 片段/常用 SQL 收藏、运行 SQL 文件、多语句/批量执行、超级 SQL/管理员模式、SQL 分享 [1][2]。
  - 结果集：排序/筛选、**直接编辑结果集并提交**（DMS/CloudQuery/Chat2DB/NineData 均有）、复制为 INSERT/UPDATE、导出结果、多结果集页签、结果集图表（见 M5）。
  - 安全：单语句/多语句管控、最大行数、超时、全表扫描拦截、敏感列提示 [3]。
- **DBHub 现状**：数据源树（库→schema→表/视图 + 列结构 + Redis 键浏览）、多标签编辑器（纯 textarea）、结果/历史/Redis/消息 4 页签、预览分页（50 行/页）、单语句限制、1000 行截断、只读角色写拦截、查询历史。
- **差距（按竞品基线）**：
  | 能力 | 客户端基线 | DMS/CloudQuery | DBHub |
  | --- | --- | --- | --- |
  | Monaco 高亮/补全/错误定位 | 100% | 100% | ❌（规划中） |
  | SQL 格式化 / EXPLAIN / 查询取消 | 100% | 近 100% | ❌ |
  | 常用 SQL / 片段收藏 | 高频 | 常用 SQL 保存 | ❌（只有历史） |
  | 对象树函数/过程/触发器/索引节点 | 100% | 100% | ❌（仅表/视图/列） |
  | 结果集直接编辑提交 | 100% | 100% | ❌（规划的表数据管理） |
  | 复制为 INSERT/UPDATE、结果导出 | 100% | 100% | ❌ |
  | 右键表菜单（设计表/建表语句/ER） | 100% | 高频 | ❌ |
  | 跨库查询 | — | DMS/Chat2DB Pro | ❌（远期） |

### M4 表数据与表结构管理（Data & Schema DDL）

- **竞品做法**：
  - Chat2DB 社区版即有：**可视化编辑表（数据）+ 可视化编辑表结构（DDL）**；复制/清空表、修改查询结果 [4]。
  - DMS：表详情页可查看结构/索引、**可视化编辑表结构、管理表（增删列/索引）**、建表语句导出、表结构版本管理与版本 diff [2]。
  - DBeaver：模拟数据生成、ER 图、表结构比较。
  - NineData：数据归档/清理、测试数据生成、批量库表变更。
- **DBHub 现状**：只读预览 + 手写 SQL 执行（写角色可直接 DML/DDL）。
- **差距**：
  1. 表数据**可视化增删改**（行内编辑、勾选删除、新增行、改前预览 SQL、危险操作二次确认）——已在路线上；
  2. **表结构设计器**（新建表/加列/改类型/索引/外键的表单化操作 + 实时生成 DDL 预览 + 执行）；
  3. 建表语句（SHOW CREATE / pg_get_tabledef）查看与复制；
  4. 复制表/清空表/截断的右键动作（带确认与权限）；
  5. 测试数据生成、表结构对比（P2/P3）。

### M5 查询结果 → 图表 → 报表（用户点名的"报表展示"，L4 内嵌） 🔴

- **竞品做法（分三档深度）**：
  - **轻档（SQL 工具内嵌，DBHub 应对标的）**：Chat2DB Pro「智能看板/AI 数据图表」：SQL 结果一键转图表，支持柱/折线/饼等；CloudQuery 结果集直接出图；DMS SQL 窗口结果集可视化。
  - **中档（开源 BI：Redash/Metabase）**：Query（SQL/可视化提问）→ 图表（柱/折/饼/面积/漏斗/透视表/地图/数值卡）→ Dashboard 多图组合 → 分享链接/嵌入 → **基于结果集阈值的告警**（Redash Alerts）→ **仪表盘定时邮件/IM 订阅**（Metabase）[6][7]。
  - **重档（DataEase/Superset）**：40+ 图表、拖拽仪表板、数据集（SQL 数据集/多表关联数据集/Excel/API 数据集）、定时同步、大屏、下钻联动、行列级权限。
- **典型数据模型**：查询（SQL+数据源）→ 图表（维度/指标/图表类型/聚合方式）→ 仪表盘（布局）→ 分享（只读链接/嵌入 token）→ 订阅（定时执行+推送）→ 告警（阈值条件+通知渠道）。
- **DBHub 现状**：只有**平台运营**仪表盘（后端统计库）；**用户查询结果无法图表化、无法保存报表、无报表/仪表盘实体、无分享订阅**。
- **差距与最小可行方案（MVP）**：
  1. 结果区新增「图表」子页：把现有 ECharts 组件复用到查询结果，列映射维度/指标（聚合 sum/count/avg），柱/折/饼/数值卡 4 类起步；
  2. 「保存为报表」：新增报表实体（名称、数据源、库、SQL、图表配置），SQL 复用工作台查询通道（只读角色自然可用）；
  3. 「报表仪表盘」菜单：报表卡片组合成个人/共享看板；
  4. 报表分享：只读链接 + 可选访问令牌（三通道令牌底座已具备）；
  5. P2：定时刷新、邮件/Webhook/IM 订阅、阈值告警（与 M11 定时任务、通知铃铛联动——铃铛届时不再是假按钮）；
  6. 不做完整 BI（数据集建模、大屏、下钻），避免与定位失焦。

### M6 数据资产 / 数据地图（用户点名，L3 轻量内嵌） 🔴

- **竞品做法**：
  - **DMS 数据资产**：全局搜索（实例/库/表/工单）、**资产类目**（业务分类树）、资产列表、**表详情**（字段/索引/注释/敏感等级/Owner/建表语句导出/归档）、数据库 Owner、我的权限、表结构版本 [2]。
  - **DataHub/OpenMetadata/Atlas（数据地图标杆）**[8][9]：
    - 元数据采集（50+ 源连接器，定时拉取库/schema/表/列/统计信息）；
    - **资产目录 + 全文搜索**（表名/列名/注释/标签/负责人）；
    - **业务元数据**：业务描述/注释、术语表（Glossary，业务名词→技术字段）、标签（Tag）、分类分级（Classification）、Owner、重要性评分；
    - **技术元数据**：行数、存储大小、字段类型、分区、索引、数据剖析（Profiling：空值率/基数/分布/min/max）；
    - **血缘（Lineage）**：表级 + **字段级**血缘图、上游/下游影响分析；
    - 使用元数据：浏览热度、查询次数、Top 用户；
    - 资产收藏/关注/评论、数据问答（DataHub Chrome 体验）。
  - **Dataphin 资产全景**：全局/流动/结构化多视角可视化资产 [10]。
- **DBHub 现状**：元数据**按需实时查询、不落库**（databases/schemas/tables/columns 是透传接口）；无资产表、无搜索、无注释/Owner/标签、无血缘。
- **差距与务实路径**（DBHub 是在线库工具，不是数仓治理平台，做"轻量资产目录"即可对标 DMS 而非 DataHub）：
  1. **元数据采集落库**：新增资产元数据表（数据源→库→schema→表→列快照 + 行数估算 + 采集时间），连接创建后/定时/手动"同步字典"（DMS 术语）；
  2. **资产目录页（"数据资产/数据地图"菜单）**：按数据源→环境→业务分组的树/表混合导航 + **全局搜索**（直接消化当前假搜索框：搜数据源/表/列/报表/历史）；
  3. **资产详情页**：字段/类型/注释/索引/DDL/预览/行数、**人工标注**（业务负责人 Owner、业务说明、标签、分级：普通/敏感/机密）、收藏；
  4. **轻量血缘**：从查询历史的 SQL（以及未来报表 SQL）做 SQL 解析（如  `pg_query_go`/`vitess` 解析器），提取表级 SELECT→INSERT/CTAS 依赖与跨实例流向，画表级血缘图；字段级血缘、CDC 血缘、BI 血缘列为 P3（DataHub 级别）；
  5. 热度信息：直接用已有 `sys_query_history` 统计表/库查询热度与 Top 用户（成本极低，马上可做）；
  6. P3：术语表、数据剖析（空值率/基数）、分类分级自动识别。

### M7 数据集成 / 导入导出 / 迁移 / 对比

- **竞品做法**：
  - Chat2DB 社区版无、Local/Pro 有：数据导入导出（CSV/XLSX/SQL）、结构导入导出、数据迁移、结构同步 [4]。
  - DMS 数据方案：数据导入、数据导出（库/表/结构/查询结果，带审批与行数上限）、数据库克隆、数据归档 [11]。
  - NineData 四大模块含**数据复制（结构/全量/增量 CDC）、数据对比（结构+数据对比并生成修复 SQL）、备份恢复** [12]。
  - DBeaver：数据传输向导。
- **DBHub 现状**：无。
- **差距/分级**：
  - P1：**查询结果导出（CSV/Excel/SQL INSERT）** + 表数据导入（CSV）——工作台刚需；
  - P2：整库结构导出（建表语句打包）；
  - P3：结构同步/数据对比、CDC 迁移、备份恢复（NineData 级别，工作量大，除非定位需要否则不做）。

### M8 变更管控（工单 · 审批 · SQL 审核 · 回滚）—— L2 分水岭

- **竞品做法**：
  - Bytebase：工单（Issue）流水线、环境（dev→prod）、200+ 内置 SQL 审核规则、风险分级、审批流、GitOps、发布编排 [13]。
  - Archery/Yearning/SQLE：DDL/DML 工单、规则引擎（40~700 条）、可视化审批流、定时上线、Online DDL、**执行前备份、自动生成回滚语句**、钉钉/飞书/企微/邮件通知 [14][15]。
  - DMS：普通/无锁数据变更、结构变更工单、预检查、审批、执行（逐条暂停/自动）、**数据追踪（binlog 解析生成回滚脚本）**、变更窗口 [11][16]。
  - DBHub 同类替代现状：只读角色拦截 + 单语句限制；**写角色可直接执行任意 DML/DDL，无预检/审批/备份/回滚**。
- **差距**：工单实体与状态机、SQL 审核规则引擎（无 WHERE 的 UPDATE/DELETE、SELECT *、全表扫描、影响行数预估、NOT NULL 缺省、索引建议）、审批流配置、定时执行、执行备份与回滚脚本、通知中心。
- **务实分级**：P2 先做**工作台 SQL 预检（不阻断，出风险报告）+ 高危语句二次确认**；P3 再做工单审批流（这是"管控平台"身份的门票，投入大）。

### M9 数据安全（细粒度权限 · 脱敏 · 分级 · 访问控制）

- **竞品做法**：
  - DMS：实例/库/表/列/行五级 × 查询/变更/导出三动作的权限申请工单、到期回收、敏感列管理、行级管控、数据水印、IP 白名单、安全访问代理、超级 SQL [16][17]。
  - CloudQuery：表级 DML/DQL/DDL 授权、结果集/导出/右键菜单逐项授权、项目组批量授权、**动态脱敏（内置+自定义算法）、行过滤（按用户属性）、访问时段控制、防复制/防导出、高危阻断、双因素认证** [18]。
  - Dataphin：分类分级识别规则 + 脱敏算法 + 查询脱敏配置。
- **DBHub 现状**：3 粗角色（admin/developer/readonly）、数据源全员共享、AES-GCM 凭据加密、PBKDF2、三通道令牌、只读写拦截、审计。
- **差距**：库/表/列级授权与申请流程、敏感字段识别与动态脱敏（结果集渲染层脱敏，和资产分级是一套数据）、行级过滤、访问时段/IP 白名单、水印、2FA/SSO。
- **分级**：P2 敏感列标记（M6 资产页）+ 结果集动态脱敏规则（投入产出比最高）；P3 细粒度授权工单、SSO/2FA。

### M10 监控与运维诊断（目标库可观测）

- **竞品做法**：
  - DMS 接 DAS：一键诊断、实时会话（PROCESSLIST/KILL）、慢查询分析、空间/容量分析、性能趋势。
  - CloudQuery：服务器负载、读写状态、慢查询监控、连接用户数、SQL 执行次数/平均时长图表 [18]。
  - Archery：慢日志管理、会话管理。
  - NineData：慢查询分析。
- **DBHub 现状**：`redis/overview`（Redis 信息）；PG/MySQL 无任何目标库监控；仪表盘只统计平台自身查询（**注意：平台查询指标 ≠ 数据库监控，不要混为一谈**）。
- **差距/分级**：P2 实例概览（版本/启动时间/连接数/库表数/容量）、会话列表与 KILL、慢查询 Top N（PG pg_stat_statements / MySQL slow log）；P3 诊断报告、告警。

### M11 定时任务 / 调度

- **竞品做法**：DMS「任务管理」新建定时 SQL；NineData 定时 SQL 任务；Archery 定时任务；Dataphin/DolphinScheduler 为大数据调度（依赖 DAG，非本产品范畴）。
- **DBHub 现状**：无。
- **差距/分级**：P2 定时 SQL（cron + SQL + 数据源，结果留存/导出/推送）；这同时是报表订阅、阈值告警的技术底座。

### M12 数据服务（Data API）

- **竞品做法**：Dataphin 数据服务：把 SQL/表快速发布为 REST API，API 鉴权、调用统计、限流、运维监控 [10]；DMS 也有数据服务最小粒度输出。
- **DBHub 现状**：无。
- **差距/分级**：P3：将保存的报表/查询一键发布为只读 API（平台已有令牌体系，鉴权天然可复用）。

### M13 组织、审计、通知、设置（平台底座）

- **竞品做法**：
  - 审计：DMS 操作审计（查询/变更/登录/导出全记录，3 年留存）；CloudQuery 审计**分析图表**（操作类型次数、平均耗时、失败高亮、脆弱环节预警）。
  - 通知：DMS 通知管理（工单/任务状态、邮件/钉钉）；这是铃铛按钮的归宿。
  - 组织：部门/项目组、SSO。
- **DBHub 现状**：用户与 RBAC（admin 管理）、操作审计（分区表、筛选）、查询历史、改密、安全机制只读说明；通知无、系统参数不可配、**全局搜索框与铃铛为假入口**、设置入口重复（侧栏底部 + 头像下拉）。
- **差距**：
  1. 立即修：假搜索（由 M6 全局搜索消化）、假铃铛（M8/M11 通知中心消化，在那之前隐藏）、设置去重（个人资料/改密进头像下拉，系统设置仅 admin 且承载可配置参数：令牌时长/查询行数上限/超时）；
  2. P2：审计分析图表（复用 ECharts）、通知中心；
  3. P3：组织/项目组、SSO/2FA。

### M14 AI 能力（横切）

- **竞品做法**：Chat2DB：NL2SQL、SQL 解释、优化建议、一键纠错、AI 建表、AI 图表/报表、Chat2Excel、多轮对话（上下文带 schema）[4]；DMS SQL 诊断；Bytebase AI 审核。
- **DBHub 现状**：AI 助手抽屉占位。
- **差距/分级**：P1 随 Monaco 落地：NL2SQL（注入当前库表 schema 上下文）、解释 SQL、优化/格式化建议；P2 一键纠错（执行报错带错误回传）、AI 图表配置推荐；P3 AI 建表/自然语言数据问答。

## 4. 目标信息架构（菜单蓝图）

原则：一级菜单随阶段渐进，**每个菜单项必须对应真实路由**（延续既有红线）；功能先在页签/抽屉内聚，不够再升级一级菜单。

### 阶段一（P0 闭环 + P1，建议未来 2~3 个迭代）

```
概览
  └─ 仪表盘（保留运营视角；增加"我的"区：最近访问库表/最近 SQL）
数据
  ├─ 数据资产 ★新（数据地图：资产目录 + 全局搜索落地 + 表详情：字段/索引/DDL/注释/Owner/标签/热度）
  ├─ 数据源管理（现有；加环境与分组字段）
  ├─ SQL 工作台（Monaco；结果集页签：数据 / 图表★ / 历史 / Redis / 消息）
  └─ 报表中心 ★新（保存的报表 + 我的仪表盘；从工作台结果"另存为报表"进入）
安全
  ├─ 用户与权限（admin）
  └─ 操作审计（admin）
[底部] 个人设置（头像下拉：资料/改密/外观）；系统设置仅 admin（令牌时长/行数上限等可配项）
```

要点：用户点名的两个模块在阶段一就出现——**数据资产**（M6 轻量版）与**报表展示**（M5 轻档，工作台结果一键转图表 + 报表中心）。

### 阶段二（P2，平台化）

```
数据
  ├─ 数据资产
  ├─ 数据源管理（连接概览、环境、分组）
  ├─ SQL 工作台
  ├─ 报表中心（分享链接）
  └─ 数据运维 ★新（实例概览/会话管理/慢查询）            ← M10
变更（新分组）
  └─ 变更工单 ★新（先 SQL 预检+高危确认，后审批流）       ← M8
安全
  ├─ 用户与权限
  ├─ 敏感数据 ★新（分级与动态脱敏规则）                  ← M9
  └─ 操作审计（增加审计分析图表）
任务
  └─ 定时任务 ★新（定时 SQL；通知铃铛落地为通知中心）     ← M11/M13
```

### 阶段三（P3，按定位选做）

```
数据
  └─ 数据集成 ★新（导入导出增强、结构同步/数据对比/迁移）  ← M7
  └─ 数据服务 ★新（SQL 发布 API）                        ← M12
治理
  └─ 数据血缘 ★新（字段级）/ 术语表 / 质量规则           ← M6 深化、数据质量
安全（深化）
  └─ 细粒度授权 / 审计水印 / SSO / 2FA
变更（深化）
  └─ 审批流编排 / 回滚备份 / GitOps
```

> 命名建议：左侧分组从「概览/数据/安全」演进为「概览 / 数据 / 变更 / 安全 / 任务」；"数据源管理"与"数据资产"的边界要在 UI 上讲清楚——**数据源管理 = 连接配置与凭据（IT 视角）；数据资产 = 纳管后的库表目录、注释、Owner、血缘（业务视角）**，这也是 DMS 的划分方式。

## 5. 与 DBHub 既有路线的衔接与取舍建议

1. **既定路线（工作台闭环 → 表数据管理 → Monaco/AI）不动摇**，它正好覆盖 P0；但顺序建议微调为：
   表数据管理（M4）与 Monaco（M3）并行 → **立即插入 M5 轻图表 + M6 资产目录**（用户本轮点名，且两者都大量复用已有资产：ECharts、元数据接口、查询历史、RBAC）→ 再做导入导出与表结构设计器。
2. **M5/M6 是性价比最高的两块新增**：
   - 报表图表：ECharts 已在前端使用，后端只需新增报表 CRUD 表与"按报表配置执行查询"接口（复用 query/execute 通道）；
   - 数据地图：元数据采集是一次性的库表快照落库，热度统计直接 GROUP BY 现有 `sys_query_history`；搜索也顺手消化假搜索框。
3. **不要陷入"做全 DataPhin/DataHub"的陷阱**：数据质量六性、术语表、字段级血缘、数据剖析、数据服务 API 市场是数百人年的产品；DBHub 做到 **DMS 级"资产目录 + 表详情 + 表级血缘"** 即与自身定位匹配。
4. **工单审批（M8）是定位分水岭**，建议明确：在用户规模/合规需求出现前，用"SQL 预检 + 高危确认 + 全量审计 + 只读角色"作为轻量替代；一旦做工单，环境（dev/prod）、审批流、通知、回滚要成套交付，不能半成品。
5. **三个假/重入口属 UX 红线，与排期无关，建议在下一迭代随功能落地（搜索→资产页；铃铛→通知中心；设置去重→即改）**。
