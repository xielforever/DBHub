# 部署运维指南 (Deployment)

本文档介绍如何将 DBHub 部署到生产环境，**与仓库根 `docker-compose.yaml` / `frontend|backend/Dockerfile` 保持一致**（文档即契约）。

## 1. 部署架构

```mermaid
graph LR
    User --> Nginx[Nginx 负载均衡/SSL]
    Nginx --> Frontend[前端静态资源 nginx]
    Nginx --> Backend[后端 API 服务 Go]
    Backend --> DB[(PostgreSQL 16 元数据库)]
    Backend --> Redis[(Redis 7 缓存)]
```

- 前端：`node:24` 构建 → `nginx:1.27-alpine` 运行时，`dist` 静态资源 + `/api/` 反代至后端
- 后端：`golang:1.25.5-alpine3.23` 构建 → `alpine:3.20` 运行时，静态编译 `CGO_ENABLED=0`，内置 `internal/db/migrations` 自动迁移
- 基础设施：`postgres:16-alpine` / `redis:7-alpine`，healthcheck 就绪后后端才启动

## 2. Docker Compose 部署（开发与生产共用同一编排，按环境区分）

### 2.1 仓库现状（以 `docker-compose.yaml` 为准）

```yaml
services:
  postgres:
    image: ${POSTGRES_IMAGE_VERSION} # postgres:16-alpine
    ports: ["${POSTGRES_PORT}:5432"]
    healthcheck: pg_isready
  redis:
    image: ${REDIS_IMAGE_VERSION}    # redis:7-alpine
    healthcheck: redis-cli ping
  backend:
    build: { context: ./backend, dockerfile: dev.Dockerfile } # 开发：air 热重载
    # 生产：改用 Dockerfile（多阶段静态编译）
    environment:
      - DATABASE_URL=postgres://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB}?sslmode=disable
      - REDIS_URL=redis://redis:6379/0
  frontend:
    build: { context: ./frontend, dockerfile: dev.Dockerfile } # 开发：vite HMR
    # 生产：改用 Dockerfile（node 构建 → nginx）
```

开发环境直接 `docker compose up -d`（含源码挂载、HMR、air）；生产环境将 `dockerfile` 字段改为 `Dockerfile` 或使用独立 `docker-compose.prod.yaml`。

### 2.2 准备工作

- Docker Engine ≥ v20.10，Compose v2
- 准备 `.env`：仓库已提交开发样例，仅含非敏感默认值；**生产必须通过密钥管理系统注入** `APP_SECRET_KEY`（≥32 字节）、`POSTGRES_PASSWORD`、`APP_ADMIN_PASSWORD`

### 2.3 开发一键启动

```bash
docker compose up -d
docker compose ps                    # 4 容器 healthy
curl http://localhost:8080/api/health # {"status":"ok","version":"mock-0.24.0"...}
open http://localhost:5173           # 前端 Vite，带全局搜索、暗色玻璃
```

### 2.4 生产构建与发布

```bash
# 构建（CI 中）
docker build -t my-registry/dbhub-frontend:$(git rev-parse --short HEAD) -f frontend/Dockerfile frontend
docker build -t my-registry/dbhub-backend:$(git rev-parse --short HEAD)  -f backend/Dockerfile  backend

# 生产编排示例 docker-compose.prod.yaml（精简）
services:
  frontend:
    image: my-registry/dbhub-frontend:latest
    ports: ["80:80"]
    depends_on: [backend]
  backend:
    image: my-registry/dbhub-backend:latest
    ports: ["8080:8080"]
    environment:
      - APP_ENV=production
      - PORT=8080
      - APP_SECRET_KEY=${APP_SECRET_KEY}
      - DATABASE_URL=postgres://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB}?sslmode=disable
      - REDIS_URL=redis://redis:6379/0
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_healthy }
  postgres: { image: postgres:16-alpine, volumes: [pgdata:/var/lib/postgresql/data] }
  redis: { image: redis:7-alpine }
```

启动：

```bash
export APP_SECRET_KEY=$(openssl rand -hex 32)
export POSTGRES_PASSWORD=... 
docker compose -f docker-compose.prod.yaml up -d
```

### 2.5 环境变量清单（与 `.env` / `backend/internal/config` 一致）

| 变量 | 说明 | 默认（开发） |
| --- | --- | --- |
| `FRONTEND_IMAGE_VERSION` | 前端构建镜像 | `node:24.12.0-bullseye` |
| `BACKEND_IMAGE_VERSION` | 后端构建镜像 | `golang:1.25.5-alpine3.23` |
| `POSTGRES_IMAGE_VERSION` | 元数据库镜像 | `postgres:16-alpine` |
| `REDIS_IMAGE_VERSION` | 缓存镜像 | `redis:7-alpine` |
| `APP_SECRET_KEY` | JWT/加密主密钥 | `dev-only...32b` |
| `APP_ADMIN_USERNAME/PASSWORD` | 引导管理员 | `admin/admin123` |
| `JWT_ACCESS_TTL_MINUTES` | Access TTL | `15` |
| `JWT_REFRESH_TTL_HOURS` | Refresh TTL | `168` |
| `DATABASE_URL` | 容器内 DSN | `postgres://dbhub:...@postgres:5432/dbhub_meta?sslmode=disable` |
| `VITE_API_PROXY_TARGET` | Vite 代理 | `http://backend:8080` |

## 3. 运维监控

### 3.1 日志查看

```bash
docker compose logs -f --tail=100 backend
docker compose logs -f frontend
curl http://localhost:8080/api/health | jq
```

### 3.2 备份策略

- **数据库备份**: 每天定时 `pg_dumpall`
    ```bash
    docker exec dbhub-postgres pg_dumpall -c -U dbhub > dump_$(date +%Y-%m-%d).sql
    ```
- **前端静态资源**: `dist/` 已由多阶段构建固化，无需备份

### 3.3 升级流程

1. `docker compose pull` 或重新 `docker build`
2. `docker compose up -d --remove-orphans`
3. 后端自动执行 `internal/db/migrations`（`schema_migrations` 记录幂等）

### 3.4 无 Docker 受限环境（CI 验证）

见 `docs/开发指南/环境搭建指南.md §6` PGlite 线协议服务模拟 PG，限单连接 `META_DB_MAX_CONNS=1`。
