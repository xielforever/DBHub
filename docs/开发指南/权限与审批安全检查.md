# 权限、审批与删除安全检查

检查日期：2026-10-18。检查基线：`4752d0e`。范围为应用代码与隔离环境，不代表对实际生产网络、部署密钥或商业 GaussDB 实例的渗透测试。

## 检查范围

- 身份、工作空间成员角色和成员版本，平台管理员与工作空间管理员的边界。
- 个人连接、数据源目录、驱动、SSH 隧道、代理、个人历史和旧分享接口。
- 正式报表与仪表盘的送审、验证、决策、发布、下线、回滚、受众组与执行账号。
- 工单、导出审批、SQL 事务、Redis 命令、后台任务的归属、状态迁移与撤权。
- 删除引用关系、并发审批、Cookie 认证和出站目标白名单。

路由梳理包含 218 处字面量路由声明，其中 126 处为修改请求；循环注册的命令及工作空间前缀入口另行沿调用链检查。此数字用于说明入口梳理范围，不等于每个接口均经过独立渗透测试。

## 已确认并修复的问题

P1 表示可能绕过审批、身份或执行边界；P2 表示对象归属、可用性或误操作保护缺失；P3 表示影响有限的元数据写入越权。

| 编号 | 级别 | 原有问题 | 修复后的规则与验证 |
| --- | --- | --- | --- |
| S01 | P1 | 正式报表通过普通草稿送审，可绕过专用受众变更的新增受益人检查 | 验证、验证记录入库、审批及首次发布均检查审阅人是否新增受益；下线后仍比较最近发布的受众。覆盖直接授权与组成员变化，保留独立审批和历史恢复正向用例 |
| S02 | P1 | 管理员可审批自己提交的变更工单 | 仓储原子更新要求当前管理员、真实操作者及申请人不同；并发决定只有一次成功；执行仍需已批准状态 |
| S03 | P2 | 管理员可批准自己的导出申请 | 独立管理员审批，禁止覆盖已决定状态；下载仍限申请人及其当前连接授权。历史自批的导出恢复待审 |
| S04 | P1 | 工单只保存可修改的个人连接 ID，批准后可更换目标修订再执行 | 提交时冻结目标修订与数据库；审批、领取执行及发 SQL 前校验；执行者使用自己的同修订凭据，禁止借用申请人凭据 |
| S05 | P1 | Redis 建立会话后撤销数据源权限，仍可派发删除命令 | 在每次读取、扫描、概览及修改命令前重查当前成员、源授权、配置与驱动；真实 Redis 撤权用例确认原键保留 |
| S06 | P1 | 管理员请求暂停期间被撤权并恢复后，维护连接可继续重置其他人的密码 | 维护事务锁定并核对捕获的成员版本；旧请求失败，新请求按当前授权正常执行 |
| S07 | P1 | Cookie 兜底认证的修改请求缺少 CSRF 防护 | Cookie 修改请求必须带 `X-DBHub-CSRF: 1`，前端自动携带；跨源浏览器必须通过生产 CORS 白名单预检；普通 Bearer API 调用不增加要求 |
| S08 | P1 | SSH 连通性测试绕过平台目标白名单 | 测试在拨号前执行相同目标校验；本地 TCP 监听用例证明白名单外地址没有收到连接 |
| S09 | P1 | 删除隧道/代理会静默转为直连；删除发布者连接会级联清除查询策略，使他人结果范围扩大 | 网络引用外键改为 `RESTRICT`；承载策略的连接在删除或切换目标修订前锁定父记录并检查依赖，覆盖并发创建策略，返回 409；显式处理策略后可操作。真实复现确认删除前只读账号返回 1 行，原删除路径会扩大到 2 行 |
| S10 | P2 | 管理员可以删除他人的个人查询历史，清空路径还尝试截断共享表 | 单条删除及清空始终限当前用户，工作空间 RLS 继续生效；清空自己不影响其他人的记录 |
| S11 | P2 | 已停用的旧分享接口仍允许查询或撤销其他人的记录 | 列表、撤销与删除均限制创建者；无权或不存在统一 404；公开读取及新建公开分享保持停用 |
| S12 | P1 | 报表下线后，可自行加入其历史受众组，再恢复发布取得数据权限 | 用户组防自授权检查包含历史发布；已有组的版本与成员检查在同一行锁内，发布与组变更串行校验 |
| S13 | P3 | 旧仪表盘收藏可修改不可见的私有对象，仓储修改与删除缺少归属条件 | 收藏要求当前可见且只修改本人的收藏；仓储修改、删除也校验归属，管理员仅可维护可见的工作空间共享旧定义 |
| S14 | P2 | 概览排行的自定义提示将连接名直接作为 HTML，恶意标签可插入 DOM | 此提示改为 Canvas 富文本绘制，连接名不进入 HTML 解释；真实生产浏览器验证恶意 `img` 标签不再生成元素。此处复现的是 HTML 注入，未将其夸大为已绕过生产 CSP 执行脚本 |

前端同时隐藏自己的工单审批按钮，明确等待其他管理员。管理员待审列表展示完整 SQL、冻结的源修订与数据库，批准前需确认已核对目标和影响范围，避免仅凭截断 SQL 作决定。

## 升级影响

新增 `0037_security_execution_boundaries.sql`，迁移在后端启动时由既有迁移锁串行执行。

1. 升级前尚未执行的 `pending`、`approved` 工单缺少可靠的原始目标快照，保留记录并转为拒绝，附重新提交原因。不能用升级时的最新目标伪造原始审批目标。
2. `executing`、`executed`、`failed` 历史记录保留状态；执行中或结果不确定的旧记录仍需核查目标数据库，不能自动重试。
3. 历史自行批准的导出恢复 `pending`，由其他管理员重新审批；正常独立审批保持有效。
4. SSH 隧道及代理若仍被连接引用，删除返回 409。先在个人连接中显式解绑，再删除配置。
   承载查询安全策略的连接也返回 409，需管理员显式处理策略，避免删除个人连接时意外解除其他人的限制。
5. 直接依赖 Cookie 调用修改接口的自定义客户端需增加 `X-DBHub-CSRF: 1`。官方前端已添加；Header 令牌调用方式兼容。

迁移回归从原 36 份迁移构造旧库，验证上述历史保留、审批失效、四条网络引用外键及重复执行幂等性。新建库也执行完整迁移。

## 仍需在生产环境验证的边界

- 生产 HTTPS、CORS 精确域名、受信代理、数据库与 Redis 网络隔离、目标白名单和最小权限账号仍按部署验收执行。代码回归无法证明真实环境已正确配置。
- 业务目标白名单不应包含元数据库、系统 Redis 或 JDBC 管理地址。业务 Redis 应使用独立实例或受限 ACL 账号；不同逻辑库编号不能替代账号及网络隔离。开发环境的宽松 CORS 和示例网络不作为对外部署配置。
- `govulncheck` 已安装，但本环境访问 `vuln.go.dev` 漏洞库被网络策略拒绝，因此 Go 依赖漏洞扫描未完成。前端 `npm audit` 的零漏洞结果不能替代 Go、JDBC、JRE 和容器系统包扫描。
- 平台管理员、身份管理和用户组管理属于受信控制面。不同账号不等于不同自然人；防自批不能替代组织上的管理员分权、账号交付和身份审查。
- 已送往外部数据库的操作可能在撤权后完成；校验在派发前执行，无法对另一数据库提供跨库原子撤权。结果不确定时不自动重试。
- 有权限的用户仍可执行合法但破坏性较大的 SQL，或删除其本人无引用的资源。基础条件检查和确认框不能保证业务正确性；恢复能力依赖正式备份与业务操作规范。
- 使用者持有自己的数据库账号，可使用个人连接或其他数据库客户端访问数据库已授予的范围。敏感行、列的最终授权应落实到数据库账号、视图及数据库权限；工作台查询策略不能替代这一边界。
- 生产旧库升级/恢复、真实业务负载、业务 UAT、外部告警送达及真实 Kubernetes 集群验收仍需完成。本次检查不作“所有安全风险已清零”的结论。
