# 数据源检查与采集可靠性

本轮修复数据源采集失败误清理、同源并发采集、编辑表单空口令测试和检查结果刷新后丢失的问题。功能仍由用户手动触发。

## 元数据采集

`POST /api/v1/assets/sync` 对每个 MySQL/PostgreSQL 数据源执行一轮完整采集，Redis 返回 `skipped`。同一个数据源涉及的所有库、Schema 和对象都成功读取后，快照更新与过期对象清理才在元数据库的一个事务中提交。

- 任一库连接失败、Schema 读取失败、快照写入失败、请求取消或超时：整轮不发布，该数据源原快照保持不变，返回 `status=failed`，发布表/视图数为 0。
- 成功时返回 `status=succeeded`；旧对象按连接、数据库、Schema、表名匹配清理。不同 Schema 的同名表互不混淆；完整成功但为空的清单可以清空旧快照。
- PostgreSQL 事务级 advisory lock 按元数据库 Schema 和数据源 ID 隔离。同源互斥跨处理器、跨后端实例生效；事务结束或连接关闭时释放，不依赖某个进程的内存锁。
- 单源重复采集返回 HTTP 409；全量采集遇到正在采集的源时，该项返回 `busy`，继续处理其他源。
- 采集开始与发布前检查连接配置的 `updated_at`；期间配置变更时拒绝发布旧结果。采集事务使用同一个池连接，避免持锁后再申请连接造成连接池死锁。
- 整体请求仍为串行采集、4 分钟上限。只有空请求体或 `{}` 表示全量；显式 `connection_id` 必须为正整数，0、负数、null、未知字段和尾随 JSON 均拒绝。

以上保证元数据库里的字典按轮次发布，不代表目标数据库的多个查询处于同一个 DDL 快照。源端结构在采集中改变并引发读取错误时，本轮失败，修复后可重新采集。新快照发布期间读者继续看到旧的已提交数据。多源全量请求按源分别提交，一个源失败不撤回其他已成功的源。

## 编辑连接和口令

`POST /api/v1/connections/{id}/test` 的空请求体测试已保存配置。有完整连接配置请求体时测试编辑草稿，限管理员或该连接的 developer 创建者；草稿不保存配置，也不替换已保存配置的最近检查。

编辑草稿的口令留空时，服务端可以复用已保存口令。数据库类型、主机、端口、账号、TLS 模式或代理/SSH 隧道改变后，需要重新输入口令，避免将原口令隐式发送到新地址。已保存的配置与口令通过单条 SQL 读取，并发编辑不能混用旧地址和新口令。响应和持久化检查都不包含口令。

保存编辑表单时空口令仍表示保留原口令。未保存的新建连接沿用 `/connections/test`，不复用其他连接的口令。

## 最近一次检查

迁移 `0020_connection_checks.sql` 增加 `sys_connection_checks`。每个连接最多保留一条最近检查，包含成功/失败、检查开始和结束时间、耗时、版本兼容信息或清洗后的错误。列表和详情的可选 `last_check` 用于页面刷新后恢复展示。

检查与配置 `updated_at` 绑定。配置修改后旧记录立即从读取结果中隐藏；旧配置的迟到结果不能重新标记新配置，较早开始的慢检查也不能覆盖较新的检查。连接删除时检查记录级联删除。该表独立于连接配置，因此写入检查不会改变配置版本或使正在采集的配置无故失效。

连接测试失败保持 HTTP 400，响应 `data` 同时返回检查结果；`recorded=true` 表示检查已保存。草稿测试或被配置变更/更新检查淘汰的结果为 `recorded=false`。卡片显示时间和耗时，失败显示错误；最近检查不能当作持续在线状态，也不是完整检查历史。

## 验证

在 Docker 中运行：

```sh
./scripts/cloud/dev.sh exec -T backend go test -race -count=1 ./internal/server -run '^(TestDatasourceReliability|TestMetadataSyncReliability)$'
./scripts/cloud/dev.sh exec -T backend go test -race -p=4 ./...
./scripts/cloud/dev.sh exec -T backend go vet -p=4 ./...
./scripts/cloud/dev.sh exec -T frontend sh -ec 'npm run test:query; npm run build'
DBHUB_BROWSER_TEST_SCRIPT=/app/scripts/cloud/version_browser_test.py ./scripts/cloud/browser.sh
```

新增真实数据库回归覆盖 10 个场景：最近检查与草稿、口令目标保护、检查结果乱序、配置/口令并发一致性、配置修改与失败持久化、快照原子提交及同名对象、跨处理器互斥与配置变更、同步输入防呆、部分 Schema 超时保留旧快照，以及跨 HTTP 处理器并发/取消后释放锁。失败发布通过非法 JSON 快照触发真实数据库事务错误，读取失败通过独立目标账号的 statement timeout 与表锁触发，不向真实业务库注入故障。

浏览器验证真实三类数据源、刷新后恢复检查、编辑时复用口令、目标更改提示、旧响应失效、配置修改后旧检查失效、失败检查刷新恢复，以及空口令保存后恢复连接。版本警示中的 MariaDB 仍为界面契约样例，不计入数据库兼容实测。
