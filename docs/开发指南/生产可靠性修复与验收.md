DOMPurify 覆盖仅作用于 Monaco，用于解除编辑器固定旧补丁版本的告警；后续升级编辑器时重新评估该覆盖。包审计清零反映本次漏洞库状态；本轮没有完成 Go/JDBC/操作系统镜像全量漏洞扫描。

## 运行与恢复

`scripts/cloud/production_acceptance.py` 使用独立生产镜像、PostgreSQL 和持久化 Redis。元数据库与业务库分开，创建三张正式报表、一个正式看板、用户组受众和只读执行账号。没有个人连接的查看者读取三仓库数据，隐藏仓库由目标视图排除。

Redis 故障时验证就绪 503、存活 200、鉴权 503 和原会话恢复；PostgreSQL 故障时就绪及身份查询均为 503。数据库故障期间持久保存审计事件，替换后端后补写；同一事件随审计卷再恢复一次，数据库只保留一个事件。

恢复使用[备份脚本](../../scripts/ops/backup-metadata.sh)、[恢复脚本](../../scripts/ops/restore-metadata.sh)和[对账 SQL](../../scripts/ops/verify-metadata.sql)。拒绝覆盖已有备份，拒绝向已有用户表、视图或序列的数据库恢复。新库在应用启动前对账，然后以原应用密钥和会话验证账号解密、组授权、发布、真实查询及无权用户拒绝。业务目标库独立存在，元库恢复不代替业务数据恢复。

浏览器在严格 CSP 下执行 Monaco 查询，验证刷新暂时失败的恢复。原有仪表盘 13 项浏览器流程用实际候选镜像重跑，覆盖图表、手机、补权和审批差异。测试通过自动化协议轮询页面状态，兼容禁用页面动态求值的策略。

原始证据仅保存计数、摘要、时间和无敏感内容的结论；临时配置、会话、容器和卷在 `finally` 清理，不向开发工作空间保留演示看板。

## 持续负载与范围

发布演练使用实际时钟运行 1800 秒、4 个客户端，混合正式报表、三卡看板和个人数据工作台读取。校验每次金额/行数，按预期 SQL 数量对账持久回执，确认租约清空并采样内存及元库活动连接。看板轮次包含三次 SQL，延迟按完整业务轮次统计；错误和回执差异须为 0。

负载使用合成三仓库视图、单实例后端 2 CPU/512 MiB。4 个客户端共用开发者和查看者两个测试身份；每个看板轮次串行执行三张卡片，轮次之间保留 0.5 秒间隔，用于验证持续运行、会话续期和计数一致性。浏览器同时查询两张卡片的行为由独立回归覆盖。真实业务 SQL、生产规模、并发和目标基础设施仍需容量验收。普通工作台事务为进程内状态，多实例路由、配额及故障切换单独验证。

本次实测持续 1800.04 秒：正式报表 3,620 轮、三卡看板 3,634 轮、工作台 3,625 轮，共 10,879 轮、18,147 次 SQL 执行，错误为 0，持久回执完全一致，查询租约归零。完整业务轮次平均 161.71 毫秒、P95 为 476.35 毫秒；61 次内存采样的峰值为 38.95 MiB，元库活动连接采样最多为 3（含采样查询）。两个身份各完成两次访问令牌续期，4 次刷新均返回 200。临时容器、网络、卷及凭据文件已清理，Cloud 的 6 个开发服务保留。

## 复现

```sh
./scripts/cloud/dev.sh exec -T backend go test ./... -count=1
./scripts/cloud/dev.sh exec -T backend go test -race ./... -count=1
./scripts/cloud/dev.sh exec -T backend go vet ./...
./scripts/cloud/dev.sh exec -T frontend sh -ec 'npm ci --no-audit --no-fund; npm audit --audit-level=low; npm run test:query; npm run test:report; npm run test:dashboard; npm run build'
docker build -t dbhub-backend:production-fix-20261018 -f backend/Dockerfile backend
docker build --secret id=proxy_ca,src="${CODEX_PROXY_CERT:-/etc/ssl/certs/ca-certificates.crt}" -t dbhub-frontend:production-fix-20261018 -f frontend/Dockerfile frontend
export DBHUB_DASHBOARD_BACKEND_IMAGE=dbhub-backend:production-fix-20261018
export DBHUB_DASHBOARD_FRONTEND_IMAGE=dbhub-frontend:production-fix-20261018
DBHUB_DASHBOARD_USE_IMAGE=1 python3 scripts/cloud/dashboard_acceptance.py
python3 scripts/cloud/production_acceptance.py --duration 1800 --clients 4
```

宿主需要 Python Playwright 1.62.0 和 Chromium。`DBHUB_CHROMIUM_PATH` 可指定浏览器，系统路径不存在时使用 Playwright 自带版本。`--duration 0` 执行故障、恢复、限流和浏览器流程，并记录未执行持续负载。结果见[机器验收记录](../acceptance/production-readiness-fix-2026-10-18.json)，原始记录保存在 Cloud 私有目录。
