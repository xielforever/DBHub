# 编码规范 (Coding Standards)

为了保证 DBHub 项目代码的可维护性和一致性，所有贡献者必须遵循以下编码规范。

## 1. 通用原则

- **KISS 原则**: Keep It Simple, Stupid。避免过度设计。
- **DRY 原则**: Don't Repeat Yourself。提取公共逻辑。
- **代码注释**: 复杂的业务逻辑必须添加注释。导出的函数/结构体必须遵循 Go Doc 规范。
- **英文命名**: 变量、函数、文件名必须使用英文，严禁拼音。

## 2. 前端规范 (Vue/TS)

### 2.1 命名风格
- **文件/目录**: 使用 `kebab-case` (e.g., `user-profile.vue`, `data-table/`).
- **组件名**: 使用 `PascalCase` (e.g., `UserProfile`, `DataTable`).
- **变量/函数**: 使用 `camelCase` (e.g., `getUserInfo`, `isLoading`).
- **常量**: 使用 `UPPER_SNAKE_CASE` (e.g., `MAX_RETRY_COUNT`).

### 2.2 Vue 组件
- **Script Setup**: 统一使用 `<script setup lang="ts">`。
- **结构顺序**:
    1. `script setup`
    2. `template`
    3. `style`
- **Props 定义**: 使用 TypeScript 接口定义 Props。
    ```typescript
    interface Props {
      title: string
      isActive?: boolean
    }
    defineProps<Props>()
    ```

### 2.3 样式
- **Tailwind 优先**: 尽量使用 Utility Classes。
- **CSS 变量**: 主题色、圆角等必须使用 `design-tokens.md` 中定义的 CSS 变量。

## 3. 后端规范 (Go)

### 3.1 代码格式
- 提交前必须运行 `gofmt` 或 `goimports`。

### 3.2 命名风格
- **包名**: 简短、全小写，不带下划线。
- **接口名**: 以 `er` 结尾 (e.g., `Reader`, `Writer`)。
- **私有变量**: `camelCase`。
- **导出变量**: `PascalCase`。

### 3.3 错误处理
- 严禁忽略 error。
- 错误必须向上传递或处理，不得静默吞没。
- 使用 `fmt.Errorf("context: %w", err)` 包装错误以保留堆栈上下文。

### 3.4 数据库交互
- 禁止拼接 SQL 字符串，必须使用参数化查询。
- 事务操作必须显式处理 Rollback：
    ```go
    tx, _ := db.Begin()
    defer tx.Rollback() // 确保发生 Panic 或错误时回滚
    // ... 业务逻辑
    tx.Commit()
    ```

## 4. Git 提交规范

遵循 **Conventional Commits** 规范。

格式: `<type>(<scope>): <subject>`

**Type 类型**:
- `feat`: 新增功能
- `fix`: 修复 Bug
- `docs`: 文档变更
- `style`: 代码格式调整（不影响逻辑）
- `refactor`: 代码重构
- **chore**: 构建过程或辅助工具变动

**示例**:
- `feat(auth): 增加 JWT 登录接口`
- `fix(ui): 修复按钮在移动端点击无响应的问题`
- `docs(readme): 更新快速启动指南`
