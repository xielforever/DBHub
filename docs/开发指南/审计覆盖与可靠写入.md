# 审计覆盖与可靠写入

本次补齐关键 HTTP 操作与鉴权拒绝的审计，并将请求结束后直接写数据库的方式，改为执行前持久化记录、执行后持久化结果、数据库幂等补写。审计补写只写日志，绝不重新执行原 SQL、提交事务或再次下载数据。

## 覆盖范围

| 操作 | 审计动作 | 关联与结果 |
| --- | --- | --- |
| 开启事务 | `TRANSACTION_BEGIN` | 本人连接、数据库登录账号、修订、事务编号；`begun` |
| 提交／回滚事务 | `TRANSACTION_COMMIT` / `TRANSACTION_ROLLBACK` | 原目标会话身份、事务编号；`committed` / `rolled_back`；结束失败为 `unknown` |
| 取消查询 | `QUERY_CANCEL` | 本人的任务和连接；`cancel_requested` 或 `already_finished`；其他用户请求被拒绝 |
| 申请／审批导出 | `EXPORT_CREATE` / `EXPORT_REVIEW` | 导出编号和审批结果 |
| 下载导出 | `EXPORT_DOWNLOAD` | GET／HEAD、导出和连接编号；未批准、无权限和不存在的请求也记录 |
| 登录／刷新／退出 | `LOGIN` / `REFRESH` / `LOGOUT` | 认证结果；成功后关联已验证的平台身份 |
| 其他变更 | 资源的 `CREATE` / `UPDATE` / `DELETE` 等 | 数据源、驱动、定义、授权、用户／组、策略等；保存路由模板和 HTTP 状态 |
| 普通只读接口鉴权失败 | `AUTH_DENIED` | 缺少、无效、过期令牌，失效会话、不可用用户、角色不足；会话服务故障的 503 也记录 |

统一审计位于路由鉴权与异常恢复之外，角色中间件拒绝和 handler panic 不再绕过审计。普通成功 GET、HEAD、健康检查、OPTIONS 和在线心跳不会产生业务操作日志。后台自动回收活动事务不属于本次 HTTP 操作审计范围。

`cancel_requested` 表示取消信号已发送，不能代替原查询的执行回执。`download_response` 表示服务端返回下载响应，不证明接收方已完整收到文件。响应写入报错单独记录 `response_failed`；不会把已确认成功的 SQL 回执改为未知。没有持久化完成结果、进程中断或结果校验失败时，恢复为 `unknown`，不推断成功。

审计保存固定字段：平台用户和角色、个人连接、数据源系列与修订、配置的数据库登录账号、驱动、执行请求编号，以及事务／任务／导出编号。数据库账号表示建立目标连接使用的配置账号，不跟踪 SQL 内的有效角色切换。路由使用 `/query/exports/{id}/download` 这样的模板，不保存 URL 查询参数。日志及待写文件均不保存请求／响应正文、密码、Token、SQL 正文、SQL 参数或导出内容。未保存连接测试中的元数据若包含 PostgreSQL JSONB 不支持的 NUL，落库时以带引号的转义文本保存，避免一条异常记录持续占用待写队列；其他正常字段不改变表示。

## 持久化与恢复

1. 受审计操作进入 handler 前，生成独立 UUID 和精确到微秒的事件时间，将执行前记录写入权限 0600 的文件，同时实际分配结果槽位空间。同步文件及目录成功后才继续。
2. 鉴权通过后、SQL 连接加载时，以及事务结束、取消和下载等关键位置，原子更新已验证的身份和目标快照。快照更新失败时停止进入后续操作。
3. handler 结束后写入结果槽位并 `fsync`。每个文件共 32 KiB，两个槽位分别带长度与 SHA-256 校验；校验用于识别不完整写入，不提供防篡改保证。
4. 立即尝试落库；失败后保留文件，后台按 1、2、4、8、16、32 秒退避重试，单次数据库调用有超时。不会因为重试次数或记录年龄而丢弃文件。
5. 数据库以 `(event_id, created_at)` 唯一约束执行 `ON CONFLICT DO NOTHING`。数据库已提交但确认丢失时，重试仍只有一条日志。只有数据库确认成功后才删除待写文件并同步目录。
6. 启动时重放已完成文件；只有执行前记录或结果槽位损坏的请求恢复为 `unknown`。执行前记录本身损坏时阻止启动并保留文件，等待修复。未完成原子发布的临时文件没有对应已获准执行的操作，可在启动时清理。

新迁移 `0025_reliable_audit.sql` 增加事件标识，并移除审计到用户／连接的外键，使待写记录能在原用户或连接删除后保存原始 ID 与快照。旧日志保留且 `event_id` 为空，不补造历史字段。

队列满或执行前记录无法持久化时返回 **503**，handler 不执行。无法持久化拒绝请求本身时，仍有结构化访问日志；不宣称能够在完全不可写的介质上保存拒绝记录。执行结果写入失败会停止接收新的审计操作，并保留执行前记录；已执行操作不会为补写审计而自动重跑。修复存储后重启，可将中断记录恢复为待确认。

## 配置与运行状态

| 配置 | 默认值与要求 |
| --- | --- |
| `DBHUB_AUDIT_DIR` | 开发默认 `.dbhub/audit`；生产必须是绝对路径，挂载持久化存储，目录权限 0700 |
| `DBHUB_AUDIT_MAX_PENDING` | 默认 10000，允许 1–100000；默认记录占用约 312.5 MiB，另留目录元数据及原子替换临时文件空间 |

Cloud 使用 `/runtime/audit`，位于仓库外的持久化状态目录。生产镜像以 UID/GID 65532 运行，目录 `/var/lib/dbhub/audit` 已准备正确权限；生产 Compose 将 `backend-audit` 命名卷挂载到此处。重建或替换容器应复用该卷；不要在未排空队列时删除卷。

每个后端副本独占自己的审计目录／卷，文件锁拒绝两个进程同时打开同一目录。多个副本可共用元数据库，不能共用本地队列目录。跨机器迁移需要带走对应持久卷。

- `GET /api/v1/audit-logs/delivery`：仅管理员可见，返回本实例待写数（含进行中的请求）、容量、最早待写时间、最近落库时间、写入／存储失败计数和错误分类。计数按进程启动累计。
- 管理员“操作审计”页面每 10 秒刷新写入状态，可按事务、取消、导出和访问拒绝筛选，展开查看 HTTP 状态、事务编号与事件 UUID。状态读取失败时显示不可读取，避免保留过期的正常提示。
- `/api/health` 保留存活检查；`/api/ready` 在本地队列满或存储失败时返回 503，生产后端 HEALTHCHECK 使用就绪接口。数据库补写失败但本地仍可安全排队时，保持接收能力，同时显示积压及失败计数。
- 服务端输出审计持久化错误和待重试警告，不输出审计请求正文或原始数据库错误详情。

元数据库备份以外，还需保留尚未补写的审计卷。持久卷丢失无法仅靠应用恢复尚未落库的事件。这套机制不提供目标业务库与日志之间的分布式原子事务、不可篡改存储、数据库行级审计、授权变更前后明细，或自动归档保留策略。

## 验收与复现

```sh
./scripts/cloud/start.sh
./scripts/cloud/dev.sh exec -T backend go test -race -count=1 -p=4 -timeout 300s ./...
./scripts/cloud/dev.sh exec -T backend go vet -p=4 ./...
./scripts/cloud/dev.sh exec -T frontend sh -ec 'npm run test:query && npm run build'
DBHUB_BROWSER_TEST_SCRIPT=/app/scripts/cloud/audit_browser_test.py ./scripts/cloud/browser.sh
```

`auditlog/journal_test.go` 强制终止真实子进程，分别验证执行前、快照更新后、完成后和结果部分写入的恢复；验证自动重试、容量拦截、目录故障、文件锁及并发。`middleware/audit_test.go` 检查拦截前不执行、拒绝请求、panic、隐式响应、元数据边界与传输失败。

最终 Go 竞态回归 201 个测试条目、14 个测试包及 `go vet` 通过；前端 14 项、类型检查和构建通过。审计浏览器 8 项（其中 3 项为状态响应样例）通过，页面脚本错误为 0。最终生产镜像验证非 root、只读容器的私有卷权限、替换后的卷保留及相对路径配置拒绝。临时容器、测试卷及本轮无用构建层已清理，保留已验收的应用镜像。

取消和下载另行注入快照失败，断言不会发送取消信号、不会返回导出内容，且结果明确记录为拒绝。浏览器正常流程在Go 保护路径和元数据转义修正前完成；最终完整 Go 套件覆盖该修正，审计前端代码没有随后变化。

`server/audit_integration_test.go` 使用独立 PostgreSQL Schema 验证真实事务、目标会话中断、取消归属、导出审批／下载、失效认证和 Redis 会话服务不可用。暂时重命名该测试 Schema 的审计表模拟审计写入不可用，验证重启后恢复、删除原连接后补写及业务 SQL 只执行一次；另模拟数据库提交后确认丢失，检查事件 UUID、数据库行 ID 与时间均不变，并验证含 NUL 的历史待写快照在重启后可补写。不会停止现有数据库服务。

浏览器创建独立临时管理员和私有连接，真实验证审计页面、筛选、关联详情及手机布局；待写、暂停和状态读取失败三个界面场景使用明确的响应样例，不能替代上述数据库故障验收。完成后删除本轮连接、用户及其私有定义，并撤销测试会话。计数、指纹与截图见 [验收记录](../acceptance/audit-reliability-2026-10-17.json)。

最终 Cloud 实际 HTTP 探针还验证：带 NUL 账号的未保存连接测试返回 400，审计保存转义后的账号且不含口令，待写记录归零。
