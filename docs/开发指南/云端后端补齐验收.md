# 云端后端补齐与验收契约

SQL 工作台现已按 [第一阶段范围](SQL工作台第一阶段.md) 收缩为基础 SQL 编辑和执行。本文中的高级后端接口继续保留，其对应工作台入口暂缓。执行现有手动事务须显式传入 `transaction_id`；省略时始终使用独立连接。

本轮以真实 PostgreSQL、MySQL、Redis 为验收对象。应用正常路径不返回模拟成功或演示数据；Mock 仅保留为显式独立演示服务。所有安装、构建、测试和应用进程在 Docker 容器中执行。

## 1. 数据访问

- 测试目标连接时真实拨号、校验 TLS 和凭据；连接失败、SQL 错误、Redis 错误均返回非 2xx 业务错误，日志与响应不得泄露凭据。
- 关系型数据库执行单条语句；默认超时 30 秒、最多返回 1000 行，可在服务端允许的范围内调整。只读角色使用数据库只读事务，并拒绝事务控制语句、复合语句与写语句。
- 表、列、索引、主外键和分页预览来自目标数据库；动态标识符由驱动/AST 正确引用，数据条件参数化。
- PostgreSQL/MySQL 血缘解析使用实际 SQL AST，解析不支持时明确报告，不伪造血缘。

## 2. 已有前端接口补齐

所有接口沿用 `{code,message,data}` 信封及 Bearer JWT 鉴权。

| 接口 | 请求 | 成功响应 data / 约束 |
|---|---|---|
| `GET /api/v1/snippets` | `q,visibility,connection_id,page,page_size` | `{items,total,page,page_size}`；本人私有片段与团队共享片段 |
| `POST /api/v1/snippets` | `{name,sql_text,database_name?,connection_id?,visibility?}` | 片段详情；当前用户为所有者 |
| `PUT /api/v1/snippets/{id}` | 上述字段部分更新 | 片段详情；所有者或管理员 |
| `DELETE /api/v1/snippets/{id}` | 无 | `{id}`；所有者或管理员 |
| `POST /api/v1/query/transaction/begin` | `{connection_id,database?}` | `{transaction_id,status,connection_id}`；事务绑定用户和目标连接 |
| `POST /api/v1/query/transaction/commit` | `{connection_id,transaction_id}` | `{transaction_id,status,committed:true}` |
| `POST /api/v1/query/transaction/rollback` | 同上 | `{transaction_id,status,rolled_back:true}` |
| `GET /api/v1/query/transaction/status` | `connection_id` | `{active,transaction_id?,started_at?,queries?}` |
| `POST /api/v1/query/execute` | `{connection_id,database?,sql,transaction_id?,timeout_ms?,max_rows?,params?}` | 查询/写入结果；显式传入事务 ID 才复用事务连接，省略时使用独立连接；超时或断开取消真实查询 |
| `DELETE /api/v1/redis/key` | `{connection_id,key}` 或同名 query | `{key,deleted}` |
| `PUT /api/v1/redis/key/ttl` | `{connection_id,key,ttl}` | `{key,ttl}`；`-1` 清除过期时间，非负为秒 |
| `POST /api/v1/redis/key` | `{connection_id,key,type,value,ttl?}` | `{key}`；支持 string/hash/list/set/zset，已存在冲突 409 |
| `PUT /api/v1/redis/key/value` | `{connection_id,key,value}` | `{key}`；保持未显式修改的 TTL |
| `PUT/DELETE /api/v1/redis/hash/field` | `{connection_id,key,field,value?}` | `{key}` |
| `POST /api/v1/redis/list/push` | `{connection_id,key,value,direction}` | `{key}`；direction 为 left/right |
| `POST /api/v1/redis/list/pop` | `{connection_id,key,direction}` | `{key,value}` |
| `POST/DELETE /api/v1/redis/set/member` | `{connection_id,key,member}` | `{key}` |
| `POST/DELETE /api/v1/redis/zset/member` | `{connection_id,key,member,score?}` | `{key}` |

只读角色不得修改 Redis。事务空闲超时自动回滚，关闭应用时回滚；跨用户访问返回 403/404，不泄露他人事务。

## 3. 代理与会话

- 目标连接关联 `proxy_id`，支持 HTTP CONNECT、HTTPS CONNECT、SOCKS5 以及数据库代理网关；连接测试实际连接指定代理/目标。TLS 与 SSH 主机密钥验证保持开启。
- JWT 刷新令牌旋转、登出撤销及禁用用户校验在后端生效，使用 Redis 保存会话；Redis 故障不得绕过撤销检查。
- `POST /api/v1/auth/logout` 使用当前访问令牌撤销所在会话。生产 CORS 读取显式允许域名，不使用开发通配策略。

## 4. 高级功能与真实边界

- 查询执行由服务端限制并发、排队、超时和返回行数；队列状态仅用户本人和管理员可查看、取消。
- 列权限与行条件由服务端策略保存并执行。客户端角色切换不得改变真实授权；不支持安全改写的查询明确拒绝。
- 工单审批与 SQL 执行分离；仅批准的工单可执行，执行结果和历史记录持久化，失败不得标记已执行。
- AI 使用可配置的 OpenAI 兼容 HTTPS 服务。未配置模型或凭据时返回明确的“未配置”状态，不生成模拟回复；测试可使用本机协议桩，真实模型验证需环境设置中的密钥。
- 实时协作来自后端认证在线会话，移除随机模拟在线人数；查询分享使用持久化令牌、期限与撤销。
- 前端服务失败保留错误提示，不自动改用 localStorage 伪造业务成功。

## 5. 验收

自动化测试覆盖：真实查询/写入/分页、无效连接与 SQL、只读绕过防护、事务提交/回滚/隔离、片段权限、各 Redis 数据类型与 TTL、代理连通与错误、会话撤销、限流取消、策略执行、工单状态、分享撤销、血缘 AST 与前后端构建。测试不能以 Mock 结果代替真实数据库断言。

## 6. 新增控制接口

- `GET/PUT /query/settings`：本人持久化超时、最大行数与误写保护；非管理员不得关闭误写保护。
- `GET/PUT /query/policies`、`DELETE /query/policies/{id}`：策略仅管理员可修改；按连接、数据库、模式、表和真实角色匹配。当前策略只允许单表 SELECT，拒绝 JOIN、CTE、子查询、函数与写操作；启用策略的角色只能访问明确配置的表。掩码返回 NULL，隐藏列不进入派生表；预览、分享和导出也执行同一策略。
- `GET /query/jobs`、`POST /query/jobs/{id}/cancel`：后端进程执行队列，单用户 2、全局 8 并发；最多单用户 10、全局 100 个执行与等待任务。取消会取消数据库上下文。
- `GET/POST /query/presence`：Redis 在线心跳，45 秒失效；显示同一连接的真实登录用户名，不同步编辑器文档。
- `GET /ai/status`、`POST /ai/complete`：OpenAI 兼容 HTTPS Chat Completions；仅用户主动提交 SQL、表名和执行计划，不自动执行建议。
- `POST /tickets/{id}/execute`：仅管理员执行批准工单；原审批接口不接受 executed。原子状态变更为 executing，成功 executed，失败 failed，执行结果持久化。执行过程中应用崩溃的 executing 状态需人工核查目标数据库，禁止自动重试。
- `GET/POST /query/shares`、`DELETE /query/shares/{id}`、公开 `GET /public/query-shares/{token}`：令牌仅保存 SHA-256，分享 1–30 天；快照由服务端重新运行只读查询生成，最多 100 行。
- `GET/POST /query/exports`、`POST /query/exports/{id}/review`、`GET /query/exports/{id}/download`：服务端生成最多 1000 行的只读结果快照，申请人或管理员查看，管理员审批，仅批准后下载 CSV/JSON。此流程审阅授权结果的导出，不扩大查询权限。

以上路径均相对 `/api/v1`。生产元数据库和 Redis 必须配置；本地未配置元数据库时仅提供健康与认证接口。

## 7. 本轮验收记录

- 真实 PostgreSQL/MySQL 查询、元数据、分页、错误与事务提交/回滚均通过；HTTP MySQL 事务专门验证跨请求保持同一物理事务。
- Redis 五种类型、12 个写接口、TTL、存在冲突、只读禁止写入通过。
- 片段私有/共享与跨用户修改限制、角色校验、禁用用户、刷新旋转和登出撤销通过。
- HTTP CONNECT 实际转发 PostgreSQL 查询、错误代理凭据、SOCKS5 握手转发、HTTPS 证书拒绝和 SSH 主机密钥/超时验证通过。
- 服务端资源限制、取消真实长查询、行列策略、分页预览与分享/导出策略继承、撤销分享、工单审批/一次执行/失败状态通过。
- PostgreSQL/MySQL AST 血缘、OpenAI 兼容 HTTPS 协议桩与未配置状态通过；用户选择稍后配置真实模型，未执行外部模型调用。
- `go test -race ./...`、`go vet ./...`、Vue 类型检查与生产构建通过。生产 Go 镜像已构建并通过健康检查；Chromium 验证真实查询界面、AI 未配置提示、权限、工单、代理及桌面/手机布局，无页面脚本异常。

单后端进程的队列与事务、单表 SELECT 策略、Vitess 派生 MySQL 解析器的语法范围，以及在线人数而非文档协同编辑，均为当前明确支持边界；不支持的能力不会返回模拟成功。
