# SQL 工作台执行可靠性

第一阶段保持“运行、格式化”的日常操作，补齐请求防重、异常结果核实和并发边界。Redis 沿用认证会话与在线状态用途，暂不缓存热点业务表或任意 SQL 结果。

## 执行登记与结果核实

1. 客户端生成 UUID，并在发送前保存待确认编号。认证刷新重放沿用原请求体；取消、断网和超时不自动重发 SQL。
2. 服务端校验输入、目标连接与 SQL，在元数据库以 `(user_id, request_id)` 唯一约束登记。只有登记成功的处理器可以执行；其他处理器返回原回执。同一编号更改 SQL、参数、选项或角色返回冲突。
3. 排队、权限和误写检查通过后，必须成功持久化 `running`，才能向目标数据库发送用户 SQL。登记故障阻止发送。
4. 成功后保存执行摘要；错误根据是否已经发送 SQL、数据库是否明确拒绝语句，区分 `rejected`、`failed` 和 `unknown`。回执写入独立于 HTTP 请求的取消，带 3 秒清理超时。
5. 客户端遇到通信异常时仅请求 `GET /query/executions/{request_id}`。写入成功可恢复影响行数；查询成功只显示完成摘要，因为没有缓存结果行。

回执保存实际连接、数据库、状态、影响行数和耗时，不保存 SQL、参数、列名或查询行。SQL 历史沿用原有持久化规则，不属于结果缓存。回执只对本人开放，管理员不能跨用户读取。

浏览器 `sessionStorage` 只保存按用户隔离的待确认编号；存储写入失败时不发送 SQL。离开页面中止当前 HTTP 请求，保留编号；重新进入工作台会核实状态。状态仍在处理或不明时暂停新的执行，提供“核实状态”和明确确认后的“已核实，继续”。404 也保持待确认，因为原请求可能尚在登记。

## 状态与保证范围

| 状态 | 含义 |
| --- | --- |
| `queued` | 已登记，正在检查或排队，尚未发送用户 SQL |
| `running` | 已持久化开始执行，可能已经发送 SQL |
| `succeeded` | 已获得目标数据库的成功响应；显式事务内仅表示语句完成 |
| `rejected` | 未向目标数据库发送用户 SQL |
| `failed` | 目标数据库明确拒绝语句，或只读查询未完成 |
| `unknown` | 无法确定结果，可能已经提交，须核实目标数据库 |

同一已登记编号只取得一次执行机会。新编号代表新执行，不能用 SQL 文本去重，因为用户可能确实需要多次执行相同语句。跨页面主动生成不同编号的写入仍是不同请求。

DBHub 元数据库与任意外部目标数据库不共享原子提交协议。因此不能承诺外部写入恰好一次：目标写入提交后、回执落盘前进程退出，会留下无法自动确认的结果。对此保留原编号、禁止自动重跑。超过 5 分钟仍停留在排队/执行的记录展示为 `unknown`，不释放编号；后来收到确定结果时仍可更新回执。

登记记录不设置自动删除或过期重用。后续容量治理需要保留防重键或等价归档，不可简单通过 TTL 删除后重新执行。显式事务的提交、回滚和其他高级 API 沿用各自契约；本次请求防重覆盖 `/query/execute`。

## 防呆与并发

- 默认禁止没有 WHERE 或明显恒真的 UPDATE/DELETE，识别数字字面量比较、布尔常量及简单 AND/OR/NOT 组合，包括 CTE 中的写入。管理员原有误写保护配置继续生效。
- 这不是任意 SQL 的影响范围证明；`WHERE id>0` 仍可能匹配全表。返回行数限制也不限制更新、删除的影响行数。生产执行确认继续保留。
- SQL 执行接口在单进程内每用户最多 2 个、全局最多 8 个并发；执行和等待合计每用户最多 10 个、全局最多 100 个，等待最多 30 秒。过载返回 429 且回执为 `rejected`。
- 取得槽位后再次检查取消状态；结束函数可重复调用而不重复释放；用户没有等待或活动任务时清理其并发状态；关闭后拒绝新任务并取消已有任务。
- 多个处理器共享元数据库时能防重；并发总量限额仍是各进程独立，尚未实现分布式调度。其他高级 API 不自动纳入此执行队列。

## 验收

全部应用检查在 Docker 内运行：

```sh
./scripts/cloud/dev.sh exec -T frontend sh -ec 'npm run test:query; npm run build'
./scripts/cloud/dev.sh exec -T backend sh -ec 'go test -race -p=4 ./...; go vet ./...'
./scripts/cloud/browser.sh
```

前端回归覆盖重复运行、取消竞态、丢失写入响应、确定拒绝与未知结果、页面离开、刷新恢复、浏览器存储故障、并行核实及查询结果未保存时的提示。后端验证真实 PostgreSQL/MySQL 写入防重、独立处理器间 24 个并发相同编号只修改一次、跨用户隔离、响应丢失、登记与回执持久化故障、锁等待超时、进程失联留下的过期状态、HTTP 过载及取消恢复。队列单元测试验证用户与全局限额、队列满、等待超时、取消和重复结束时的资源释放。

浏览器检查真实查询与移动布局，并模拟已提交写入的响应丢失，验证恢复期间不再发送 SQL。该验证不替代生产容量规划或多实例负载测试。

2026-10-16 Cloud 验收通过：14 个前端回归测试、12 项真实浏览器检查、Vue 类型检查和生产构建、完整 Go 竞态测试与静态检查。真实 HTTP 测试验证同一用户 2 个执行和 8 个等待名额占满后，第 11 个请求返回 429；取消后可重新执行。浏览器依赖保持在临时容器中，应用使用真实 PostgreSQL、MySQL 与 Redis。
